# 設計概要

コード構成・DB・API・画面の現状と、逆行を防ぐための設計判断をまとめる。
1〜4節は実装時に実態へ合わせて更新し、5節には `architect` の計画に含まれる設計判断を、該当する見出しの下へ転記する。どの見出しにも当たらないときは見出しを足す。

書き方の決まり:

- 4節・5節には、色コード・px・周期などの見た目の値を書かず、CSSを正とする。値そのものが判断の中身のとき(タッチで押せる44pxなど)だけ書く
- 関数名・変数名・セレクタは、書き方を変えると壊れる注意のときだけ書く
- 5節の各項目には、逆行を防ぐ理由を書く。理由の無い決定は書かない
- アイコン名(Tabler Iconsのクラス名)は4節「アイコン」の表にだけ書き、画面の説明と5節では表の「意味」の言葉で書く

## 1. コード構成

```

cmd/server/logfile_*.go  # setupLogOutput の切り替え(logfile_gui.go は windowsgui タグのときだけログを kondate.log へ、logfile_console.go は何もしない)

internal/db/migrations/  # SQLマイグレーションファイル(embedでバイナリに焼き込み)
internal/model/          # ドメイン構造体

web/static/              # フロントエンド(画面ごとのHTMLと同名JS。一覧 recipes.html / recipes.js、詳細 recipe.html / recipe.js、取り込み import.html / import.js。画面によらないJS部品 common.js。全画面共通の既定スタイル base.css。開発モードの背景の模様 dev-mode.svg。embedでバイナリに焼き込み)
web/static/vendor/       # 同梱した外部ライブラリ(配布ファイルのまま。tabler-icons/ にoutlineのCSS・woff2・LICENSE。版数はREADME)

bin/                     # ビルド成果物の出力先(Git管理外)
scripts/                 # preview用サーバーの起動スクリプト(preview-server.ps1)
data/                    # SQLiteファイルの実行時生成先(Git管理外)
```

## 2. DBスキーマ

### `recipes`(レシピ)
| カラム | 型/制約 |
|---|---|
| id | INTEGER PRIMARY KEY |
| name | TEXT NOT NULL(タイトル) |
| body | TEXT NOT NULL DEFAULT ''(材料・調味料・手順を含む自由テキスト) |
| cooked_count | INTEGER NOT NULL DEFAULT 0(作った回数) |
| image_version | INTEGER NOT NULL DEFAULT 0(画像を保存した回数。画像URLの `v` に使う) |
| image | BLOB(JPEG。NULLなら画像なし。必ず最後の列にする) |

### `tags`(タグ)
| カラム | 型/制約 |
|---|---|
| id | INTEGER PRIMARY KEY |
| name | TEXT NOT NULL UNIQUE(大文字・小文字を区別) |

### `recipe_tags`(レシピとタグの紐付け)
| カラム | 型/制約 |
|---|---|
| recipe_id | INTEGER NOT NULL REFERENCES recipes(id) ON DELETE CASCADE |
| tag_id | INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE |

主キーは `(recipe_id, tag_id)`。どのレシピにも付いていないタグはレシピの保存・削除と同じトランザクションで消すので、`tags` には使われているタグだけが残る。

### `recipe_bookmarks`(ブックマーク)
| カラム | 型/制約 |
|---|---|
| recipe_id | INTEGER PRIMARY KEY REFERENCES recipes(id) ON DELETE CASCADE |

行があればブックマーク中。レシピを消すとCASCADEで消える。

### `schema_migrations`(マイグレーション適用履歴)
| カラム | 型/制約 |
|---|---|
| name | TEXT PRIMARY KEY(マイグレーションファイル名) |
| applied_at | TEXT NOT NULL DEFAULT (datetime('now')) |

`internal/db/db.go` の `Migrate()` が `main.go` から起動時に呼ばれ、 `internal/db/migrations/*.sql` を未適用のものだけファイル名昇順・1ファイル1トランザクションで適用する。

## 3. APIエンドポイント

ルーティングは `internal/handler/router.go` の `NewRouter()` に集約する(Go 1.22以降のメソッド付きパターン)。レシピのJSONは `{"id","name","body","cooked_count","tags","bookmarked","image_url"}`(`tags` はタグ名の配列でタグのid昇順、無ければ `[]`。`bookmarked` はブックマーク中ならtrue。`image_url` は画像があれば `/api/recipes/{id}/image?v={image_version}`、無ければnull)。POST/PUTのリクエストは `{"name","body","tags"}` で、`tags` が無い・nullなら空として扱い、そのレシピのタグを丸ごと置き換える(前後の空白を除き、空は捨て、完全一致の重複はまとめ、同じ名前のタグが無ければ作る)。PUTは `cooked_count`・`bookmarked`・画像を受け付けず値も変えない。

| メソッド パス | 概要 |
|---|---|
| GET /healthz | 死活監視用(`{"status":"ok"}`固定) |
| GET /dev-mode.css | 画面の背景の模様のCSS。`DEV_MODE=1` のときは `body` に白の背景色と dev-mode.svg の繰り返しを指定し、そうでないときは中身が空。どちらも200・`text/css` |
| GET /api/recipes | レシピ一覧取得。200で配列(id昇順、bodyとtagsを含む。0件は `[]`) |
| GET /api/tags | 使われているタグ名の配列(id昇順、0件は `[]`) |
| POST /api/recipes | レシピ新規作成。リクエスト `{"name","body"}`、201で作成したレシピ |
| POST /api/recipes/import | レシピをまとめて登録。リクエストは配列 `[{"title","body","tags","cooked_count"}, ...]`(`title` 以外は省略・null可。`body` は空文字、`tags` は空、`cooked_count` は0)。全件を1トランザクションで配列の順に登録し、201で `{"count": 件数}`。上限5MB。画像とブックマークは扱わない(取り込んだレシピはブックマークなし) |
| GET /api/recipes/{id} | レシピ1件取得。200 |
| PUT /api/recipes/{id} | レシピ更新(全体置換)。リクエストは作成と同じ、200で更新後のレシピ |
| DELETE /api/recipes/{id} | レシピ削除。204(ボディなし) |
| POST /api/recipes/{id}/cooked | 作った回数を1増やす。200で更新後のレシピ |
| DELETE /api/recipes/{id}/cooked | 作った回数を1減らす(0未満にはしない)。200で更新後のレシピ |
| PUT /api/recipes/{id}/bookmark | ブックマークを付ける。すでに付いていても200で更新後のレシピ |
| DELETE /api/recipes/{id}/bookmark | ブックマークを外す。付いていなくても200で更新後のレシピ |
| PUT /api/recipes/{id}/image | 画像を保存(`image_version` を1増やす)。ボディはJPEGのバイト列そのまま(上限2MB)。200で更新後のレシピ |
| DELETE /api/recipes/{id}/image | 画像を外す。画像が無くても200で更新後のレシピ |
| GET /api/recipes/{id}/image | 画像のバイト列。`Content-Type: image/jpeg`、`Cache-Control: public, max-age=31536000, immutable`。`?v=` は見ない |
| GET / | ルートパスのみ `/recipes.html` へリダイレクト(302)。それ以外は静的ファイル配信(embed。`DEV_MODE=1` のときのみ `os.DirFS("web/static")` から配信) |

エラー応答は `internal/handler/respond.go` の `writeError` で `{"error": "メッセージ"}` として返す。

| ステータス | 条件 | メッセージ |
|---|---|---|
| 400 | `{id}` が数値でない・1未満 | IDが不正です |
| 400 | リクエストJSONが不正 | リクエストの形式が不正です |
| 400 | `name` が空白除去後に空 | 名前を入力してください |
| 400 | 画像のボディが2MBを超える | 画像が大きすぎます |
| 400 | 画像のボディがJPEGでない(空を含む) | JPEG画像を送ってください |
| 400 | 取り込みのボディが配列でない(nullを含む) | リクエストの形式が不正です(上の行と同じ) |
| 400 | 取り込みのボディが5MBを超える | リクエストが大きすぎます |
| 400 | 取り込みの配列が空 | 取り込むレシピがありません |
| 400 | 取り込みの配列に不正な件がある | `N件目: 理由` を先頭から最大10行、改行区切り。11件以上なら最後に `ほかN件`。理由は「形式が不正です」「名前を入力してください」「作った回数は0以上の整数にしてください」 |
| 404 | 対象IDのレシピが無い | レシピが見つかりません |
| 404 | `GET .../image` でレシピに画像が無い | 画像が見つかりません |
| 500 | 上記以外(詳細はログのみ) | サーバー内部でエラーが発生しました |

### 一覧(`recipes.html` / `recipes.js`)

- 見出しの行の右端に、取り込み画面へ移るアイコンだけのリンク(`aria-label`「レシピを取り込む」)
- 見出しの下に検索欄、その下に絞り込みの行、その下にタイルグリッドを並べる。検索欄と絞り込みの行は、一覧の読み込みに成功したときだけ出す(タグが0件でも出す)

検索欄:

- 上段は、今の探す対象の文言(「名前で探す」/「名前と本文で探す」)を出したボタン。押すたびに対象が切り替わる。既定は名前のみ
- 下段はキーワードの入力欄(プレースホルダ「キーワード」、`aria-label` は今の対象の文言)。入力のたびに(IMEの変換中も)、空白で区切った語をすべて名前に含むレシピだけを表示する。「名前と本文」では、語ごとに名前か本文のどちらかに含めばよい。全角と半角、大文字と小文字、ひらがなとカタカナは区別しない。EnterはIMEの確定でなければフォーカスを外すだけ
- キーワードがあるときだけ、入力欄の右端にアイコンだけの「キーワードを消す」を出す。押すとキーワードを消して入力欄にフォーカスを戻す。対象は戻さない

絞り込みの行:

- 先頭にアイコンだけの「ブックマークで絞り込む」トグル(`aria-pressed`)。押している間は、ブックマーク中のレシピだけを表示する
- 続けて「タグ」ボタンと、選んでいるタグの札を並べる。札ごとにアイコンだけの「「名前」を外す」を付ける
- 右端に並び順の `<select>`(`aria-label`「並び順」)。新着順(既定。id降順)・名前順・作った回数が多い順・少ない順から選び、絞り込んだ結果を並べ替える。追加パネルは並び順によらず先頭に置く
- ブックマーク・タグ・キーワードの条件はすべてANDでかける

タグ選択ダイアログ:

- 「タグ」ボタンで開く `<dialog>`(見出し「タグで絞り込む」)。中身は、タグの検索欄(プレースホルダと `aria-label` は「タグを探す」、空白区切りのAND)とタグのトグルボタン(`aria-pressed`)。選んでいるタグには、選んでいることを示すアイコンを付ける
- 並べるのは、選んでいるタグと、今の絞り込み結果に付いているタグだけ。選んでいないタグが1つも並ばないときは「一緒に選べるタグはありません」を出す(検索語があるときは「「語」を含む、一緒に選べるタグはありません」)
- 押すたびに一覧とURLへすぐ反映する。決定ボタンは無い。開くと閉じるボタンにフォーカスが移る。閉じるボタン・Esc・外側のタップで閉じる

タイルグリッド:

- 画面幅で列数が変わる正方形のタイル。先頭は `recipe.html` へのリンクの追加パネル(中央に「追加」)で、0件でも出す
- レシピのタイルは詳細(`recipe.html?id=N`)へのリンク。画像を出し、画像が無ければ中央に画像なしのアイコンを出す。下端に名前の帯を置き、名前を1行で出す(長い名前は「…」で省略し、全文はタイルの `title`)
- 名前の帯のすぐ上に、タグの札を1行で並べる。収まらない分は「+N」(Nは並べるタグのうち隠した数)にまとめる。タグで絞り込んでいるときは選んでいるタグを除き、残りが0件なら札の行を出さない。札は押しても絞り込まない
- 右上に、作った回数のバッジ(アイコンと数字)を出す。0回のときは出さない。下地の色は、全レシピの最大回数を基準に5段階で濃くなる。絞り込み・検索・並び順では色が変わらない
- 左上に、ブックマークのトグル(`aria-label`「「名前」をブックマーク」、状態は `aria-pressed`)。付いていないときも出す。押すとPUT/DELETEで付け外しし、ページは移らない。送信中は、そのレシピのボタンだけを無効にする。失敗したらサーバーの `error` 文言を一覧のエラー欄に出し、状態は変えない
- ブックマークで絞っている間にタイルで外したレシピは、その場で一覧から消える。フォーカスは、詰めてきた同じ位置のタイル(末尾なら1つ前のタイル、1件も残らなければ「ブックマークで絞り込む」)へ移る
- 名前がちょうど「好評」のタグ(完全一致)が付いたタイルは、内側の縁が明滅して目立つ(端末で動きを減らす設定のときは光ったまま止まる)。そのタイルの札の行には「好評」を並べない。「+N」にも数えず、ほかのタグが無ければ札の行を出さない。代わりに、読み上げ用の見えない「好評」の文字を名前の帯の先頭に置く(「好評」で絞り込んでいるときは置かない)。詳細ページでは強調しない

状態:

- 一覧の読み込みに失敗したときは、検索欄・絞り込みの行・追加パネルを出さず、エラー文言だけを出す
- ブックマーク・タグ・キーワードのどれかで絞っていて0件のときは「条件に合うレシピがありません」を出す。探す対象を切り替えただけでは出さない
- ブラウザの戻るでキャッシュから復元されたときは、一覧を読み直す

URLクエリ(操作のたびに履歴を増やさずに書き戻し、読み込み時にURLから状態を戻す。知らない値や存在しないタグは捨てて、URLからも消す):

- `?q=` キーワード(前後の空白を除いた入力のまま。空なら付けない)
- `?scope=body` 探す対象が「名前と本文」(キーワードが空でも残す)
- `?bookmark=1` ブックマークで絞り込み中
- `?tag=名前` 選んでいるタグ(複数なら繰り返す)
- `?sort=name` / `cooked-desc` / `cooked-asc` 並び順(新着順のときは付けない)

### 詳細(`recipe.html` / `recipe.js`)

- `?id=N` なら閲覧表示、`id` が無ければ新規作成の編集フォームを出す。IDが無効なとき・存在しないとき(`?id=` が空のときを含む)は、エラー文言と「一覧へ戻る」だけを出す
- 上部の行は、閲覧表示では左にアイコンだけの「一覧へ戻る」、右にブックマーク・「作った」・アイコンだけの「編集」・「削除」。編集中は、左に「キャンセル」、右に「保存」だけを出す
- 「一覧へ戻る」は、一覧から来たときはブラウザの戻ると同じに動く(一覧の絞り込み条件が残る)
- 送信中は、上部と本文のボタンをすべて無効にする

閲覧表示:

- 名前・タグの札(0件なら札の行を出さない)・画像・本文を出す。本文は書いたとおりの改行で出し、`http://`・`https://` のURLは新しいタブで開くリンクにする。選択・コピーできるのは名前と本文だけ
- ブックマークはアイコンだけのトグル(`aria-label`「ブックマーク」、状態は `aria-pressed`)。押すとPUT/DELETEで付け外しする
- 「作った」は、アイコンと回数を出したトグル(`aria-label`「作った」、状態は `aria-pressed`)。押すと回数を1増やして押した状態になり、もう一度押すと1減らして戻る。押した状態はページを読み込むたびに戻る
- 「削除」は確認ダイアログ(「削除する」/「キャンセル」)の後に削除し、一覧へ移る。詳細のURLは履歴に残さない
- 失敗したときは、閲覧表示のエラー欄にサーバーの `error` 文言を出し、表示は元のまま残す

編集フォーム:

- 上から、エラー欄・名前欄(プレースホルダ「名前」)・タグ欄・画像欄・本文欄(プレースホルダ「本文」)の順。欄に見出しは付けず、読み上げ名は `aria-label` で付ける
- タグ欄は、入力欄(プレースホルダ「タグ」、`aria-label`「追加するタグ」)と「追加」ボタン。IMEの確定でないEnterでも足せる。入力候補は `GET /api/tags` のタグから、付けているタグを除いたもの。下に付けた札の列を出し、札ごとにアイコンだけの「「名前」を外す」を付ける(札が0件なら場所を取らない)。入力欄に文字を残したまま保存すると、その文字もタグとして足す
- 画像欄は、画像があればプレビューの右下にアイコンだけの「画像を外す」を重ねる。無ければ「画像なし」枠を出す。枠全体が貼り付け欄(`aria-label`「画像をここに貼り付け」)で、Ctrl+Vやスマホ長押しの「ペースト」でクリップボードの画像を受け取る。中央に「画像を選ぶ」と「Ctrl+V・長押しで貼り付け」の案内を出す。選んだ画像・貼った画像は、保存するまで送らない
- 保存に成功すると閲覧表示に戻る。失敗したときは、フォームの先頭にサーバーの `error` 文言を出す。レシピは保存できて画像だけ失敗したときは、選んだ画像を残して編集フォームにとどまる(新規作成ならURLはすでに `?id=` 付き)
- 「キャンセル」は、未保存の変更があれば確認ダイアログ(「破棄する」/「キャンセル」)を出す。既存のレシピなら閲覧表示へ、新規作成なら一覧へ戻る
- 未保存の変更があると、戻る・再読み込み・タブを閉じるの操作で、ブラウザ標準の離脱確認を出す(iOS Safariでは出ない)

### 取り込み(`import.html` / `import.js`)

- 上部の左にアイコンだけの「一覧へ戻る」(一覧から来たときはブラウザの戻ると同じに動く)、右に「取り込む」
- 見出しの下に、JSONを貼る大きなtextareaを置く。その下に「受け付けるJSONの形」の説明と例を常に出す。選択・コピーできるのは例だけ
- 「取り込む」で `POST /api/recipes/import` を呼び、送信中はボタンを無効にする
- 成功したら欄を空にし、欄の上に「N件のレシピを取り込みました」と「一覧へ戻る」を出す
- 失敗したら、サーバーの `error` 文言を改行どおりに欄の上へ出し、入力は残す

## 5. 設計判断(逆行防止用)

### 全体・ビルド・運用

- **モジュール名は `kondate-supporter`**: 外部へ公開せず `go install` もしないため、GitHubのパスにはしない。importを短く保ち、旧実装を参照するときの読み替えを無くす。
- **ディレクトリ・ヘルパー関数・設定項目は、それを使うROADMAP項目で作る**: `.gitkeep` などの目印ファイルも置かない。置き場だけを先に作ると、使われない層や項目が残るため(旧実装は一度に大きく作ろうとして完成しなかった)。
- **次のものはROADMAPに項目が追加されるまで作らない**: 在庫・献立・買い物リストのテーブル・API(旧実装はこれらの画面まで一度に作ろうとして完成しなかった)。静的ファイル(`web/static`)のキャッシュの仕組み(画面が少なく、LAN内の通信で足りる)。デプロイの自動化、つまり転送や、systemd・Windowsのサービス化による常駐化(個人利用では必要性が薄く、READMEの手順で足りる)。
- **Makefileはsh前提で書き、引数なしの `make` はhelpを出す**: 開発PCではGit Bash/WSLからmakeを実行するので、cmd.exeでの動作は考えず、環境変数は `VAR=値 コマンド` の形で渡す。`make` だけを打ったときに開発サーバーが起動せず、どのターゲットがあるかもその場で分かるようにする。helpの一覧はターゲット行の末尾の `## 説明` から作るので、ターゲットを増やすときはその行に `## 説明` を書くだけでよく、help側は書き換えない(この書き方でないターゲットは一覧に出ない)。詳しい理由や注意は、ターゲットの上の行に `#` コメントで書く。
- **`make run` とpreviewは、固定パスへビルドしてから `DEV_MODE=1` で起動する**: `go run` は実行のたびに一時パスへバイナリを作るため、Windowsファイアウォールの許可を何度も求められ、許可ルールも増え続ける。`DEV_MODE=1` で画面ファイルをディスクから配信し、HTML/JSの修正をビルドし直さずに確認できるようにする。previewは同じパスへ上書きビルドするので、起動時に前回のpreview用exeを止める(残っているとビルドに失敗し、ポートも埋まったまま古い埋め込み画面を配信し続けていた)。
- **開発サーバー・preview・常駐運用は、ポート・実行ファイル名・DBを分ける**: 3つを同時に動かしてもぶつからないようにする。config.goの既定値 `:8080` は常駐運用(`make build-win` のexe、将来のRaspberryPi)用に残す。`make run` は `KONDATE_ADDR=:8082` を指定し、previewのポートとDBは `.claude/launch.json` で指定する。既定値を変えないのは、配置するexeを環境変数なしで起動すれば常駐用のポートになるようにするため。実行ファイル名を分けるのは、Windowsでは実行中のexeを上書きできず、常駐運用のサーバーを動かしたまま開発用やpreview用をビルドすると失敗するため。
- **配置用ビルド(build-rpi・build-win)は、`CGO_ENABLED=0`・`-trimpath`・シンボル除去で静的バイナリ1つにする**: SQLiteドライバがCGO不要なので静的バイナリ1つで配置でき、シンボルを除いて転送・保存のサイズを抑える。RaspberryPi Zero向けは、Pi Zero/Zero WがARMv6なので `GOARM=6` を付ける。共通のリンカフラグは `RELEASE_LDFLAGS` にまとめ、ターゲット固有のフラグ(build-winの `-H windowsgui`)はその後ろに足す。`-ldflags` を2回書くと、後の方だけが効くため。
- **`make build-win` は、RaspberryPiを用意するまでのつなぎで、コンソールを出さない**: 開発用の `make run` とは別に、embedから配信する配置用exeを作る。GOARCHは指定せず、ビルドしたマシンに合わせる。`-H windowsgui` でコンソールウィンドウを出さないのは、常用中にコンソールを誤って閉じるとサーバーが止まるため。止めるのはタスクマネージャーか `taskkill /F` で、手順はREADMEに書く。終了処理は作らない(SQLiteはトランザクション単位で書き込みが確定するので、強制終了でもDBは壊れない)。
- **ログをファイルへ出すのは、ビルドタグ `windowsgui` のときだけ**: コンソールが無いビルドとログの出し先を必ず組にするため。環境変数では切り替えず、Makefileの `-tags windowsgui` とファイル先頭の `//go:build` で選ぶ(タグ名を片方だけ変えると、コンソールなしのビルドでログが消える)。`make run`・preview・RaspberryPi向けはコンソールに出す。
  - 出し先は、標準 `log` の既定のloggerの出し先を替えるだけにし、ロガーのパッケージや構造化ログは作らない。起動メッセージ・起動の失敗・handlerの500の詳細・`net/http` のエラーがどれも既定のloggerを通るので、呼び出し側を書き換えずに全部ファイルへ入る。
  - ログファイルは、DBと同じフォルダの `kondate.log` に追記するだけで、分割しない。DBのパスを場所の設定に使えば設定が増えない。書くのは起動時とエラーのときだけなので、個人利用では大きくならない。
  - ログファイルを開けなくても起動は続け、ダイアログも出さない。ログが無くても画面は使えるため。フォルダに書けなければDBも作れず、そこで起動が止まる。
- **外部ライブラリはCDNを使わず、`web/static/vendor/<名前>/` に配布ファイルのまま同梱する**: LAN内でインターネットにつながらなくても画面が崩れず、embedでバイナリに入るので配置もファイル1つのまま。編集しないのは、更新を配布ファイルの差し替えだけで済ませるため(手順と版数はREADME)。Tabler Iconsは、使うアイコンがoutlineだけなので、outlineのCSSとwoff2だけを置く(filled・200/300版、woff・ttfは置かない)。CSSのフォント指定は先頭がwoff2で、対応ブラウザは後ろの形式を取りに行かない。そのため、置いていない形式への参照はCSSに残したままにする。
- **開発モードの模様は、`GET /dev-mode.css` の中身をサーバーで切り替えて出す**: HTMLとJSに分岐を置かないので、HTMLはembedでもディスクでも同じファイルのまま使え、設定を取りに行くAPIやJSも要らない。開発モードでないときも空のCSSを200で返す(404にすると、常駐運用で画面を開くたびにブラウザのコンソールへ読み込みエラーが出る)。
  - 模様は `body` の背景に指定する。`html` に背景が無ければ `body` の背景がビューポート全体に描かれるので、要素を足さずに、どの画面でも本文の列の外まで模様が出る(`html` に背景を付けると、模様が本文の列の中だけになる)。
  - 模様は `web/static/dev-mode.svg` を繰り返して敷き、SVG自体は透明にして、白はCSSで付ける。文字・大きさ・傾き・間隔を、SVGの1ファイルで直せるため。背景画像のSVGではWebフォントが使えないので、フォントは `sans-serif` にする。
  - 模様は淡くし、白い背景の部品の下に隠れて本文やタイルを読みにくくしないようにする。

### バックエンド・DB・API

- **SQLiteの接続は `SetMaxOpenConns(1)` で1本に制限し、PRAGMAはDSNの `_pragma` で指定する**: 書き込みを直列化して `SQLITE_BUSY` を避ける。単一プロセス・個人利用で、RaspberryPi Zeroにも合う。PRAGMAを接続後の `Exec` で設定すると、プールが作る新規接続に反映されないことがある。
  - 外部キーは `_pragma=foreign_keys(1)` で有効にする。SQLiteは接続ごとに既定で外部キーが無効で、`ON DELETE CASCADE` も効かない。トランザクションの中で `PRAGMA foreign_keys` を実行しても効かない。
  - トランザクションの中では `r.db` を使わず、必ず `tx` を使う。接続が1本なので、`r.db` を使うと空き接続を待ち続けて止まる。
- **マイグレーションは `internal/db` で直接embedする**: 読み込み側は `Migrate()` だけなので、専用のパッケージは分けない。
- **依存は `handler → service → repository` に保ち、serviceはrepositoryの具象型を直接持つ**: テストの差し替えなど、インターフェースが要る場面がまだROADMAPに無いため。
  - handlerはrepositoryをimportしない。「見つからない」は、repositoryのエラーをserviceが自分のエラーに置き換えて伝える。ユーザー向けの文言はserviceのエラー値に持たせ、handlerはHTTPステータスへの振り分けだけを行う。
  - タグはレシピに従属するものとして、レシピのrepository・service・handlerで扱い、層ごとに型を分けない。タグはレシピに付いている間だけ存在し、作るのも消すのもレシピの保存・削除の中で行う。タグだけを操作するAPIは無い。
  - 保存・削除のトランザクションはrepositoryのメソッドの中で完結させる。SQLをrepositoryに閉じ込めたまま、レシピとタグの書き込みを1つにまとめられる。
- **名前のチェックとタグ名の正規化はserviceで行う**: どちらも業務ルールのため。画面でも同じ規則でタグの重複を防ぐが、正しさを決めるのはサーバー。
  - 名前は前後の空白を除いて空なら不可とし、保存するのも空白を除いた後の値。`body` は自由テキストとして書かれたまま保存する。
  - タグ名は前後の空白を除き、空を捨て、完全一致の重複をまとめる。大文字と小文字は区別し、書かれたとおりに保存する。表記ゆれを吸収する比べ方は、絞り込み・検索の側で行う。
- **PUTは全体置換にし、部分更新(PATCH)は作らない**: 項目が名前・本文・タグだけのため。全体置換なので、送られなかった `body` と `tags`(nullを含む)は空として扱う。
- **作った回数・ブックマーク・画像は専用エンドポイントでだけ変え、PUTの全体置換では受け付けない**: PUTに含めると、編集中に別の端末で「作った」・ブックマーク・画像を変えたとき、保存で古い値に戻ってしまう。
  - 回数の増減はSQLの式(`cooked_count + 1`、下限0は `MAX`)で行い、読んでから書く手順にしない。
  - 画像のボディはJSONに包まず、バイト列のまま送れる。
- **ブックマークの付け外し・画像を外す・回数の減算は、すでにその状態でもエラーにせず、200で更新後のレシピを返す**: 画面側で今の状態を確かめずに呼べる。別の端末で先に変わっていても失敗せず、画面は返ってきたレシピで表示を合わせればよい。ブックマークは回数ではなく状態を決める操作なので、PUT/DELETEにして何度送っても結果が同じになるようにする。
- **IDの存在は事前にSELECTせず、書き込みの結果で確かめて404にする**: 問い合わせが1回で済み、確かめてから書くまでの間に別の端末で消されても取り違えない。
  - DELETEは `RowsAffected` が0なら404にする。
  - 作った回数・画像のUPDATEは、`RETURNING` で返った更新後の行をそのまま応答に使い、行が無ければ404にする。
  - PUTはUPDATEの `RowsAffected` が0なら404にし、タグを付け替えた後にSELECTで読み直して返す(受け付けない回数の実際の値も返せる)。タグより先にUPDATEするのは、存在しないidにタグを付けると外部キー違反になり、404と見分けにくいため。
  - ブックマークは書き込みの後にSELECTで読み直し、行が無ければ404にする。付けるときは `INSERT ... SELECT id FROM recipes WHERE id = ? ON CONFLICT DO NOTHING` にする(`VALUES (?)` では、存在しないidが外部キー違反になるため)。外すときのDELETEは、行が無くてもエラーにならない。2つの文は1つのトランザクションにまとめる。
- **一覧APIはid昇順(登録順)で本文とタグも含めて返し、画面の並び順はブラウザで決める**: SQLiteの文字列比較では日本語の名前がよみ順に並ばないため、名前の比較は `Intl.Collator` が使えるブラウザで行う。並び順を変えるたびに通信せず、家庭内の規模なら全件を並べ替えても十分速い。一覧と詳細でレスポンスの形を分けない。
- **レシピを返す応答は、一覧・1件取得・`RETURNING` のどれも、同じ列リスト `recipeColumns` で読む**: 応答の形が1つにそろい、読み込む処理も1つで済む。列を足すときはこの列リストに足す(別に書くと、応答によって項目が欠ける)。
  - タグ名の配列は相関サブクエリの `json_group_array`(タグのid順)で、`bookmarked` は `EXISTS` サブクエリで読む。家庭内の規模なら、行ごとのサブクエリでも重くならない。
  - 画像の有無は `typeof(image) = 'blob'` で調べる。列の型だけを見て中身を読まないので、画像の本体を読まずに `image_url` を組み立てられる。
- **画像はファイルでなくrecipesのBLOB列に入れる**: 保存先がDBファイル1つなので、preview用DBを使えば画像も自動で分かれ、バックアップや配置もDBファイルだけで済む。1レシピ1枚・2MBまでならSQLiteで足りる。
- **`image` はrecipesの最後の列にする**: SQLiteは大きなBLOBを行の後ろのオーバーフローページに置き、BLOBより後ろの列を読むとそこを辿るため。今後recipesに列を足すときはこの点に注意する。
  - `ALTER TABLE ... ADD COLUMN` は列を末尾に足すので、この決まりを破ってしまう。そのため、ブックマークはrecipesの列にせず、`recipe_bookmarks` に行があるかどうかで持つ。外すときは行を消すだけで済み、レシピを消せばCASCADEで一緒に消える。
- **画像URLの `v`(`image_version`)は、ブラウザのキャッシュを切り替えるためだけに使う**: 画像URLは `immutable` で1年キャッシュされる。
  - `image_version` は保存のたびに増やし、画像を外しても戻さない。外して付け直したときに同じ `v` になると、古い画像が表示されてしまう。
  - 取得では `v` を見ず、常に今の画像を返す。古い版はDBに残さないため。
- **`image_url` はhandlerで組み立てる**: パスはルーティングの知識のため。modelは画像の有無と版をJSONに出さずに持ち、handlerが応答に `image_url` を足す。
- **画像の大きさ・形式の検査はhandlerで行う**: `http.MaxBytesReader` で、2MBを超えた時点で読むのをやめ、大きなボディをメモリに溜めない。形式は `http.DetectContentType` がimage/jpegかどうかで見る。ボディの検査はDBより前なので、IDが無く画像も不正なときは400になる。
- **タグはレシピのJSONに名前の配列で持たせ、idは画面に出さない**: 画面がタグを見分けるのも、URLの絞り込み条件(`?tag=名前`)も名前で足りる。名前はUNIQUEなので取り違えない。
- **タグの置き換えは、紐付けを全部消して付け直した後に、未使用のタグを消す順で行う**: 付けたままのタグを途中で消さないので、idが変わらず、タグの並び(id昇順=最初に作られた順)が保存のたびに入れ替わらない。
- **未使用のタグは保存・削除のたびに消し、`GET /api/tags` は `tags` をそのまま返す**: 未使用のタグがDBに残らないので、使われているかを毎回確かめなくてよい。
- **`recipe_tags.tag_id` にはインデックスを作らない**: 主キー `(recipe_id, tag_id)` で、レシピからの検索は足りる。タグの削除や未使用タグの判定で全件を走査しても、家庭内の規模なら問題にならない。

### 取り込み

- **取り込みのボディは、要素を生のJSONのまま並べた配列として読み、1件ずつ読み直す**: 1件の型の誤り(`title` が数値など)で全体が「リクエストの形式が不正です」にならず、「N件目: 形式が不正です」と何件目かを返せる。ボディが `null` のときは配列としての読み込みがエラーにならないので、読んだ結果がnilかどうかで配列でないと判断する(空の配列はnilにならず「取り込むレシピがありません」になる)。要素が `null` のときも構造体への読み込みがエラーにならず空の件になるので、`{` で始まらない要素は先に形式の誤りにする。
- **取り込みの作った回数は生のJSONのまま受け、整数のリテラルだけを受け付ける**: 整数型で受けると `3.0` や大きすぎる値で件全体が形式の誤りになり、`json.Number` で受けると `"3"` のような文字列も通ってしまう。省略とnullは0とし、負の数は業務ルールとしてserviceで弾く。
- **取り込みは全件を検査してから、1つのトランザクションで配列の順に登録する**: 1件でも不正なら1件も登録しないので、途中まで登録されたあとに送り直して二重に登録されることがない。handlerで読めなかった件も理由を付けてserviceへ渡し、検査とエラー文言の組み立てをserviceの1か所にまとめる。
- **取り込みの不正は1件につき最初の理由1つにまとめ、先頭から10件までを改行区切りで返し、残りは「ほかN件」とする**: 1回送れば何件かまとめて直せ、数百件が不正でもエラー文言が長くならない。理由は、handlerで読めなかったもの(形式の誤り・整数でない作った回数)→名前が空→作った回数が負、の順に決まる。そのため、名前が空で作った回数が `3.0` の件には作った回数の理由が出る。エラー文言に改行が入るので、取り込み画面のエラー欄は改行どおりに出す。
- **取り込みのボディの上限は5MBにし、上限を超えた時点で読むのをやめる**: 本文1,000字程度のレシピなら約1,500件まで一度に送れ、読み込みのメモリはPi Zeroにも収まる。画像と同じく、大きなボディをメモリに溜めない。
- **取り込みではタグを足すだけにし、未使用タグの削除は行わない**: 新しいレシピにタグを付けるだけなので未使用のタグは生まれず、1件ごとに未使用のタグを探さずに済む。タグを足す処理(同じ名前のタグが無ければ作る)は通常の保存と共用し、タグの作り方を1か所に保つ。
- **取り込みでは、同じ名前のレシピがあっても別のレシピとして登録する**: 名前はUNIQUEでなく、通常の作成と同じ扱いにする。
- **取り込み画面は貼った文字列をブラウザで解析せず、そのままサーバーへ送る**: 画面共通の「入力チェックはサーバーだけで行う」に合わせ、構文の誤りもサーバーの「リクエストの形式が不正です」に任せる。`api()` は本文が文字列のときは文字列化し直さずにそのまま送る。常に `JSON.stringify` するように変えると、ボディがJSONの文字列1つになり、配列でないとして弾かれる。
- **取り込みに成功したら貼り付け欄を空にし、失敗したら入力を残す**: もう一度「取り込む」を押しても、同じレシピが二重に登録されないようにする。失敗したときは、直して送り直せるようにする。
- **「取り込む」ボタンは詳細ページの「保存」と同じく上部の右に置き、結果とエラーは貼り付け欄の上に出す**: 貼り付け欄の高さによらず、スクロールしないで押せ、結果も押した位置の近くに出る。
- **受け付けるJSONの形の説明と例は貼り付け欄の下に常に出し、選択・コピーできるのは例だけにする**: スマホでも欄がすぐ目に入り、2回目からは読み飛ばして貼れる。例は写して自分のJSONを作れるようにし、説明の文はコピーする用が無いので選択できないままにする。
- **取り込み画面の「一覧へ戻る」は、詳細ページの「一覧へ戻る」と同じ判定で、一覧から来たときだけブラウザの戻ると同じに動かす**: 一覧の絞り込み条件を残すため。判定の式は使うのが2画面だけなので共通部品に移さず、各画面のJSに同じ式を書く。直すときは両方を直す。
- **一覧から取り込み画面へは、見出しの行の右端のアイコンだけのリンクで移る**: たまにしか使わない操作なので、タイルの並びには入れず小さく置く。

### 画面共通

- **画面は1つのHTMLと同名のJSに分け、画面によらない既定スタイルは base.css に置く**: 3画面の見た目を1か所でそろえる。base.css には要素の既定スタイルと役割クラスだけを書き、画面固有の部品のCSSは各HTMLの `<style>` に置く。HTMLでは base.css をアイコンのCSSの後に読み込む。同じ詳細度なら後の指定が効くので、配布ファイルを編集せずに base.css で上書きできる。
- **画面によらないJSの部品は `common.js` に置き、画面のJSより先に読み込む**: 一覧・詳細・取り込みで、API呼び出しや回数の表示を同じ処理で使う。置くのは、画面の要素IDや画面の状態を参照しない関数と定数だけにする。`common.js` が画面の要素IDを参照すると、その要素を持たない画面で動かなくなるため。
  - 要素が要る部品(「先頭へ戻る」、ダイアログの外側タップの判定)は、要素を各画面のHTMLに置き、引数で受け取る。特定の要素IDを前提にする確認ダイアログの処理は、そのダイアログを持つ詳細ページのJSに置く。
  - ES modulesにせず、クラシックスクリプトのグローバルで共有する。部品が少なく、画面ごとに `import` を並べる手間に見合わないため。HTMLでは `common.js` → 画面のJSの順に書く。画面のJSでは `common.js` と同じ名前をトップレベルで宣言しない(同名の `const` があるとエラーになる)。
- **入力チェックはサーバーだけで行う**: クライアントに二重実装せず、APIの `error` メッセージをそのまま表示する。
- **ボタン・入力欄・select・ダイアログ・画像・画像なしの枠は同じ枠線と角丸にそろえ、アイコンだけのボタンも角丸の四角にする**: 画面全体の形をそろえ、ボタンと入力欄が並んでも線の太さと色が同じに見えるようにする。編集フォームで画像を選んだり外したりしても、プレビューと「画像なし」枠の形が変わらない。
  - ボタンは白地に枠を付けたアウトラインにし、保存の色(`.primary`)と取り消せない操作の色(`.danger`)は役割クラスで付ける。色の意味をクラスで表し、画面ごとに色を書かないため。
  - ボタンは `inline-flex` でアイコンと文字を並べ、縦位置と間隔をそろえる。
  - 入力欄は内側に余白を取る。角丸にすると文字が角に寄って見えるため。
  - selectは `appearance` を変えず、ブラウザの矢印を残す。矢印を自前で描かずに済む。
  - 例外: 「先頭へ戻る」は丸くする。画像や本文の上に重なって浮かぶので、他のボタンと形を変えて浮いていることが分かるようにする。大きさ・枠・hoverと押している間の背景は他のボタンと同じ。
  - 例外: 一覧タイルのブックマークの下地と回数バッジは、角丸を他より小さくする。どちらも高さが小さく、同じ半径では両端が丸いカプセル形に見えて、他の部品の角丸の四角と形がそろわないため。小さくしすぎると角が尖って見えるので、角丸の四角に見える大きさにする。
- **影は、ほかの部品の上に重なる「先頭へ戻る」とダイアログにだけ付け、ダイアログの影を大きく広げる**: 重なっていることを影で表す。ダイアログは「先頭へ戻る」の上にも開くので、影を広げて一番手前にあると分かるようにする。影の濃さは同じにし、広がりだけで手前か奥かを表す。
- **タッチで押す部品(ボタン・ボタンの見た目のリンク・1行の入力欄・select)は高さ44px以上、アイコンだけのボタンは44px四方以上にする**: タッチで押しやすくする。base.css の要素と役割クラスの指定で決めるので、画面で部品を足せば何もしなくても満たす。
  - 例外: 一覧の検索欄の中の、探す対象の切り替えとキーワードの入力欄は低くする。検索欄の箱を縦に大きくしないため。どちらも左右いっぱいなので、タッチでも狙いやすい。
  - 例外: キーワードを消すボタンは、横幅を44pxのまま、高さを入力行に合わせる。入力行の右端に重ねるので、はみ出さないようにする。
  - 例外の部品は、画面の `<style>` で base.css の最小の高さを打ち消す(打ち消さないと44pxに広がる)。
- **ボタンとボタンの見た目のリンクは、hoverの背景を `@media (hover: hover)` の中だけで付け、押している間(`:active`)の背景は常に付ける**: タッチ端末ではタップ後にhoverが残り、押した後も色が付いたままに見えるため。押している間の手応えは `:active` で出す。
  - hover・押している間の背景は無効のボタンには付けず、無効のボタンは薄くする。保存中などに無効になったボタンが押せるように見えないようにする。
  - 例外の部品は、画面の `<style>` でIDを含む指定にして背景を透明にする。IDを含まないと、base.css のhover・押している間の背景のほうが優先されて出てしまう。
  - 例外: 一覧タイルのブックマークは、44px四方には背景を付けず、中の小さな下地にだけhover・押している間の色を付け、ブックマーク中の下地は変えない。透明な部分に色を付けると、小さな下地に見せた意味がなくなるため。
  - 例外: 一覧の検索欄の中の、キーワードを消すボタンと探す対象の切り替えは、hover・押している間も背景を付けない。検索欄の箱の枠の内側に重ねているので、背景を付けると角丸の枠線にかかって見えるため。
- **押すたびに状態が切り替わるボタン(「作った」・ブックマーク・絞り込み)は、押した状態を背景と枠の色で表し、`aria-pressed` で伝える**: 同梱しているのはoutline版のアイコンだけで、塗りつぶしに切り替えられないため。CSSは `aria-pressed` の値を見て色を付け、状態の値を1つにまとめる。色の指定はIDを含めて、base.css のhover・押している間の背景より優先させる(IDを含まないと、押した状態でもhoverや押している間に色が変わる)。
  - ブックマーク中は青系、「作った」はオレンジ系にする。両方が押された状態でも、色でどちらか分かるようにするため。
  - `aria-label` と `title` は状態で変えず、状態は `aria-pressed` だけで伝える。状態ごとに名前を変えると、読み上げで状態が二重に伝わるため。
  - 例外: 一覧タイルのブックマークは、背景と枠ではなく、小さな下地を濃い青にしてアイコンを白にする。画像の上の小さな下地でも、付いていると分かるようにするため。
- **アイコンだけのボタン・リンクには、`aria-label` と `title` にもとの文言を入れ、アイコン自体は `aria-hidden="true"` にする**: 読み上げではアイコンの文字ではなく名前が読まれ、PCではカーソルを合わせると意味が出る。
- **アイコンは意味ごとに決め、4節「アイコン」の表にアイコン名・このプロジェクトでの意味・使う所をまとめる**: 同じ意味に別のアイコンを使ったり、同じアイコンを別の意味に使ったりすると、画面によって意味がぶれるため。アイコンを足す・替えるときは、先に表を見て、同じ意味のものがあれば使い回す。画面の説明や設計判断には意味の言葉だけを書き、名前は表の1か所にまとめる。
- **作った回数はアイコンと数字だけで表し、0回は数字を出さない**: 一覧で作ったことのあるレシピが見分けやすく、文言を切り替える処理も要らない。
- **画面を移る操作はリンクにし、ボタンの見た目にするときは `<a class="button">` にする**: 長押しや中クリックで新しいタブにも開ける。base.css では `a.button` をボタンと同じ見た目にする。`<a>` は既定では枠を高さの外側に足すので、`box-sizing: border-box` を指定してボタンと高さをそろえる。
- **確認は詳細ページの確認 `<dialog>` 1つを文言違いで使い回し、`confirm()` は使わない**: 見た目を画面とそろえるため。使うのは削除と未保存の破棄だけで、どちらも取り消せない操作なので、OKボタンはHTMLで取り消せない操作の色に固定し、JSで切り替えない。ボタンは文字だけにする(OKの文言を「削除する」「破棄する」と差し替えて使い回すので、アイコンを固定できない)。
- **タグの札は base.css の役割クラスにし、「外す」ボタン付きの札はその変種にする**: 詳細の編集フォームと一覧の選択中タグの2画面で同じ札を使うため。一覧タイル上の札の小ささは一覧の `<style>` で上書きする。
- **textareaは上下だけ大きさを変えられるようにし、base.css の要素の指定に置く**: 入力欄は本文の列いっぱいの幅なので、横に広げると列からはみ出す。高さは長い本文を書くときに広げたいので、変えられるまま残す。どの画面でも同じtextareaの振る舞いなので、base.css に置く。
- **`[hidden]` には `display: none !important` を指定する**: `display` を指定した要素では `hidden` 属性が効かなくなるため。
- **UIの文字は body で選択できなくし、選ばせたい要素だけ選択できるように戻す**: 長押しやドラッグでボタン・見出し・タグの札が選択され、タッチ操作の邪魔になるのを防ぐ。既定を選択不可にしておくので、新しい画面を足しても、何もしなければ選択できない扱いになる。iOS Safari向けに `-webkit-user-select` も並べて書く。
  - 入力欄(`input`・`textarea`)と `[contenteditable]` は base.css で戻す。iOS Safariでは祖先に `-webkit-user-select: none` があると入力欄に文字を入力できなくなることがあり、貼り付け欄も戻さないと長押しの「ペースト」が出なくなるため。どれも要素の既定の振る舞いなので base.css に置く。
  - 画面固有の要素(詳細の名前と本文、取り込みの例)は各画面の `<style>` で戻し、base.css には書かない。どれを戻すかとその理由は各画面の項目に書く。
- **本文の列の幅は、一覧のタイルでも詳細と同じにして広げない**: 広い画面で操作が遠くならないようにする。
- **「先頭へ戻る」は、下へスクロールしているときだけ本文の列の右下に浮かせる**: 先頭にいるときは押しても何も起きないため出さない。本文の列の幅と同じく、広い画面で操作が遠くならないよう、本文の右端にそろえる。
  - 出すかどうかは、初期化時と `scroll`・`pageshow` で判定する。再読み込みやbfcacheからの復元でスクロール位置が戻ったときも正しく出すため。表示の切り替えや絞り込みでページが短くなったときは、ブラウザが `scroll` を出すので別に呼ばない。
  - 横の位置は、本文の列の右端と画面の端からの余白の、内側にある方にそろえ、`%` で求める。fixedの `%` はスクロールバーを除いた表示領域の幅が基準なので、本文の右端にそろう。狭い画面では本文の余白と同じだけ端から離れる。
  - なめらかにスクロールし、端末で動きを減らす設定のときだけすぐ移る。移動の様子が見えるので、どこへ戻ったかが分かるため。CSSの `scroll-behavior` は他のスクロールまで変わるので使わず、`scrollTo` の引数で指定する。
  - `body` の下の余白をボタンの高さ分広げる。ページの最後までスクロールしたとき、浮かせたボタンが最後のタイルや本文欄の右下(サイズを変える取っ手)を隠さないようにするため。

### 詳細ページ

- **「作った」は押すたびに切り替わる1つのボタンにし、取り消し専用のボタンは置かない**: SNSの「いいね」と同じく、押すと回数が増えて押した状態になり、もう一度押すと減って元に戻る。続けて押しても回数が重ねて増えず、取り消すと必ず開いたときの回数に戻る。
- **「作った」の押した状態は画面のJSだけで持ち、詳細ページを読み込むたびに押す前に戻す**: 記録したいのは回数で、誰がいつ押したかではないのでDBには持たない。編集に切り替えてもページを離れるまでは保つので、閲覧表示に戻ったあとも取り消せる。
- **ブックマークボタンは閲覧表示の操作ボタンの先頭(「作った」の左)に置く**: 状態を切り替えるボタン2つを隣に並べ、取り消せない削除からいちばん離して押し間違いを防ぐ。
- **ブックマークの状態は画面で持たず、サーバーの `bookmarked` をそのまま表示し、押したときは表示中の値を見てPUTかDELETEを選ぶ**: 「作った」と違い、ブックマークはDBに持つ状態のため。PUT/DELETEは何度送っても同じ結果になるので、別の端末で先に変わっていても返ってきたレシピで表示がそろう。失敗したときは `showView` を呼ばないので、表示は元のまま残る。
- **編集フォームの欄には見出しを付けず、名前・タグ・本文の欄はプレースホルダで示し、読み上げ用の名前は `aria-label` で付ける**: 見出しの行の分だけフォームが縦に伸び、スマホでは本文欄が下へ押し出されるため。プレースホルダは入力すると消えるが、欄の並び順と中身で区別できる。読み上げはプレースホルダに頼らず `aria-label` で名前を付ける。タグの入力欄は、付けた札の列と区別するため読み上げでは「追加するタグ」のままにする。画像欄は「画像なし」枠やプレビューで画像の欄だと分かるので、文言を足さない。
- **編集フォームの欄の間隔は `#edit-mode` の `display: flex; flex-direction: column; gap: 1rem` で決め、各欄の上下marginは0にする**: エラー文言・プレビュー・「画像なし」枠は状態によって出たり消えたりする。隠れた要素はgapに数えられないので、どの状態でも欄の間が1remにそろう。marginで取ると要素ごとの指定が重なり、間隔がずれやすい。タグ欄の中の入力行と札の列の間は欄の内側なので0.5remのままにする。
- **詳細は1件取得APIで読む**: 詳細ページは単独のURLで開くため、一覧のデータは使えない。`?id=` の値は検査せず `encodeURIComponent` してAPIへ渡し、サーバーの `error` 文言をそのまま出す(入力チェックはサーバーだけで行う)。例外は `?id=` が空のときで、パスが `/api/recipes/` になって静的配信の404が返り、意味のある文言が出ないため、画面側で「IDが不正です」を出す。
- **「一覧へ戻る」は、一覧から来たときだけ `history.back()` にする**: 判定は読み込み時の `document.referrer` が同じオリジンの `/recipes.html` かどうか。一覧の絞り込み条件をURLに残す項目を入れたとき、ブラウザの戻ると同じ動きにしておけば戻ったときも条件が残る。URLを直接開いたときなどは `recipes.html` へのリンクとして動く。
- **削除後は一覧へ移り、詳細のURLを履歴に残さない**: 一覧から来たときは `history.back()`、それ以外は `location.replace("recipes.html")` で移る。ブラウザの戻るで削除済みのレシピのページに戻らないようにする。
- **新規作成の保存では、POSTの直後に `history.replaceState` でURLを `?id=` 付きにする**: 画像の保存が失敗して編集フォームにとどまっても、再読み込みで同じレシピを開けるようにする。
- **詳細ページの操作ボタンは上部の戻るボタンと同じ行に置き、編集中は左端の「一覧へ戻る」を「キャンセル」に入れ替えて、右側は保存だけにする**: 本文が長くても、スクロールせずに閲覧表示のブックマーク・「作った」「編集」「削除」や編集中の「保存」「キャンセル」を押せるようにする。編集中は編集をやめる操作をキャンセル1つにまとめ、保存とキャンセルを左右に離して押し間違えを防ぐ。ヘッダーには `#back-link`・`#cancel-button`・閲覧表示用と編集中用の2つの `.actions` を並べ、`showView` / `showEdit` で `hidden` を入れ替える。読み込みエラーのときは `#back-link` だけを出す。保存ボタンはフォームの外に置き、`form="edit-mode"` で結び付ける(submitイベントも名前欄のEnterによる送信もフォーム内にあったときと同じく動く)。
- **編集フォームのエラー文言はフォームの先頭に置く**: 保存ボタンが上部にあるので、押した位置の近くに結果を出す。
- **詳細はまず閲覧表示にし、「編集」で入力フォームに切り替える**: 調理中の誤編集やキーボードの出現を防ぐため。本文は `white-space: pre-wrap` で書いたとおりの改行で表示し、URLの部分だけ `<a>`、残りはテキストノードで入れる(`innerHTML` を使わず、本文に書かれたHTMLを解釈させない)。
- **本文中のURLは `http://`・`https://` から空白やASCII以外の文字の手前までとし、末尾の句読点・閉じ括弧(`. , : ; ! ? ' " ) ] } >`)を外す**: 日本語の文中に書いたURLが、後ろの文字や「。」「)」を巻き込まないようにする。括弧の対応は数えないので `)` で終わるURLは末尾が欠けるが、レシピの出典URLでは稀なので受け入れる。
- **本文のリンクは新しいタブで開き、`rel="noopener noreferrer"` を付ける**: 調理中に見ているレシピの画面を残すため。開いた先からこのページを操作させず、LAN内のURLも送らない。
- **本文のリンクの処理は `recipe.js` に置き、`common.js` には置かない**: 使うのは詳細ページだけのため。
- **長いURLの折り返しは `#view-body a` にだけ `overflow-wrap: anywhere` を付ける**: 本文のほかの文字の折り返し方を変えないため。
- **編集のキャンセルでは、未保存の変更があれば確認する**: 変更の有無は編集開始時の値との比較。ページの離脱は次項の `beforeunload` で確認する。外側タップの判定は確認 `<dialog>` で使い、 `pointerdown` と `click` の対象がどちらも `<dialog>` 自身のときだけとみなし、テキスト選択のドラッグで閉じないようにする。
- **ページ離脱の確認は `beforeunload` でブラウザ標準のダイアログに任せる**: 詳細ページを分けたので、戻る・再読み込みで編集中の入力が消えるようになった。これらは画面内の確認 `<dialog>` では止められないため、編集中は一覧へ戻るボタンを出さないので、画面内で編集をやめる操作はキャンセル(画面内の確認 `<dialog>`)だけになる。確認するのは編集中で `isDirty()` が真のときだけ。リスナーは常に登録し、判定は中で行う。
- **画面内で確認済みの遷移では `leaving` を立てて `beforeunload` を素通りさせる**: 新規作成のキャンセルで「破棄する」を選んだ後に、ブラウザの確認を重ねて出さないため。`leaveToList()` で立て、bfcacheから戻ったときは `pageshow` の `persisted` で下ろす。
- **iOS Safariでは離脱確認が出ないことを受け入れる**: `beforeunload` の確認に対応していない。個人利用で、入力の自動保存などの代替はROADMAPに無いため作らない。
- **選んだ画像はブラウザで縮小・JPEG変換し、保存するまで送らない**: 長い辺が800pxを超えるときだけ縮め、canvasで品質0.85のJPEGにする。2MBの上限に収まり、Pi Zeroで画像を処理しなくて済む。保存前は送らないので、破棄してもサーバーには何も残らない。
- **変換は `<img>` に読み込んでcanvasへ描く**: ブラウザがEXIFの向きを反映した大きさで描くため、スマホの写真が横倒しにならない。描く前に白で塗り、透過PNGの透過部分が黒くならないようにする。
- **編集中の画像の変更は `imageChange`(null / `{blob,url}` / `"remove"`)の1つの値で持つ**: 未保存の判定と保存時に呼ぶAPIをこの値だけで決められる。もともと画像の無いレシピで外したときはnullに戻し、変更なしとして扱う。
- **保存はレシピのPOST/PUTを先に、画像APIを後に呼ぶ**: 新規作成では画像を送るためのidがPOSTまで無いため。画像だけが失敗したら、選んだ画像を残して編集フォームにとどまり、`current` を保存済みのレシピに替える(新規作成ならこの時点でURLも `?id=` 付きになっている)。再保存はPUTと画像の送り直しになり、新規作成でも二重に登録されない。
- **画像は幅いっぱい・高さ25vh固定とし、合わない分は `object-fit: cover` で切る**: 縦長・横長どちらの写真でも高さが一定になり、スマホでも名前・タグのすぐ下に本文が見える。閲覧表示と編集のプレビューで同じ見た目にする。画像が無いときの枠(`.no-image`)は文言・案内・ボタンが収まる高さ(10rem)が必要なので、画像の高さには合わせない。
- **編集フォームの画像欄は、画像の有無でできる操作だけを出す**: 画像が無いときは「画像なし」枠に貼り付けと「画像を選ぶ」を、画像があるときはプレビューに「画像を外す」だけを出し、下に並べるボタン行は置かない。その状態で使えない操作が並ばず迷わない。差し替えは外してから選び直す形にし、画像がある状態での貼り付けや選び直しでうっかり上書きしないようにする。
- **「画像を選ぶ」は `contenteditable` の外に置き、枠いっぱいの貼り付け層の上に重ねる**: ボタンを中に入れると編集できる中身の一部になり、`beforeinput`/`input` で中身を戻す処理とぶつかるため。「画像なし」と案内の文言は貼り付け層の中に置き、枠のどこを長押ししても「ペースト」が出るようにする。ボタンの層は `pointer-events: none` にしてボタンだけで受け、それ以外のタップは下の貼り付け層に届ける。枠の高さは、文言・案内・44pxのボタンを縦に並べても窮屈にならない10remにする。
- **「画像を外す」はアイコンだけにしてプレビューの右下に重ね、`.danger` にしない**: 画像を隠す範囲が小さい。外しても保存するまでは確定せずキャンセルで戻せるので、取り消せない操作に使う赤にはしない。
- **クリップボードの画像は `contenteditable` の欄の `paste` イベントで受ける**: `navigator.clipboard.read()` はHTTPのLAN内では使えないため。スマホの長押しに「ペースト」を出すため入力できる要素にし、`inputmode="none"` で画面キーボードを抑止する。
- **貼り付けた画像は「画像を選ぶ」と同じ `setPendingImage` に渡す**: 縮小・JPEG変換・プレビュー・未保存の判定・保存を、画像の入手方法によらず1つの流れにする。
- **貼り付け欄の中身は `beforeinput` で変えさせず、変わったら `input` で戻す**: `inputmode="none"` で止まるのはスマホの画面キーボードだけで、PCのキー入力やドロップは止まらないため。IME変換など止められない入力に備え、本来の中身を控えて入れ直す。
- **貼り付けは「画像なし」枠の上でだけ受け付ける**: ページ全体でCtrl+Vを拾うと、名前や本文への貼り付けと区別できないため。
- **処理中は貼り付け欄を無効にせず、貼り付けを無視する**: 欄が編集できないものに変わると、フォーカスや長押しメニューの動きが変わるため。
- **閲覧表示のレシピ名と本文だけを選択できるようにする**: 材料や出典URLをコピーしたいのはこの2つの要素だけのため。本文中のリンクは親に従う。一覧タイルの名前は、タイル全体が詳細へのリンクで長押しはリンクの操作に使うので、選択できないままにする。
- **タグ欄の「外す」は44px四方のアイコンだけのボタンにし、編集フォームの札は閲覧表示より大きくする**: アイコンだけのボタンはタッチで押しやすい44px以上にそろえる規則を優先する。閲覧表示の札は押す操作が無いので小さく出す。
- **タグの候補は、編集を始めるたびに `GET /api/tags` で読み、失敗しても無視する**: 別の端末で増えたタグも候補に出る。候補は入力の補助なので、取れなくても手で打てば足りる。付けているタグは候補から外す。
- **入力欄で、IMEの変換を確定するEnterではタグを足さない**: 日本語のタグ名を確定しただけで追加されないよう、`isComposing` と `keyCode === 229`(Safari向け)のときは何もしない。それ以外のEnterはフォームの送信を止めてタグを足す。
- **入力欄に文字を残したまま保存すると、その文字もタグとして足す**: 打ったタグが黙って消えないようにする。入力欄に文字があるだけでも未保存の変更とみなし、キャンセルや離脱で確認を出す。

### 一覧タイル

- **一覧タイルの枠線・角丸は `.tile-visual` に付け、`overflow: hidden` で中身を切り抜く**: 画像と名前の帯を1つの枠に収め、帯の下側の角を枠の角丸に合わせるため。回数バッジは枠の内側にあるので欠けない。
- **一覧タイルのブックマークの下地(`.tile-bookmark-mark`)と回数バッジ(`.tile-cooked`)は、タグの札と同じ枠線を付けた角丸の四角にする**: 左上と右上に並ぶ2つは枠線も半径もそろえる。角丸を他の部品より小さくする理由は「画面共通」の形の項目に書く。枠の色はブックマーク中の濃い青や回数の5段階目のオレンジの下地でも#999のままにし、変えるのは下地の色だけにする。余白は変えず、枠の分だけ外側が上下左右1pxずつ大きくなるが、2つとも同じだけ大きくなるので上端と高さはそろったままになる。
- **一覧は `pageshow` の `persisted` のときに読み直し、詳細は読み直さない**: 一覧はbfcacheから復元されると詳細ページでの保存・削除・「作った」が反映されないため。詳細は編集中の入力が消えないよう復元のままにする。
- **一覧はタイルグリッドにし、列数は `repeat(auto-fill, minmax(140px, 1fr))` だけで決める**: media queryを書かずにスマホは2列、40remの本文幅では4列までになる。
- **名前は画像の有無によらず正方形の下端の半透明の黒い帯に白文字1行で重ね、枠外には出さない**: タイルが正方形1つにそろい、画像なしでも同じ場所で名前を読める。長い名前は `text-overflow: ellipsis` で省略し、全文はタイルの `title` と詳細で確認する。文字の大きさは帯の上のタグの札と同じ0.7remにする。タイル幅140px前後では0.9remだと短い名前でも省略され、0.8remでもまだ省略が多かったため、札と同じ大きさまで下げた。
- **画像なしタイルの中央には名前ではなく薄い色の ti-photo-off を置く**: 名前は帯に出るので二重に出さず、画像が無いことを一目で分かるようにする。
- **一覧タイルは `<li>` の中に、詳細へのリンク `<a class="tile">` とブックマークボタンを兄弟要素として並べ、ボタンを `position: absolute` でリンクの正方形の左上に重ねる**: `<a>` の中に `<button>` を入れるのはHTMLとして不正で、押したときにリンクへ移ってしまうため。`li` を `position: relative` にして重ねる基準にし、包む要素は増やさない。リンクの見た目は正方形だけにし、輪郭は `.tile-visual` の枠線が担う。リンクの下線と文字色は打ち消す。
- **一覧タイルのブックマークボタンは、付いていないときも常に出す**: タッチ端末にはhoverが無く、出さないと付ける手段が見つからないため。左上に置き、右上の回数バッジ・下端の札と名前の帯と重ならないようにする。
- **一覧タイルのブックマークボタンは、44px四方の透明で枠のないボタンの中に、回数バッジと同じ形の下地(`.tile-bookmark-mark`)を入れて小さく見せる**: 押せる範囲はタッチで押しやすい44px四方のまま残し、画像を隠す範囲だけをバッジと同じ大きさに抑える。ボタンはタイルの角(`top: 0; left: 0`)に置き、内側の余白(`0.3rem` + `.tile-visual` の枠線1px)で下地を寄せて、下地の上端をバッジの `top: 0.3rem` とそろえる。下地の余白・行の高さ・アイコンの大きさ・枠線・角丸は `.tile-cooked` と同じにして高さをそろえる。
- **一覧タイルのブックマークボタンの `aria-label` と `title` は「「名前」をブックマーク」にする**: 一覧には同じボタンが並ぶので、読み上げでどのレシピのボタンか分かるよう名前を入れる(選択中タグの「「名前」を外す」と同じ形)。
- **一覧でブックマークの付け外しに成功したら、返ってきたレシピで `recipes` の該当件を置き換えて `renderList()` で描き直す**: ボタンだけを書き換えると、別の端末で変わった名前や回数が配列とずれる。絞り込みの結果も `filteredRecipes()` から作り直されるので、表示が常に配列と一致する。押したボタンにフォーカスがあったときは、作り直した同じレシピのボタンに戻す。
- **一覧のブックマークの送信中は、そのレシピのボタンだけを無効にし、送信中のidを `bookmarkBusy` で持つ**: 別のタイルは続けて押せるようにする。別のタイルの成功で `renderList()` が走ってボタンが作り直されても、`createTile` がこの集合を見て無効のままにする。
- **一覧でブックマークの付け外しに失敗したら、`recipes` も描画も変えず、サーバーの `error` 文言を一覧のエラー欄に出す**: 詳細ページと同じく、表示中の状態を元のまま残す。エラー欄は次の付け外しと一覧の読み直しで空にする。
- **一覧の行と列の間隔はどちらも0.5remにする**: 名前の行が枠外になくなり、行の間を広げて名前との対応を示す必要がなくなったため。
- **一覧の画像は `loading="lazy"` で読む**: 縮小せず出すので、画面外のタイルの画像までPi Zeroから一度に取りに行かないようにする。サムネイルは作らない。
- **作った回数のバッジは `cookedContent()` を使い回し、クラスを足して重ねる**: 詳細の「作った」ボタンとアイコン・数字の中身を1か所で決める。出すかどうかと色は一覧の `createTile` と `.tile-cooked` だけで決め、詳細は0回でもアイコンを出して見た目も変えない(押して回数を変える操作のため)。
- **一覧タイルの回数バッジは0回のとき出さず、1回以上は下地のオレンジの濃さで回数の多さを示す**: よく作るレシピが一覧で一目で分かるようにするため。0回で出さないのは、まだ作っていないレシピを見分けやすくするため。段階は `Math.ceil(回数 * 5 / 最大値)` の1〜5で、`回数 / 最大値 * 5` の順だと境目の値が小数の誤差で次の段階に上がることがあるため、掛けてから割る。最大値は絞り込む前の `recipes` 全件から `renderList()` のたびに求めて `createTile` に渡すので、絞り込み・検索・並び替えで同じレシピの色は変わらず、読み直しで回数が変わっても全タイルが同じ基準で描かれる。段階はバッジの `data-level` に入れ、色は `recipes.html` の `.tile-cooked[data-level="N"]` に付ける色は白(#ffffff)と #ffab1a の間をRGBの成分ごとに4等分して補間した5色にし、段階が上がるほど同じ幅で濃くなるようにする。5段階目だけ `color: #fff` でアイコンも白にし、1〜4段階目は下地が明るいので黒のままにする。枠線は5段階とも#999のままにし、色を変えるのは下地だけにする。
- **一覧の回数バッジは `.tile-cooked` に `line-height: 1rem` を指定し、アイコンと数字を同じ高さの行に収める**: アイコンはTabler Iconsの `line-height: 1` で1remの高さだが、数字は既定の行高でそれより高くなり、アイコンだけのときと数字があるときでバッジの高さが変わっていた。幅は桁数に合わせて変わるままにする。共用の `.cooked` でなく `.tile-cooked` に書くのは、詳細の「作った」ボタンを変えないため。
- **レシピの追加は一覧先頭のパネルから行い、ヘッダーに新規作成ボタンは置かない**: 追加の入口がタイルと同じ並びにあり、タッチ端末でも大きな的になる。0件でも同じ場所に出るので、空状態の案内文は要らない。
- **追加パネルは一覧の読み込みに成功したときだけ出す**: 失敗したときに追加の入口だけが出ると、一覧が空と見分けがつかないため。一覧のエラー欄は `.error` にして、空のときは隠す。
- **追加パネルは名前の帯と回数バッジを付けず、破線の枠で中央に ti-plus と「追加」を出す**: レシピのタイルと形と大きさをそろえながら、レシピではないことを一目で分かるようにする。枠は他と同じ1pxにし、枠と文字の色はボタンにそろえて #999 と #555 にし、hover/activeの背景もボタンと同じ規則(hoverは `@media (hover: hover)` の中だけ)で付ける。
- **追加パネルは `loadList()` の中でJSから作る**: 一覧を読み直すときにリストを丸ごと空にして作り直すため。HTMLに固定で置くと、読み直すたびに残す処理が要る。
- **タイルのタグは名前の帯のすぐ上に1行で並べ、はみ出す分は末尾から隠して「+N」にまとめる。タグで絞り込んでいるときは、選んでいるタグを除いて並べる**: タイルの大きさを変えずに付いているタグが分かる。選んでいるタグは表示中のどのタイルにも付いていて、選択中タグの札の行にも出ているので、タイルからは除いて残りのタグを見やすくする。除くのは `createTile` で札を作る前に行い、Nは並べるタグのうち隠した数とする。残りが0件なら札の行を出さない。タグを選ぶたびに `renderList()` でタイルを作り直すので、外したタグはすぐ戻る。収まるかは描画後に `scrollWidth` で測り、列数が変わる `resize` のたびに測り直す(rAFで1回にまとめる)。1つ目だけでも収まらないときはそのタグを「…」で省略する。札の行と名前の帯は `.tile-footer` にまとめて下端に置き、札の行の高さを決め打ちしない。タイル上の札は押しても絞り込まない(タイル全体が詳細へのリンクのため)。
- **名前がちょうど「好評」のタグが付いたレシピは、一覧タイルの `.tile-visual` に `popular` クラスを付け、枠線を無くして、`::after` の重ねで内側にオレンジ(#ff8000)の縁(`box-shadow: inset 0 0 1px 4px`)を描く**: アイコンを足さずに、よく褒められたレシピが一覧で目に入るようにする。オレンジにしたのは写真に重ねて目立つ色だからで、回数バッジの5段階目と色は近いが、形と位置(タイルの縁全体)で見分けられる。判定は `POPULAR_TAG` との完全一致で、`normalizeForSearch` は通さない(「好評!」「大好評」を対象にしないため)。絞り込み前の `recipe.tags` で判定するので、「好評」で絞り込んでいても強調は残る。
- **強調はタイルの内側に描き、外側のグローは使わない**: 以前は外側に `box-shadow` のグローを付けていたが、好評のタイルが並ぶとグリッドの間隔(0.5rem)が色で埋まり、隣の好評でないタイルまで縁取られて見えた。内側に描けば強調がそのタイルの枠の中に収まる。`.tile-visual` に直接 inset の影を付けると、全面に敷いた画像の下に隠れるため、`::after` を一番手前に重ね、`pointer-events: none` でタップをリンクへ通す。角丸は `.tile-visual` の8pxから枠の1pxを引いた7pxにする。
- **縁は `mix-blend-mode: plus-lighter`(加算合成)で重ね、2秒周期で `opacity` を0〜1に往復させる。端末が `prefers-reduced-motion: reduce` のときは明滅を止め、光ったまま(`opacity: 1`)にする**: 値は写真に重ねて見ながら決めた。加算合成なら写真の色を塗りつぶさずに縁が光って見え、明滅の動きで密集していても好評のタイルだけを見分けやすい。`opacity` が0まで下がり、好評でないタイルと区別がつかない瞬間があることは、承知の上で選んだ。画像なしのタイルは薄い灰色(#eee)の下地なので、加算すると縁がほぼ白になりほとんど強調されない。これも承知の上で、指定は分けない。
- **好評のタイルは枠線を0にし、回数バッジの `top` を `calc(0.3rem + 1px)` にする**: 枠線が無くなると、`.tile-visual` の中にある回数バッジが1px上がり、外から位置を決めているブックマークの下地(`calc(0.3rem + 1px)`)と上端がずれる。その1px分をバッジの `top` に足してそろえる。
- **明滅は `opacity` だけを動かす**: `box-shadow` そのものを動かすより描き直しの負担が軽く、タイルの多い一覧でもスマホやタブレットで重くなりにくい。
- **強調するのは一覧タイルだけで、詳細ページ・トグルボタン・API・取り込みの項目・絞り込みは足さない**: 好評はタグ1つで表すので、付け外しは編集フォームのタグ欄、絞り込みは今のタグの絞り込みで足りる。
- **強調したタイルでは「好評」の札を札の行に並べず、「+N」にも数えない。代わりに、見えない `.tile-popular-label`(「好評」)を `.tile-footer` の先頭に置く**: 内側の縁の明滅で分かることを札で二重に示さず、ほかのタグの場所を空ける。見えない文字はリンクの読み上げ名に残し、読み上げでも好評だと分かるようにする。札の行の外に置くのは、`fitTileTags` の測り方と「+N」の数え方を変えないため。「好評」で絞り込んでいるときは、ほかの選択中タグと同じく読み上げ名からも除く。見えなくするクラスは使うのがこの画面だけなので、`base.css` ではなく `recipes.html` の `<style>` に置く。

### 一覧の絞り込み

- **タグの絞り込みは一覧APIの結果を画面内で絞るだけにし、サーバーに絞り込みのAPIを作らない**: 一覧APIは全件をタグ付きで返し、家庭内の規模ならブラウザで絞っても十分速い。タグを押すたびに通信しなくて済む。
- **一覧の読み込みは `GET /api/recipes` と `GET /api/tags` を並行して呼び、どちらかが失敗したら一覧の読み込み失敗として扱う**: ダイアログのタグをid昇順に並べるため(レシピのJSONにidは無い)。片方だけで画面を出すと、タグが欠けたまま絞り込めてしまう。
- **選んでいるタグはid昇順で持ち、URLの `?tag=名前`(複数なら繰り返し)に `history.replaceState` で書き戻す**: 詳細から戻ったとき・再読み込み・bfcacheからの復元のどれでも、`loadList()` でURLを読み直すだけで同じ状態になる。`pushState` にしないのは、タグを押すたびに履歴が増えて、戻るで一覧から出られなくなるため。URLにあっても存在しないタグは読み込み時に捨て、URLからも消す。
- **並べ替えは `filteredRecipes()` の中で絞り込んだ後に行う**: 一覧の描画と、ブックマークを外したあとのフォーカスの移り先が、同じ並びで位置を数える。`recipes` 自体の並び(APIのid昇順)は変えない。
- **名前は `Intl.Collator('ja')` で比べ、漢字の名前が読みの順にならないことは受け入れる**: 読みを持つ列が無いため。ひらがな・カタカナは五十音に近い順になる。Collatorは1つ作って使い回す。
- **名前が同じなら新着順、作った回数が同じなら名前順、それも同じなら新着順で決める**: 最後に必ずidで決まるので、選び直しや読み直しで並びが入れ替わらない。
- **既定の並び順は新着順(id降順)にする**: 追加したばかりのレシピが追加パネルのすぐ後ろに出る。
- **並び順は `?sort=name` / `cooked-desc` / `cooked-asc` として `replaceState` で残し、新着順のときは付けない。知らない値は新着順として扱い、読み込み時にURLから消す**: タグ・キーワード・ブックマークと同じく、詳細から戻ったとき・再読み込み・bfcacheからの復元で同じ並びになる。読み込み時はselectの値もURLから入れ直し、ブラウザの復元値と食い違わないようにする。
- **並び順は `<select>` にし、絞り込みの行の右端に `margin-left: auto` で寄せる**: 4つから1つを選ぶ操作で、ボタンを並べると狭い画面で行が何段にも折り返すため。右端なのでタグの札が増えても左側の並びが動かない。見出しは付けず、読み上げ用に `aria-label`「並び順」を付ける。
- **絞り込みの行は一覧の読み込みに成功したときだけ出し、タグが0件でも出す**: 追加パネルと同じく、失敗したときに操作だけが出ないようにし、0件でも画面の並びを一定にする。押すとダイアログで「一緒に選べるタグはありません」と分かる。
- **タグ選択ダイアログは開いたとき閉じるボタンにフォーカスし、決定ボタンを置かない**: スマホ・タブレットで開くたびに画面キーボードが出てタグが隠れないようにするため。押すたびに裏の一覧とURLへ即反映するので、閉じる操作(閉じるボタン・Esc・外側タップ)はどれでも選んだ状態が同じで、取り消しの扱いが要らない。
- **ダイアログに並べるのは、選んでいるタグと、今の絞り込み結果に付いているタグだけにする**: 押すと0件になるタグを出さない。選んでいるタグは入力によらず常に出し、押した状態のまま外せる。押した状態は青系の背景・枠・文字と ti-check で示し、色だけに頼らない。描き直したあとは同じタグのボタンへフォーカスを戻し、無ければ閉じるボタンへ戻す。
- **文字の比べ方は `normalizeForSearch`(NFKC・小文字化・カタカナ U+30A1〜U+30F6 のひらがな化の順)で正規化して部分一致を取る(`matchesKeyword`)**: 全角と半角、大文字と小文字、ひらがなとカタカナを区別せずに探せる。半角カナを先にNFKCで全角にしてからひらがなへ置き換える。キーワードは正規化した後に空白(全角空白はNFKCで半角になる)で語に分け、すべての語を含むときに一致とする(AND、語の順は問わない)。語が無い(空や空白だけの)キーワードは常に一致とする。キーワードの検索とタグ選択ダイアログの検索で同じ関数を使い、入力の規則をそろえる(空白を含むタグ名は語ごとのANDで探すことになる)。
- **「条件に合うレシピがありません」は、ブックマーク・タグ・キーワードのどれかで絞っていて0件のときだけ出す**: 絞っていないときの0件はレシピが無いだけで、追加パネルで足りる。追加パネルは絞り込み中も先頭に出す。
- **キーワードの検索も一覧APIの結果を画面内で絞るだけにし、条件は `filteredRecipes()` 1か所(`matchesSearch`)でタグ・ブックマークとANDにする**: ダイアログの候補も同じ結果から作るので、キーワードを入れると選ぶと0件になるタグが自然に消える。
- **ブックマークの絞り込みも一覧APIの結果を画面内で絞るだけにし、条件は `filteredRecipes()` の `bookmarked` でタグ・キーワードとANDにする**: 押すたびに通信しない。タグ選択ダイアログの候補も同じ結果から作るので、ブックマーク中のレシピに付いていないタグは出ない。
- **ブックマークの絞り込みはアイコンだけのトグルにし、絞り込みの行の先頭(「タグ」ボタンの左)に置く**: 先頭ならタグを選んで札が増えても位置が変わらず、「タグ」ボタンと札も隣り合ったままになる。押した状態はタイル・詳細のブックマークボタンと同じ青系の背景と枠で示す。
- **絞り込みボタンの `aria-label` と `title` は「ブックマークで絞り込む」にする**: タイルの「「名前」をブックマーク」(付け外し)と読み上げで区別できるようにする。
- **ブックマークの絞り込みは `?bookmark=1` として `replaceState` で残し、`1` 以外の値は押していない扱いにして読み込み時にURLから消す**: タグ・キーワードと同じく、詳細から戻ったとき・再読み込み・bfcacheからの復元のどれでも同じ状態になる。
- **ブックマークで絞っている間にタイルで外したレシピは、成功後の `renderList()` で消えるだけにし、専用の処理を置かない。押したボタンが消えたときは、詰めてきた同じ位置のタイル、末尾だったなら1つ前のタイル、1件も残らなければ絞り込みのボタンへフォーカスを移す**: 一覧が常に配列と絞り込み条件に一致する。フォーカスが `body` に落ちず、続けて外していける。
- **キーワードは前後の空白を除いた入力のまま `?q=` に入れ、空なら付けない**: 語に分けた形で持たず、欄に戻したときに打ったとおりの文字が出る。タグと同じく `replaceState` で書き戻し、`loadList()` でURLから欄に戻す(再読み込み時にブラウザが入力欄を復元しても、URLの値で上書きして表示と条件をそろえる)。
- **キーワードの検索はIMEの変換中も入力のたびに絞り込み、EnterはIME確定中でなければフォーカスを外すだけにする**: ひらがなとカタカナを区別しないので、変換前の読みでもカタカナの名前に一致する。結果は入力のたびに出るので送信の操作は要らず、スマホでは画面キーボードが閉じて結果が見える。
- **キーワードを消すボタンは入力欄(入力行)の右端に重ねたアイコンだけのボタンにし、キーワードがあるときだけ出す**: `type="search"` の標準ボタンはブラウザによって出ず小さいため自前で置く。消したあとは入力欄にフォーカスを戻す。大きさとhoverは「画面共通」の44pxとhoverの項目の例外。検索欄は一覧の読み込みに成功したときだけ出す。
- **探す対象(名前のみ/名前と本文)は、検索欄の箱の内側の上段に置いた、左右いっぱいのリンク風のボタンで切り替える**: 絞り込みの行には余裕が無いため、ボタンを足さずに検索欄の中にまとめる。今の対象の文言をそのまま出し、押すたびに切り替える。2つから選ぶだけなので `<select>` にはしない。高さは「画面共通」の44pxの項目の例外にする。下線とti-repeatで、押すと切り替わることを示す。下線は文字の `<span>` にだけ付ける(inline-flexのボタンに付けると、アイコンにも下線が引かれるため)。
- **検索欄は外側の `.search-box` に1px・#999の枠と角丸8pxを付け、中の切り替えボタンと入力欄は枠をなくす**: ラベル行と入力行を1つの欄に見せるため。中の角の半径は、枠の内側に合わせて7pxにする。入力欄のフォーカスの枠は、ブラウザ既定のoutlineのままにする。入力欄の高さは「画面共通」の44pxの項目の例外にする。文字はiOS Safariがフォーカス時に拡大しないよう1remのまま変えない。
- **切り替えボタンの読み上げ名は見えている文言(今の対象)にし、入力欄の `aria-label` も同じ文言に合わせる。プレースホルダは「キーワード」に固定する**: 入力欄に入ったとき、読み上げで今どの対象から探すかが分かるようにする。ラベル行と同じ文言が2回並ぶのを避けるため、プレースホルダは対象を言わない。切り替えボタンの `title`「探す対象を切り替える」は、PCのカーソル表示と読み上げの補足になる。
- **「名前と本文」では、名前と本文を改行でつないだ1つの文字列に `matchesKeyword` をかける(`matchesSearch`)**: 語は空白で区切った後なので空白を含まず、つなぎ目の改行をまたいで一致することがない。そのため「語ごとに、名前か本文のどちらかに含まれれば一致」と同じ結果になる。文字の比べ方(`normalizeForSearch`)は名前のみの検索・タグの検索と同じ関数のまま使う。本文の正規化は入力のたびに全件で行うが、ブラウザ側の処理で、家庭内の規模なら十分速い。
- **既定の対象は名前のみにし、「名前と本文」のときだけ `?scope=body` を `replaceState` で残す。キーワードが空でも残す。`body` 以外の値は名前のみとして扱い、読み込み時にURLから消す**: 本文には材料や手順の語が多く、名前で探したいときに関係ないレシピが混ざるため、既定は狭くする。キーワードを消して打ち直すときや、詳細から戻ったときにも、選んだ対象のまま探せるようにする。
- **キーワードを消すボタンでは対象を戻さない。対象だけを変えても「条件に合うレシピがありません」の判定には入れない**: 消すのはキーワードで、対象は探し方の設定のため。キーワードが空なら対象によらず絞らない。
- **検索欄のID・変数名は `search-input`・`search-clear`・`searchKeyword` にする**: 本文も探すようになり、「name」を含む名前が中身と合わなくなったため。
