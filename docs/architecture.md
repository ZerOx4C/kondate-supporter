# 設計概要

コード構成・DB・API・画面の現状と、逆行を防ぐための設計判断をまとめる。
1〜4節は実装時に実態へ合わせて更新し、5節には `architect` の計画に含まれる設計判断を、該当する見出しの下へ転記する。どの見出しにも当たらないときは見出しを足す。

書き方の決まり:

- 4節・5節には、色コード・px・周期などの見た目の値を書かず、CSSを正とする。値そのものが判断の中身のとき(タッチで押せる44pxなど)だけ書く
- 関数名・変数名・セレクタは、書き方を変えると壊れる注意のときだけ書く
- 5節の各項目には、逆行を防ぐ理由を書く。理由の無い決定は書かない
- アイコン名(Tabler Iconsのクラス名)は4節「アイコン」の表にだけ書き、画面の説明と5節では表の「意味」の言葉で書く

## 2. DBスキーマ

### `recipes`(レシピ)
| カラム | 型/制約 |
|---|---|
| id | INTEGER PRIMARY KEY |
| name | TEXT NOT NULL(タイトル) |
| body | TEXT NOT NULL DEFAULT ''(材料・調味料・手順を含む自由テキスト) |
| cooked_count | INTEGER NOT NULL DEFAULT 0(作った回数) |
| servings | INTEGER NOT NULL DEFAULT 0(人数。0〜99、0は未設定) |
| image_version | INTEGER NOT NULL DEFAULT 0(画像を保存した回数。画像URLの `v` に使う) |
| image | BLOB(JPEG。NULLなら画像なし。必ず最後の列にする) |

### `tags`(タグ)
| カラム | 型/制約 |
|---|---|
| id | INTEGER PRIMARY KEY |
| name | TEXT NOT NULL UNIQUE(大文字・小文字を区別) |

### `recipe_tags`(レシピとタグの紐付け)
| カラム | 型/制約 |
|---|---|
| recipe_id | INTEGER NOT NULL REFERENCES recipes(id) ON DELETE CASCADE |
| tag_id | INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE |

主キーは `(recipe_id, tag_id)`。どのレシピにも付いていないタグはレシピの保存・削除と同じトランザクションで消すので、`tags` には使われているタグだけが残る。

### `recipe_bookmarks`(ブックマーク)
| カラム | 型/制約 |
|---|---|
| recipe_id | INTEGER PRIMARY KEY REFERENCES recipes(id) ON DELETE CASCADE |

行があればブックマーク中。レシピを消すとCASCADEで消える。

### `recipe_ingredients`(材料)
| カラム | 型/制約 |
|---|---|
| recipe_id | INTEGER NOT NULL REFERENCES recipes(id) ON DELETE CASCADE |
| position | INTEGER NOT NULL(並び順。保存した行の0始まりの連番) |
| name | TEXT NOT NULL |
| quantity | REAL(量に数が無ければNULL) |
| format | TEXT NOT NULL(量の文字列のうち、数の位置をプレースホルダ `{0}` で表したもの。数が無ければ量の文字列そのもの) |

主キーは `(recipe_id, position)`。レシピを消すとCASCADEで消える。

### `plans`(献立に置いたレシピとメモ)
| カラム | 型/制約 |
|---|---|
| id | INTEGER PRIMARY KEY |
| date | TEXT(`YYYY-MM-DD`。NULLなら毎日か候補) |
| meal | TEXT(`breakfast`・`lunch`・`dinner`・`candidate`。NULLなら時間帯なしで、毎日の行だけ。`candidate` は日付がNULLの行だけで、献立の候補) |
| position | INTEGER NOT NULL(同じ date と meal の中の並び順。連番とは限らない) |
| recipe_id | INTEGER REFERENCES recipes(id) ON DELETE CASCADE(レシピの行だけが持つ。メモの行はNULL) |
| memo | TEXT(メモの文。前後の空白を除いて保存する。レシピの行はNULL) |

`CHECK ((recipe_id IS NULL) <> (memo IS NULL))` で、1行はレシピかメモのちょうど一方を持つ。インデックスは `plans_date_meal_position`(`(date, meal, position)`)。同じエリアとは、`date` と `meal` が同じ行のこと。同じエリアに同じレシピの行がいくつあってもよい。レシピを消すとCASCADEで消えるのはそのレシピの行だけで、メモの行は残る。

### `schema_migrations`(マイグレーション適用履歴)
| カラム | 型/制約 |
|---|---|
| name | TEXT PRIMARY KEY(マイグレーションファイル名) |
| applied_at | TEXT NOT NULL DEFAULT (datetime('now')) |

`internal/db/db.go` の `Migrate()` が `main.go` から起動時に呼ばれ、 `internal/db/migrations/*.sql` を未適用のものだけファイル名昇順・1ファイル1トランザクションで適用する。

## 3. APIエンドポイント

ルーティングは `internal/handler/router.go` の `NewRouter()` に集約する(Go 1.22以降のメソッド付きパターン)。レシピのJSONは `{"id","name","body","cooked_count","servings","tags","bookmarked","ingredients","image_url"}`(`servings` は人数で0〜99の整数、0は未設定。`tags` はタグ名の配列でタグのid昇順、無ければ `[]`。`bookmarked` はブックマーク中ならtrue。`ingredients` は `[{"name","quantity","format"}]` で並び順どおり、無ければ `[]`。`quantity` は数値か、量に数が無ければnull。`image_url` は画像があれば `/api/recipes/{id}/image?v={image_version}`、無ければnull)。POST/PUTのリクエストは `{"name","body","servings","tags","ingredients"}` で、`servings` が無い・nullなら0として扱い、整数のリテラルでない値(`2.5`・`"2"`・`1e2`)と0〜99の範囲外は400。`tags` が無い・nullなら空として扱い、そのレシピのタグを丸ごと置き換える(前後の空白を除き、空は捨て、完全一致の重複はまとめ、同じ名前のタグが無ければ作る)。`ingredients` は `[{"name","amount"}]`(`amount` は量の文字列)で、こちらも無い・nullなら空として扱い、丸ごと置き換える。名前と量の前後の空白を除き、両方空の行は捨てる。名前が空の行はエラー。量の数は半角・全角の数字の並び(間に小数点 `.`・`．` が1つあってもよい)で、1つなら半角にして `quantity` にし、その部分を `{0}` に置き換えた残りを `format` にする(「大さじ1.5杯」→1.5と「大さじ{0}杯」)。数が無ければ `quantity` はnull、`format` は量そのまま。2つ以上ある量(「1/3本」「2〜3個」「1,000g」)と、float64に収まらない大きさの数はエラー。材料のエラーは先頭の1件だけを400で返し、「材料N行目: 名前を入力してください」「材料N行目: 量に書ける数は1つまでです(分数・範囲・桁区切りは使えません)」「材料N行目: 量の数が大きすぎます」のどれか(Nは送られた配列での行番号)。PUTは `cooked_count`・`bookmarked`・画像を受け付けず値も変えない。献立に置いた1件のJSONは `{"id","date","meal","recipe_id","memo"}`(`date`・`meal` は毎日ならnull。候補は `date` がnullで `meal` が `candidate`。レシピの行は `memo` がnull、メモの行は `recipe_id` がnull)。

| メソッド パス | 概要 |
|---|---|
| GET /healthz | 死活監視用(`{"status":"ok"}`固定) |
| GET /dev-mode.css | 画面の背景の模様のCSS。`DEV_MODE=1` のときは `body` に白の背景色と dev-mode.svg の繰り返しを指定し、そうでないときは中身が空。どちらも200・`text/css` |
| GET /api/recipes | レシピ一覧取得。200で配列(id昇順、bodyとtagsを含む。0件は `[]`) |
| GET /api/tags | 使われているタグ名の配列(id昇順、0件は `[]`) |
| GET /api/ingredient-names | 使われている材料名の配列(完全一致の重複なし。使っているレシピが多い順、同数は最初に使ったレシピのid順、同じレシピの中では並び順。0件は `[]`) |
| POST /api/recipes | レシピ新規作成。リクエスト `{"name","body","servings","tags","ingredients"}`、201で作成したレシピ |
| POST /api/recipes/import | レシピをまとめて登録。リクエストは配列 `[{"title","body","tags","cooked_count"}, ...]`(`title` 以外は省略・null可。`body` は空文字、`tags` は空、`cooked_count` は0)。全件を1トランザクションで配列の順に登録し、201で `{"count": 件数}`。上限5MB。画像・ブックマーク・材料・人数は扱わない(取り込んだレシピはブックマークも材料もなく、人数は0) |
| GET /api/recipes/{id} | レシピ1件取得。200 |
| PUT /api/recipes/{id} | レシピ更新(全体置換)。リクエストは作成と同じ、200で更新後のレシピ |
| DELETE /api/recipes/{id} | レシピ削除。204(ボディなし) |
| POST /api/recipes/{id}/cooked | 作った回数を1増やす。200で更新後のレシピ |
| DELETE /api/recipes/{id}/cooked | 作った回数を1減らす(0未満にはしない)。200で更新後のレシピ |
| PUT /api/recipes/{id}/bookmark | ブックマークを付ける。すでに付いていても200で更新後のレシピ |
| DELETE /api/recipes/{id}/bookmark | ブックマークを外す。付いていなくても200で更新後のレシピ |
| PUT /api/recipes/{id}/image | 画像を保存(`image_version` を1増やす)。ボディはJPEGのバイト列そのまま(上限2MB)。200で更新後のレシピ |
| DELETE /api/recipes/{id}/image | 画像を外す。画像が無くても200で更新後のレシピ |
| GET /api/recipes/{id}/image | 画像のバイト列。`Content-Type: image/jpeg`、`Cache-Control: public, max-age=31536000, immutable`。`?v=` は見ない |
| GET /api/plans?from=YYYY-MM-DD&to=YYYY-MM-DD | 毎日と候補と、from〜to(両端を含む)の日付に置いた行を返す。200で配列。毎日、候補の順で、その後は日付順、同じ日付の中は朝・昼・夜の順、同じエリアの中は並び順。0件は `[]` |
| POST /api/plans | 献立にレシピかメモを1件置く。リクエスト `{"date","meal","recipe_id","memo","index"}`で、`recipe_id` と `memo` はどちらか一方だけを受ける(両方ある・両方無いときは400「リクエストの形式が不正です」)。`memo` は前後の空白を除いて保存し、空なら400「メモを入力してください」。`date` が無い・nullなら毎日か候補で、`meal` は無い・null(毎日)か `candidate`(候補)だけ。日付の行の `meal` は朝・昼・夜のどれかが必須で、無い・nullや `candidate` は不可。`index` はその `date` と `meal` のエリアの画面上の並びでの0始まりの位置で、無ければ0。負なら先頭、件数以上なら末尾に入れる。201で置いた1件 |
| PUT /api/plans/{id}/memo | メモの行の文を書き換える。リクエスト `{"memo"}`(無い・nullは400「リクエストの形式が不正です」)。`memo` は前後の空白を除いて保存し、空なら400「メモを入力してください」。置き場所と並び順は変えない。200で書き換えた1件 |
| PUT /api/plans/{id} | 置いた1件を動かす。リクエスト `{"date","meal","index"}`。`date` と `meal` の扱いはPOSTと同じ。`index` は、移る先のエリアで動かす1件を除いた並びでの0始まりの位置で、無ければ0。負なら先頭、件数以上なら末尾。同じエリアなら並べ替え。200で動かした1件 |
| DELETE /api/plans/{id} | 置いた1件を献立から外す。行が無くても204。レシピは変えない |
| GET / | ルートパスのみ `/recipes.html` へリダイレクト(302)。それ以外は静的ファイル配信(embed。`DEV_MODE=1` のときのみ `os.DirFS("web/static")` から配信) |

エラー応答は `internal/handler/respond.go` の `writeError` で `{"error": "メッセージ"}` として返す。

| ステータス | 条件 | メッセージ |
|---|---|---|
| 400 | `{id}` が数値でない・1未満 | IDが不正です |
| 400 | リクエストJSONが不正 | リクエストの形式が不正です |
| 400 | `name` が空白除去後に空 | 名前を入力してください |
| 400 | `servings` が整数のリテラルでないか、0〜99の範囲外 | 人数は0〜99の整数にしてください |
| 400 | 画像のボディが2MBを超える | 画像が大きすぎます |
| 400 | 画像のボディがJPEGでない(空を含む) | JPEG画像を送ってください |
| 400 | 取り込みのボディが配列でない(nullを含む) | リクエストの形式が不正です(上の行と同じ) |
| 400 | 取り込みのボディが5MBを超える | リクエストが大きすぎます |
| 400 | 取り込みの配列が空 | 取り込むレシピがありません |
| 400 | 取り込みの配列に不正な件がある | `N件目: 理由` を先頭から最大10行、改行区切り。11件以上なら最後に `ほかN件`。理由は「形式が不正です」「名前を入力してください」「作った回数は0以上の整数にしてください」 |
| 400 | 献立の `from`・`to`・`date` が `YYYY-MM-DD` の実在する日付でない(空・省略を含む。`date` のnullは毎日) | 日付が不正です |
| 400 | 献立の `meal` が朝・昼・夜・候補のどれでもない(空文字を含む)、日付の行に `meal` が無い・nullか `candidate`、または日付の無い行に朝・昼・夜の `meal` がある | 時間帯が不正です |
| 400 | 献立の `from` が `to` より後 | 期間が不正です |
| 400 | POST /api/plans と PUT /api/plans/{id}/memo の `memo` が前後の空白を除くと空 | メモを入力してください |
| 404 | 対象IDのレシピが無い(POST /api/plans の `recipe_id` を含む) | レシピが見つかりません |
| 404 | `GET .../image` でレシピに画像が無い | 画像が見つかりません |
| 404 | PUT /api/plans/{id} で行が無い、PUT /api/plans/{id}/memo で行が無いかレシピの行 | 献立に置いたものが見つかりません |
| 500 | 上記以外(詳細はログのみ) | サーバー内部でエラーが発生しました |

| ti-x | 取り除く・閉じる | 一覧の選択中タグの「外す」・「キーワードを消す」・タグ選択ダイアログの「閉じる」、詳細の編集中のタグ・材料の「外す」、献立のパネルの「外す」 |

### 一覧(`recipes.html` / `recipes.js`)

- 見出しの行の右端に、「一覧と献立に共通」の上部右のボタンを並べる。一覧の読み込みに失敗しても出す
- 見出しの下に検索欄、その下に絞り込みの行、その下にタイルグリッドを並べる。検索欄と絞り込みの行は、一覧の読み込みに成功したときだけ出す(タグが0件でも出す)

検索欄:

- 上段は、今の探す対象の文言(「名前で探す」/「名前と本文で探す」)を出したボタン。押すたびに対象が切り替わる。既定は名前のみ
- 下段はキーワードの入力欄(プレースホルダ「キーワード」、`aria-label` は今の対象の文言)。入力のたびに(IMEの変換中も)、空白で区切った語をすべて名前に含むレシピだけを表示する。「名前と本文」では、語ごとに名前か本文のどちらかに含めばよい。全角と半角、大文字と小文字、ひらがなとカタカナは区別しない。EnterはIMEの確定でなければフォーカスを外すだけ
- キーワードがあるときだけ、入力欄の右端にアイコンだけの「キーワードを消す」を出す。押すとキーワードを消して入力欄にフォーカスを戻す。対象は戻さない

絞り込みの行:

- 先頭にアイコンだけの「ブックマークで絞り込む」トグル(`aria-pressed`)。押している間は、ブックマーク中のレシピだけを表示する
- 続けて「タグ」ボタンと、選んでいるタグの札を並べる。札ごとにアイコンだけの「「名前」を外す」を付ける
- 右端に並び順のボタン。基準のアイコン(新着順・名前順・作った回数)と、昇順/降順のアイコン(新着順・作った回数が多い順は降順、名前順・作った回数が少ない順は昇順)を並べる。読み上げ名と `title` は「並び順: 新着順」のように今の並び順を含める。押すと、すぐ下に右端をそろえて並び順のメニューが開く。新着順(既定。id降順)・名前順・作った回数が多い順・少ない順の文字だけの項目を並べ、今の並び順には選んでいることを示すアイコンを付ける。選ぶと、絞り込んだ結果を並べ替えて閉じる。外側のタップ・Esc・ボタンをもう一度押したときは、何も変えずに閉じる。追加パネルは並び順によらず先頭に置く
- ブックマーク・タグ・キーワードの条件はすべてANDでかける

タグ選択ダイアログ:

- 「タグ」ボタンで開く `<dialog>`(見出し「タグで絞り込む」)。中身は、タグの検索欄(プレースホルダと `aria-label` は「タグを探す」、空白区切りのAND)とタグのトグルボタン(`aria-pressed`)。選んでいるタグには、選んでいることを示すアイコンを付ける
- 並べるのは、選んでいるタグと、今の絞り込み結果に付いているタグだけ。選んでいないタグが1つも並ばないときは「一緒に選べるタグはありません」を出す(検索語があるときは「「語」を含む、一緒に選べるタグはありません」)
- 押すたびに一覧とURLへすぐ反映する。決定ボタンは無い。開くと閉じるボタンにフォーカスが移る。閉じるボタン・Esc・外側のタップで閉じる

タイルグリッド:

- 画面幅で列数が変わる正方形のタイル。先頭は `recipe.html` へのリンクの追加パネル(中央に「追加」)で、0件でも出す
- レシピのタイルは詳細(`recipe.html?id=N`)へのリンク。画像を出し、画像が無ければ中央に料理のアイコンを出す。下端に名前の帯を置き、名前を1行で出す(長い名前は「…」で省略し、全文はタイルの `title`)
- 名前の帯のすぐ上に、タグの札を1行で並べる。収まらない分は「+N」(Nは並べるタグのうち隠した数)にまとめる。タグで絞り込んでいるときは選んでいるタグを除き、残りが0件なら札の行を出さない。札を押すと、そのタグを選んでいるタグに加え(URLの `?tag=` にも反映)、ページの先頭へすぐ移る。「+N」と札の外を押したときは詳細へ移る
- 左上に、作った回数のバッジ(アイコンと数字)を出す。0回のときは出さない。下地の色は、全レシピの最大回数を基準に5段階で濃くなる。絞り込み・検索・並び順では色が変わらない
- 右上に、アイコンだけの「「名前」を候補に追加」を置く。押すと候補の先頭に1件足し、画面の下端中央に「「名前」を候補に追加しました」を約3秒出す(続けて押すと文言を差し替えて数え直す)。ページは移らない。同じレシピでも押した回数だけ足す。送信中は、そのタイルのボタンだけ押せない。失敗したときは一覧のエラー欄に「候補に追加できませんでした: 理由」を出し、次に押したときと読み直したときに消す
- 名前がちょうど「好評」のタグ(完全一致)が付いたタイルは、内側の縁が明滅して目立つ(端末で動きを減らす設定のときは光ったまま止まる)。そのタイルの札の行には「好評」を並べない。「+N」にも数えず、ほかのタグが無ければ札の行を出さない。代わりに、読み上げ用の見えない「好評」の文字を名前の帯の先頭に置く(「好評」で絞り込んでいるときは置かない)。詳細ページでは強調しない

状態:

- 一覧の読み込みに失敗したときは、検索欄・絞り込みの行・追加パネルを出さず、エラー文言だけを出す
- ブックマーク・タグ・キーワードのどれかで絞っていて0件のときは「条件に合うレシピがありません」を出す。探す対象を切り替えただけでは出さない
- ブラウザの戻るでキャッシュから復元されたときは、一覧を読み直す

URLクエリ(操作のたびに履歴を増やさずに書き戻し、読み込み時にURLから状態を戻す。知らない値や存在しないタグは捨てて、URLからも消す):

- `?q=` キーワード(前後の空白を除いた入力のまま。空なら付けない)
- `?scope=body` 探す対象が「名前と本文」(キーワードが空でも残す)
- `?bookmark=1` ブックマークで絞り込み中
- `?tag=名前` 選んでいるタグ(複数なら繰り返す)
- `?sort=name` / `cooked-desc` / `cooked-asc` 並び順(新着順のときは付けない)

### 詳細(`recipe.html` / `recipe.js`)

- `?id=N` なら閲覧表示、`id` が無ければ新規作成の編集フォームを出す。IDが無効なとき・存在しないとき(`?id=` が空のときを含む)は、エラー文言と「一覧へ戻る」(献立から来たときは「献立へ戻る」)だけを出す
- 上部の行は、閲覧表示では左にアイコンだけの「一覧へ戻る」(献立から来たときは「献立へ戻る」)、右にブックマーク・「作った」・アイコンだけの「編集」・「削除」。編集中は、左に「キャンセル」、右に「保存」とアイコンだけの「抽出」を出す
- 戻るボタンは、一覧か献立から来たときはブラウザの戻ると同じに動く(一覧の絞り込み条件・献立のスクロール位置が残る)。献立から来たときは名前が「献立へ戻る」になる
- 送信中は、上部と本文のボタンをすべて無効にする

閲覧表示:

- 名前(行の右端に `ti-user` と人数。0なら出さない。読み上げ名と `title` は「N人分」)・タグの札(0件なら札の行を出さない)・画像・材料・本文を出す。材料は名前と量(書式に数量を当てはめた文字列)の2列の表で、名前を左・量を右端に置き、行の間に線を引く。見出しは付けず、読み上げ名は `aria-label`「材料」。0件なら表ごと隠して場所を取らない。タグの札は、そのタグ1つだけで絞り込んだ一覧(`recipes.html?tag=名前`)へのリンクで、一覧の他の条件(キーワード・探す対象・ブックマーク・並び順)は引き継がない。本文は書いたとおりの改行で出し、`http://`・`https://` のURLは新しいタブで開くリンクにする。選択・コピーできるのは名前・材料・本文だけ
- ブックマークはアイコンだけのトグル(`aria-label`「ブックマーク」、状態は `aria-pressed`)。押すとPUT/DELETEで付け外しする
- 「作った」は、アイコンと回数を出したトグル(`aria-label`「作った」、状態は `aria-pressed`)。押すと回数を1増やして押した状態になり、もう一度押すと1減らして戻る。押した状態はページを読み込むたびに戻る
- 「削除」は確認ダイアログ(「削除する」/「キャンセル」)の後に削除し、一覧へ移る。詳細のURLは履歴に残さない
- 失敗したときは、閲覧表示のエラー欄にサーバーの `error` 文言を出し、表示は元のまま残す

編集フォーム:

- 上から、エラー欄・名前欄(プレースホルダ「名前」)と人数欄(`aria-label`「人数」)を並べた行・タグ欄・画像欄・材料欄・本文欄(プレースホルダ「本文」)の順。欄に見出しは付けず、読み上げ名は `aria-label` で付ける
- 人数欄は、名前欄の右に `ti-user` と幅の狭い数字の入力欄を置き、数字は中央寄せにする。空欄は0として保存し、0のレシピは空欄で出す。全角の数字は半角にして送る
- タグ欄は、入力欄(プレースホルダ「タグ」、`aria-label`「追加するタグ」)と「追加」ボタン。IMEの確定でないEnterでも足せる。入力候補は `GET /api/tags` のタグから、付けているタグを除いたもの。下に付けた札の列を出し、札ごとにアイコンだけの「「名前」を外す」を付ける(札が0件なら場所を取らない)。入力欄に文字を残したまま保存すると、その文字もタグとして足す
- 画像欄は、画像があればプレビューの右下にアイコンだけの「画像を外す」を重ねる。無ければ「画像なし」枠を出す。枠全体が貼り付け欄(`aria-label`「画像をここに貼り付け」)で、Ctrl+Vやスマホ長押しの「ペースト」でクリップボードの画像を受け取る。中央に「画像を選ぶ」と「Ctrl+V・長押しで貼り付け」の案内を出す。選んだ画像・貼った画像は、保存するまで送らない
- 材料欄(`role="group"`、`aria-label`「材料」)は、アイコンだけの掴む部分・名前の入力欄(プレースホルダ「材料」、入力候補は `GET /api/ingredient-names` の材料名)・量の入力欄(プレースホルダ「量」)・アイコンだけの外すボタンを並べた行を縦に並べた1つの角丸のパネルと、その下の横幅いっぱいの破線の枠の「材料を追加」。行の間を横線、行の中の部品の間を縦線で区切り、入力欄とボタンには枠を付けない。行が0の間はパネルを出さない。量の欄には `formatAmount` で書式に数量を当てはめた文字列を入れる。材料が0件なら空の行を1つ出す(外して0行になったときは足さない)。外すボタンの名前は「「名前」を外す」で、名前が空の行は「N行目の材料を外す」。掴む部分の名前は「「名前」を動かす」(名前が空の行は「N行目の材料を動かす」)で、マウスやタッチでドラッグすると、掴んだ行が指やカーソルについて動き、ほかの行がよけて入る位置を空け、離すとその位置に入る。表示領域の上端・下端に近づけている間は自動でスクロールし、掴む部分にフォーカスがあるときは上下の矢印キーで1行ずつ動かせる。並べ替えも未保存の変更になる。IMEの確定でないEnterでは、名前欄から同じ行の量の欄へ、量の欄から次の行の名前欄へ移り(最後の行なら行を足して移る)、保存はしない
- 上部の「抽出」は、押すとすぐ下に右端をそろえてメニューを開く。項目は文字だけの「人数をタイトルから抽出する」「材料を本文から抽出する」(この順)で、外側のタップ・Esc・ボタンをもう一度押したときは何もせずに閉じる。「人数をタイトルから抽出する」は、メニューを閉じてから、名前欄の今の内容から、半角・全角の数字に続く「人分」「人前」「名分」を探す(数字との間に空白があるものは拾わない)。範囲(`〜`・`～`・`~` でつないだ2つの数)は大きい方の数にする。見つかったら最初の1件だけを使い、人数欄を半角の数で上書きし、名前から人数の部分を前後の空白ごと消す。中身が人数の部分と空白だけの括弧(`(…)`・`（…）`)は括弧ごと消す。両側に文字が残るときは半角の空白1つでつなぐ(開き括弧の直後は詰める)。画面の下端中央に「人数をN人分にしました」を約3秒出す。見つからなければ何も変えず、「タイトルに人数が見つかりません」を同じ所に出す。どちらの場合もフォーカスは「抽出」に戻る。「材料を本文から抽出する」は、メニューを閉じてから、本文欄の今の内容(未保存の編集を含む)から材料らしい行を探し、ダイアログ(見出し「本文から抽出した材料」)に候補を出す。候補ごとに、チェックボックスと名前・量を1つの押せる行にして並べ、既定はすべてチェックにする。「追加」で、名前も量も空の材料の行を外してから、チェックした候補を末尾に足す(同じ名前があっても足す)。チェックが無い間は「追加」を押せない。候補が0件なら「本文に材料らしい行がありません」と「閉じる」だけを出す。「キャンセル」・Esc・外側のタップでは何も変えずに閉じ、閉じるとフォーカスは「抽出」に戻る。本文は変えない
  - 材料らしい行の判定: 前後の空白を除き、行末の括弧書き(`（…）`・`(…)`)を1つ外した後に、文字で始まらない行(数字・記号で始まる行)と、「、」「。」「：」「:」を含む行を除く。残りのうち最後の数(半角・全角の整数・小数・分数と、`〜`・`～`・`~` でつないだ範囲)を量の始まりにし、直前の「大さじ・小さじ・大・小」(間の空白を含む)も量に含める。数が無い行は、末尾が「適量」「少々」「適宜」「少量」のときだけ、その語を量にする。量より前が名前で、名前が空か20文字を超える行は除く。量の中の分数(`/`・`／`)は、小数第2位に四捨五入した小数に直す。範囲の量はそのまま入るので、保存のエラーを見て手で直す
- 保存では、材料の全行を画面の順に `ingredients` として送る。名前も量も空の行は、未保存の変更に数えない
- 保存に成功すると閲覧表示に戻る。失敗したときは、フォームの先頭にサーバーの `error` 文言を出す。レシピは保存できて画像だけ失敗したときは、選んだ画像を残して編集フォームにとどまる(新規作成ならURLはすでに `?id=` 付き)
- 「キャンセル」は、未保存の変更があれば確認ダイアログ(「破棄する」/「キャンセル」)を出す。既存のレシピなら閲覧表示へ、新規作成なら一覧へ戻る
- 未保存の変更があると、戻る・再読み込み・タブを閉じるの操作で、ブラウザ標準の離脱確認を出す(iOS Safariでは出ない)

### 取り込み(`import.html` / `import.js`)

- 上部の左にアイコンだけの「一覧へ戻る」(一覧から来たときはブラウザの戻ると同じに動く)、右に「取り込む」
- 見出しの下に、JSONを貼る大きなtextareaを置く。その下に「受け付けるJSONの形」の説明と例を常に出す。選択・コピーできるのは例だけ
- 「取り込む」で `POST /api/recipes/import` を呼び、送信中はボタンを無効にする
- 成功したら欄を空にし、欄の上に「N件のレシピを取り込みました」と「一覧へ戻る」を出す
- 失敗したら、サーバーの `error` 文言を改行どおりに欄の上へ出し、入力は残す

### 献立(`plans.html` / `plans.js`)

- 見出し「献立」と、「一覧と献立に共通」の上部右のボタンの下に、期間選択UI、その下の行の左端に一括開閉、右端に時間帯の切り替え、その下にエラー欄、候補・毎日・各日付のエリアを並べる
- 期間選択UI: 1つの角丸の枠(`role="group"`、`aria-label`「期間」)を横幅いっぱいに置き、左端にアイコンだけの「前の期間」、右端に「次の期間」、その間の中央に「M/D(曜)」の開始日ボタン、「から」、日数ボタン、「日間」を1行で並べる
  - 開始日ボタンと日数ボタンは枠線なし・角丸なしで、hover・押している間はほかのボタンと同じ背景になる。「から」「日間」とは間を空ける
  - 開始日ボタンを押すと、ブラウザ標準の日付選択が開く
  - 日数ボタンを押すと、その場で1〜31の数字入力欄に替わる。数字の部分だけが下線の細い入力欄になり、枠の大きさは変わらない。Enter・欄の外を押したときに確定し、Escで取り消す。1〜31の整数でなければ元に戻す
  - 前後の移動は、開始日を日数分ずらす
  - 期間は端末のlocalStorage(`kondate.plans.period`)に覚え、初めて開いたときと、覚えた値が読めないときは、今日から7日間にする
- 一括開閉: 期間の枠の下の行の左端に置く、アイコンだけのボタン。毎日か各日付のどれか1つでも開いていれば「すべて折り畳み」を出し、押すと毎日と各日付を全部畳む。全部畳まれていれば「すべて展開」を出し、押すと全部開く。名前とアイコンは、見出しで1つずつ開閉したときと期間を変えたときにも合わせ直す。候補は畳まない。ドラッグ中は押しても何も起きない
- 時間帯の切り替え: 期間の枠の下の行の右端に置く(`role="group"`、`aria-label`「表示する時間帯」)。1つの角丸の枠に、アイコンだけの朝・昼・夜のボタンを縦線で区切って並べる(読み上げ名は「朝」「昼」「夜」、状態は `aria-pressed`、オンは青系)
  - オフの時間帯の帯は、各日付で出さず、ドラッグの置き先にもしない。中に置いたパネルは残り、件数にも数える。毎日と候補は変えない
  - 3つともオフにできる。そのときは各日付の枠(帯)を1つも出さず、見出しの見た目と開閉は変えない
  - ドラッグ中は押しても何も起きない
  - 状態は端末のlocalStorage(`kondate.plans.meals`、オンの時間帯の配列)に覚え、初めて開いたときと、覚えた値が読めないときは3つともオンにする
- 候補: 見出しは「候補」。候補の行を並び順のとおりに、縮小版パネルで縦に並べる。ブックマークとは関係しない。一覧タイルの「候補に追加」で先頭に足される
  - パネルは、左から掴む部分、縮小画像(無ければ料理のアイコン)、1行の名前(長い名前は「…」で省略し、全文は `title`)、人数(`ti-user` と数字。0なら出さない。読み上げ名と `title` は「N人分」)、右端のアイコンだけの「「名前」を外す」。名前と人数を入れたリンクは右端に内側の余白を取り、人数を外すボタンから離す
  - 掴む部分と外すボタン以外を押すと、詳細へ移る(メモのパネルは移らず、書き換えのダイアログを開く)
  - 見出しの右端に、アイコンだけの「メモを追加」を置く。押すとダイアログ(見出し「メモを追加」、1行の入力欄、「保存」、「キャンセル」)を開き、入力欄にフォーカスする。前後の空白を除いて空の間は「保存」を押せない。保存すると送信の結果を待ち、成功したら候補の先頭にメモのパネルを足して閉じ、フォーカスを「メモを追加」へ戻す。失敗したらダイアログの中に「メモを追加できませんでした: 理由」を出し、入力した文を残して開いたままにする。送信中は閉じない。「キャンセル」・Esc・外側のタップでは何も足さない。送信中と読み込み中とドラッグ中は開けない
  - メモのパネルは、縮小画像の場所にメモのアイコン、名前の場所にメモの文(長い文は「…」で省略し、全文は `title`)を出す。掴む部分・外すボタン・ドラッグ・件数への数え方はレシピのパネルと同じ。人数は出さない
  - メモのパネルの縮小画像と文の部分(掴む部分と外すボタンの間)を押すと、同じダイアログを見出し「メモを編集」で開く。入力欄に今の文を入れ、カーソルは末尾に置く。保存すると送信の結果を待ち、成功したらパネルの文・`title`・外すボタンの読み上げ名を書き換えて閉じ、フォーカスをそのパネルへ戻す。文が変わっていなければ送らずに閉じる。失敗したらダイアログの中に「メモを保存できませんでした: 理由」を出し、入力した文を残す。候補・毎日・各日付のどのメモでも同じ
  - 外すボタンを押すと、確認を出さずにパネルを取り除いて献立から外す。フォーカスは、詰めてきた同じ位置のパネルの外すボタンへ移す(末尾なら1つ前)。送信中と読み込み中は押しても何もしない。失敗したらパネルを元の位置へ戻し、候補の見出しの下に「外せませんでした: 理由」を出す
  - 0件なら、空の帯と同じく、枠の中央に「候補に追加」のアイコンを薄く大きめに出す。アイコンは読み上げない。読み込みに失敗したときも、枠を空にしてアイコンを出す(理由は期間選択UIの下に出る)
  - 掴む部分をマウスやタッチでドラッグすると、パネルの写しが動き、元のパネルは元の場所に薄く残る
  - 毎日の区画(見出しを含む)の上にあると、その枠に色が付き、入る位置に横線が出る(パネルの間、末尾なら枠の下端)。各日付では、朝・昼・夜の帯の上にあると、その帯の地の色はそのままに内側へ青い縁が付き、入る位置に帯の中で横線が出る(末尾は帯の下の余白、空の帯は上の余白)。開いている日付の見出し・エラー欄の上では、表示している最初の帯の先頭として扱う。畳んだ毎日・日付は見出しも枠も、オフの時間帯の帯と、3つともオフの日付も置き先にならず、上で離しても何も起きない。ほかのパネルは動かない
  - 毎日か帯の上で離すと、パネルは候補から消えて、その位置へ移って保存される(日付の行は時間帯も送る)。区画の外や候補の上で離したとき、OSにタッチを取り消されたときは、何も起きない
  - 動かすのに失敗したらパネルを候補の元の位置へ戻し、候補の見出しの下に「動かせませんでした: 理由」を出す
  - 表示領域の上端・下端に近づけている間は、材料のドラッグと同じ速さで自動スクロールする
  - 送信中と読み込み中は掴めない
- 毎日・各日付: 「毎日」の見出しと、開始日から日数分の「M/D(曜)」の見出しの下に、置いたパネルを並べる
  - 毎日は、空のとき枠の中央に朝・昼・夜のアイコンを、アイコンの半分ほどの間を空けて横に並べ、薄く大きめに出す。アイコンは読み上げない。読み込みに失敗して枠が空のときも出す。ドラッグ中の出し方は空の帯と同じ
  - 各日付は角丸の枠1つの中に、朝・昼・夜の帯を上から並べる。帯は地の色で塗り分け、文字は出さず、読み上げ名(`aria-label`)だけ「朝」「昼」「夜」を付ける。空の帯にもパネル1枚分の高さを残し、中央にその時間帯のアイコン(朝・昼・夜)を薄く大きめに出す。アイコンは読み上げない。帯の上にパネルを持ってきている間も出したままにし、最後のパネルを動かしている間は元のパネルが薄く残るので出さない。候補と毎日は分けない
  - 各日付の見出しは幅いっぱいのボタンで、左から開閉の目印のアイコン(開いている・畳んでいる)、「M/D(曜)」、右端に朝・昼・夜のアイコンとその帯の件数(0件も出す。オフの時間帯も出し、0件は薄く、1件以上は赤で出す)を並べる。開閉の状態は `aria-expanded` で伝え、読み上げ名は「M/D(曜) 朝N件 昼N件 夜N件」にする。端末の今日の日付の見出しは、ボタン全体の背景を黄緑にし、`aria-current="date"` で伝える(読み上げ名は変えない)。今日かどうかは、見出しを作り直したとき(開いたとき・期間を変えたとき)と、画面に戻ったとき(タブやアプリから戻って表示されたとき・戻るでキャッシュから復元されたとき)に判定し直す。期間に今日が無ければどの見出しも強調しない。毎日と候補の見出しは変えない
  - 毎日の見出しは幅いっぱいのボタンで、左から開閉の目印のアイコンと「毎日」を並べる(件数は出さない)。押すとパネルの枠だけを畳む・開く。開閉の状態は `aria-expanded` で伝える
  - 各日付の見出しを押すと朝・昼・夜の帯の枠だけを畳む・開く。エラー欄は畳んでも出す。開閉の状態は覚えず、開いたときと期間を変えたときは各日付が全部開いている(戻るでキャッシュから復元されたときはそのときの状態のまま)。毎日は期間を変えても開閉を変えない。ドラッグ中は毎日も各日付も押しても何も起きない。候補は畳まない
  - 件数は、読み込み・動かす・外す操作と、その失敗で元へ戻したときに数え直す
  - 置いたパネルの見た目と外すボタンの動きは候補と同じ(失敗の文言はその区画の見出しの下に出る)。ただし各日付の帯に置いたパネルの外枠は、その帯の地の色と同じ色味の濃い色にする(毎日のパネルは候補と同じ)。ドラッグ中の写しの外枠は、どこから掴んでも候補と同じ灰色にする。掴む部分と外すボタン以外を押すと詳細へ移る。外したパネルは候補に戻さない
  - 掴む部分をドラッグすると写しが動き、元のパネルは元の場所に薄く残る。区画の見せ方・自動スクロール・送信中と読み込み中は掴めないことは、候補からのドラッグと同じ
  - 毎日か帯の上で離すと、その位置へ移って保存される(同じ区画・帯なら並べ替え。帯の間や日付の間で動かすと、時間帯や日付を変えて保存する。元と同じ位置なら何も送らない)
  - 候補の区画(見出しを含む)の上でも、毎日と同じく枠に色が付き、入る位置に横線が出る(パネルの間、末尾なら枠の下端。見出し・エラー欄の上では先頭)。離すと、パネルは元の区画から消えて、候補のその位置へ移って保存される
  - 区画の外で離したとき、OSにタッチを取り消されたときは、何も起きない
  - 動かすのに失敗したらパネルを元の位置へ戻し、元の区画の見出しの下に「動かせませんでした: 理由」を出す
- 読み込み: 開いたとき、期間を変えたとき、日数が実際に変わったとき、ブラウザの戻るでキャッシュから復元されたときに、レシピ一覧と献立を読み直して並べる。読み込みに失敗したら、期間選択UIの下に「献立を読み込めませんでした: 理由」を出す

### 一覧と献立に共通

- 上部右に、アイコンだけの「レシピ」「献立」を1つの角丸の枠の中に縦線で区切って並べ、その右に間を空けて「メニュー」ボタンを置く。レシピと献立はそれぞれの画面へのリンク
- 今いる画面のボタンは、時間帯の切り替えのオンと同じ青系の背景とアイコンの色にし、`aria-current="page"` で伝える。押しても移らない
- メニューは、押すとすぐ下に右端をそろえて開く。項目は文字だけの「レシピを取り込む」で、選ぶと取り込み画面へ移る。外側のタップ・Esc・ボタンをもう一度押したときは、何もせずに閉じる

### 全画面に共通

- 一覧・詳細・取り込みでは、下へスクロールしているときだけ、本文の列の右下にアイコンだけの「先頭へ戻る」を浮かせる。押すとなめらかに先頭へ戻る(端末で動きを減らす設定のときはすぐに移る)
- どの画面も base.css の後に `/dev-mode.css` を読み込む。`DEV_MODE=1` のときだけ、背景一面に「DEV_MODE」の文字の模様が出る

## 5. 設計判断(逆行防止用)

### 全体・ビルド・運用

- **モジュール名は `kondate-supporter`**: 外部へ公開せず `go install` もしないため、GitHubのパスにはしない。importを短く保ち、旧実装を参照するときの読み替えを無くす。
- **ディレクトリ・ヘルパー関数・設定項目は、それを使うROADMAP項目で作る**: `.gitkeep` などの目印ファイルも置かない。置き場だけを先に作ると、使われない層や項目が残るため(旧実装は一度に大きく作ろうとして完成しなかった)。
- **次のものはROADMAPに項目が追加されるまで作らない**: 在庫・買い物リストのテーブル・API(旧実装はこれらの画面まで一度に作ろうとして完成しなかった)。静的ファイル(`web/static`)のキャッシュの仕組み(画面が少なく、LAN内の通信で足りる)。デプロイの自動化、つまり転送や、systemd・Windowsのサービス化による常駐化(個人利用では必要性が薄く、READMEの手順で足りる)。
- **Makefileはsh前提で書き、引数なしの `make` はhelpを出す**: 開発PCではGit Bash/WSLからmakeを実行するので、cmd.exeでの動作は考えず、環境変数は `VAR=値 コマンド` の形で渡す。`make` だけを打ったときに開発サーバーが起動せず、どのターゲットがあるかもその場で分かるようにする。helpの一覧はターゲット行の末尾の `## 説明` から作るので、ターゲットを増やすときはその行に `## 説明` を書くだけでよく、help側は書き換えない(この書き方でないターゲットは一覧に出ない)。詳しい理由や注意は、ターゲットの上の行に `#` コメントで書く。
- **`make run` とpreviewは、固定パスへビルドしてから `DEV_MODE=1` で起動する**: `go run` は実行のたびに一時パスへバイナリを作るため、Windowsファイアウォールの許可を何度も求められ、許可ルールも増え続ける。`DEV_MODE=1` で画面ファイルをディスクから配信し、HTML/JSの修正をビルドし直さずに確認できるようにする。previewは同じパスへ上書きビルドするので、起動時に前回のpreview用exeを止める(残っているとビルドに失敗し、ポートも埋まったまま古い埋め込み画面を配信し続けていた)。
- **開発サーバー・preview・常駐運用は、ポート・実行ファイル名・DBを分ける**: 3つを同時に動かしてもぶつからないようにする。config.goの既定値 `:8080` は常駐運用(`make build-win` のexe、将来のRaspberryPi)用に残す。`make run` は `KONDATE_ADDR=:8082` を指定し、previewのポートとDBは `.claude/launch.json` で指定する。既定値を変えないのは、配置するexeを環境変数なしで起動すれば常駐用のポートになるようにするため。実行ファイル名を分けるのは、Windowsでは実行中のexeを上書きできず、常駐運用のサーバーを動かしたまま開発用やpreview用をビルドすると失敗するため。
- **配置用ビルド(build-rpi・build-win)は、`CGO_ENABLED=0`・`-trimpath`・シンボル除去で静的バイナリ1つにする**: SQLiteドライバがCGO不要なので静的バイナリ1つで配置でき、シンボルを除いて転送・保存のサイズを抑える。RaspberryPi Zero向けは、Pi Zero/Zero WがARMv6なので `GOARM=6` を付ける。共通のリンカフラグは `RELEASE_LDFLAGS` にまとめ、ターゲット固有のフラグ(build-winの `-H windowsgui`)はその後ろに足す。`-ldflags` を2回書くと、後の方だけが効くため。
- **`make build-win` は、RaspberryPiを用意するまでのつなぎで、コンソールを出さない**: 開発用の `make run` とは別に、embedから配信する配置用exeを作る。GOARCHは指定せず、ビルドしたマシンに合わせる。`-H windowsgui` でコンソールウィンドウを出さないのは、常用中にコンソールを誤って閉じるとサーバーが止まるため。止めるのはタスクマネージャーか `taskkill /F` で、手順はREADMEに書く。終了処理は作らない(SQLiteはトランザクション単位で書き込みが確定するので、強制終了でもDBは壊れない)。
- **ログをファイルへ出すのは、ビルドタグ `windowsgui` のときだけ**: コンソールが無いビルドとログの出し先を必ず組にするため。環境変数では切り替えず、Makefileの `-tags windowsgui` とファイル先頭の `//go:build` で選ぶ(タグ名を片方だけ変えると、コンソールなしのビルドでログが消える)。`make run`・preview・RaspberryPi向けはコンソールに出す。
  - 出し先は、標準 `log` の既定のloggerの出し先を替えるだけにし、ロガーのパッケージや構造化ログは作らない。起動メッセージ・起動の失敗・handlerの500の詳細・`net/http` のエラーがどれも既定のloggerを通るので、呼び出し側を書き換えずに全部ファイルへ入る。
  - ログファイルは、DBと同じフォルダの `kondate.log` に追記するだけで、分割しない。DBのパスを場所の設定に使えば設定が増えない。書くのは起動時とエラーのときだけなので、個人利用では大きくならない。
  - ログファイルを開けなくても起動は続け、ダイアログも出さない。ログが無くても画面は使えるため。フォルダに書けなければDBも作れず、そこで起動が止まる。
- **外部ライブラリはCDNを使わず、`web/static/vendor/<名前>/` に配布ファイルのまま同梱する**: LAN内でインターネットにつながらなくても画面が崩れず、embedでバイナリに入るので配置もファイル1つのまま。編集しないのは、更新を配布ファイルの差し替えだけで済ませるため(手順と版数はREADME)。Tabler Iconsは、使うアイコンがoutlineだけなので、outlineのCSSとwoff2だけを置く(filled・200/300版、woff・ttfは置かない)。CSSのフォント指定は先頭がwoff2で、対応ブラウザは後ろの形式を取りに行かない。そのため、置いていない形式への参照はCSSに残したままにする。
- **開発モードの模様は、`GET /dev-mode.css` の中身をサーバーで切り替えて出す**: HTMLとJSに分岐を置かないので、HTMLはembedでもディスクでも同じファイルのまま使え、設定を取りに行くAPIやJSも要らない。開発モードでないときも空のCSSを200で返す(404にすると、常駐運用で画面を開くたびにブラウザのコンソールへ読み込みエラーが出る)。
  - 模様は `body` の背景に指定する。`html` に背景が無ければ `body` の背景がビューポート全体に描かれるので、要素を足さずに、どの画面でも本文の列の外まで模様が出る(`html` に背景を付けると、模様が本文の列の中だけになる)。
  - 模様は `web/static/dev-mode.svg` を繰り返して敷き、SVG自体は透明にして、白はCSSで付ける。文字・大きさ・傾き・間隔を、SVGの1ファイルで直せるため。背景画像のSVGではWebフォントが使えないので、フォントは `sans-serif` にする。
  - 模様は淡くし、白い背景の部品の下に隠れて本文やタイルを読みにくくしないようにする。

### バックエンド・DB・API

- **SQLiteの接続は `SetMaxOpenConns(1)` で1本に制限し、PRAGMAはDSNの `_pragma` で指定する**: 書き込みを直列化して `SQLITE_BUSY` を避ける。単一プロセス・個人利用で、RaspberryPi Zeroにも合う。PRAGMAを接続後の `Exec` で設定すると、プールが作る新規接続に反映されないことがある。
  - 外部キーは `_pragma=foreign_keys(1)` で有効にする。SQLiteは接続ごとに既定で外部キーが無効で、`ON DELETE CASCADE` も効かない。トランザクションの中で `PRAGMA foreign_keys` を実行しても効かない。
  - トランザクションの中ではdbを使わず、必ず `tx` を使う。接続が1本なので、`r.db` を使うと空き接続を待ち続けて止まる。
- **献立は `plans` に置いた1件ずつを行で持ち、主キーを `id` にする**: 同じエリアに同じレシピを何度でも置けるので、レシピと場所の組では1件を見分けられないため。テーブル・APIのパス・Goの型(`model.Plan`)・画面のJSの名前は、画面(`plans.html`)とハンドラ・サービス・リポジトリの `Plan` にそろえて「plan」で呼ぶ。同じものを層ごとに別の名前で呼ぶと、読み替えが要り、探すときにも漏れるため。
- **毎日は `date` と `meal` をNULLで表し、同じエリアの条件は `date IS ? AND meal IS ?` で書く**: 日付を持たない全期間共通の1つのリストを、別のテーブルや決め打ちの日付を作らずに表せる。毎日には時間帯が無いので `meal` もNULLにする。`= ?` で書くと、NULLの毎日の行が1件も当たらない。
- **メモは `plans` の行として持ち、`recipe_id` をNULLにして `memo` 列に文を入れる。2つの列はCHECKでちょうど一方だけを持たせる**: メモもレシピと同じく、候補・毎日・各日付の同じエリアに混ざって並び、ドラッグで動かすため。同じテーブルなら、並び順・動かす・外す処理と位置の決め方(`slotPosition`)をそのまま使える。別のテーブルにすると、エリアの中の並びを2つのテーブルにまたがって決めることになる。`recipe_id` のNOT NULLを外すには列の制約を変える必要があり、SQLiteではテーブルを作り直すしかない(0010)。作り直すので、どちらも持たない行や両方を持つ行ができないようCHECKもここで付ける。日付と時間帯の組にCHECKを付けない判断とは別で、あちらは列を足すマイグレーションでは書けなかったため。
- **`plans` を作り直すマイグレーションは、外部キーを有効にしたまま行う**: `plans` を参照するテーブルが無いので、古いテーブルを消しても外部キーの検査に当たらない。トランザクションの中では `PRAGMA foreign_keys` を切り替えられないので、切り替えに頼らない手順にした。今後 `plans` を参照するテーブルを作った後で `plans` を作り直すときは、この前提が崩れる。
- **献立に置くAPIは1つのままにし、`recipe_id` と `memo` のどちらか一方だけを受ける。両方ある・両方無いときは形式の誤りとして400にする**: 置く場所と位置の扱いがレシピとメモで同じなので、エンドポイントを分けると検査と位置の扱いが2か所になるため。どちらとも取れる要求を、片方を黙って捨てて受け付けない。
- **メモは前後の空白を除いて保存し、空なら「メモを入力してください」で弾く。検査はserviceで行う**: レシピ名と同じ規則にそろえるため。
- **メモの追加は候補の見出しの右端のボタンから行い、候補の先頭に足す**: 一覧タイルの「候補に追加」と同じく、まず候補に集め、そこからドラッグで置く流れをそろえるため。足したパネルがすぐ目に入るよう先頭に入れる。
- **メモの書き換えは、動かすAPIとは分けて `PUT /api/plans/{id}/memo` で文だけを受け、レシピの行と無い行はどちらも404にする**: 動かすAPIは移る先を必ず受けるので、まとめると文を変えるたびに今の場所を送り直すことになり、別の端末で動かした行を古い場所へ戻してしまうため。レシピの行を更新の条件(`memo IS NOT NULL`)で外すのは、memoを入れるとCHECKに当たって500になるため。
- **メモのダイアログは追加と書き換えで共用し、見出しだけを「メモを追加」「メモを編集」に替える。文が空白だけの間「保存」を押せなくし、送信の結果を待ってから閉じる。失敗したらダイアログに理由を出し、入力した文を残す。開いたら入力欄にフォーカスする**: 「入力チェックはサーバーだけで行う」の例外。本文から集めた材料のダイアログと同じく、押しても何も起きないボタンを押せるように見せないため(サーバーも同じ規則で弾く)。共用にするのは、どちらも1行の文を打つ操作で、空の扱い・結果を待つこと・失敗したときに文を残すことの規則を1か所にそろえるため。結果を待つのは、追加ではパネルに付ける行のidが応答で決まるためと、失敗したときに打った文を失わないため。送信中は閉じないので、閉じた後に結果が届くことが無い。必ず文を打つので、タグ選択ダイアログと違い開いたらフォーカスする。書き換えのときはカーソルを文の末尾に置き、全選択しない。一部を直すときに、1文字打っただけで文が全部消えないようにするため。
- **パネルの人数は、詳細の閲覧表示と同じく `role="img"` にして読み上げ名と `title` を「N人分」にし、0のときは出さない。リンクの中の名前の後ろに置き、縮めない**: アイコンは読み上げないので、数字だけでは何の数か分からないため。0は未設定の意味で、「0人分」と出すと設定した人数に見えるため。リンクの中に置くのは、人数の部分を押しても詳細へ移れるようにして、押しても何も起きない所を作らないため。縮めないのは、長い名前のほうを省略して、人数が欠けないようにするため。メモには人数が無いので出さない。
- **レシピのパネルとメモのパネルは、掴む部分と外すボタンの間のリンク・ボタンの右端に内側の余白を取る。左には取らない**: 人数が外すボタンのアイコンにくっついて、外すボタンの一部に見えないようにするため。パネルの外側やリンクの外ではなく内側の余白にするのは、余白を押しても詳細へ移れる(メモではダイアログが開く)ようにして、押しても何も起きない所を作らないため。メモのパネルにも同じ余白を取るのは、人数の無いレシピのパネルと文字の終わる位置をそろえるため。左に取らないのは、縮小画像を掴む部分に接したまま置き、間に隙間を作らないため。メモのボタンには base.css のボタンの左右の余白を打ち消す指定があり、それより後に書くと余白が0に戻るので、余白はリンクと共通の指定にまとめて書く。
- **メモのパネルは、縮小画像の場所にメモのアイコン、名前の場所に文を出し、掴む部分と外すボタンの間をリンクではなくボタンにして、押すと書き換えのダイアログを開く。掴む部分と外すボタンはレシピのパネルと同じにする**: 移る先の詳細が無いため。レシピのパネルで詳細へ移るのと同じ場所を押す操作にそろえ、キーボードでも開けるようにする。並びの中で、レシピのパネルと同じ高さ・同じ位置に操作がそろうようにする。外すときに確認を出さない、件数に数える、ドラッグの置き先も同じにするのは、メモも献立の1件として扱うため。
- **メモの文を変えずに「保存」を押したときは、送らずに閉じる**: 元と同じ位置に離したドラッグと同じく、何も変わらない保存で、送信中に操作できない時間を作らないため。
- **メモのダイアログは、開くたびに入力欄と「キャンセル」を押せる状態に戻し、「保存」は空かどうかだけで決める**: 送信中は3つとも押せなくするが、閉じ方(保存の成功・文が変わらない保存・キャンセル)ごとに戻すと戻し忘れが起き、次に開いたとき文を打てなくなるため(保存に成功したときに戻し忘れていた)。失敗したときは開いたまま打ち直すので、その場でも戻す。
- **献立の候補は、`date` をNULLにし `meal` を `candidate` にした `plans` の行で表し、候補用のテーブルとAPIを作らない**: 候補も、同じレシピを何件でも置ける並び順付きのリストなので、毎日と同じく「同じエリア」の1つとして扱えば、置く・動かす・外す処理と位置の決め方をそのまま使えるため。候補と献立の間で動かすときも、1件のUPDATEで済む。`meal` は時間帯の列だが、日付の無い行に時間帯は無いので、日付の無い行に限って候補の印に使う。列を足すと、毎日・候補・日付の組の検査が増えるため。並べるときは `CASE` に候補も入れる。入れないと毎日と候補の行がどちらもNULLになり、2つのエリアが混ざって並ぶ。
- **時間帯は `meal` 列に `breakfast`・`lunch`・`dinner` の文字列で持ち、朝・昼・夜の並びは `ORDER BY` の `CASE` で決める**: DBとAPIのJSONを見ただけで時間帯が分かり、数値と時間帯の対応表をサーバーと画面の2か所に持たずに済むため。文字列の順で並べると朝・夜・昼になるので、並べるときは必ず `CASE` で順番に直す。
- **献立に置く操作は、エリアの並びを丸ごと置き換えるAPIにせず、1件を位置を指定して足すAPIにする**: 別の端末で同じエリアに置いたものを、古い並びで上書きして消さないため。位置は画面に並んでいる順の0始まりの番号で受け、範囲外は先頭・末尾に寄せてエラーにしない。別の端末で件数が変わっていても、置く操作を失敗させないため。
- **`position` は並び順を表すだけで、連番を保証せず、主キーにもUNIQUEにもしない**: レシピを消すとCASCADEで行が抜けて番号が空くため。足すときは、受けた番号をそのまま使わず、その番号の位置にある行の `position` を探し、それ以降を1つずつずらして入れる。UNIQUEにしないのは、ずらすUPDATEの途中で番号が一時的に重なるため。
- **献立に置くレシピの存在は、`INSERT ... SELECT ... FROM recipes WHERE id = ?` の結果で確かめて404にする**: `VALUES` で入れると存在しないidが外部キー違反になり、404と見分けにくいため(ブックマークと同じ)。
- **献立のAPIはレシピのidだけを返し、名前と画像は、画面がレシピ一覧APIの結果から引く**: レシピの列リストと画像URLの組み立てを2か所に持たないため。
- **日付の行の時間帯は省略を受け付けず、400にする**: 省略を夜などに読み替えると、画面が送り忘れたときに黙ってその時間帯に入り、間違いに気づけないため。
- **献立の日付と時間帯の検査はserviceで行い、`YYYY-MM-DD` の実在する日付と、日付の行には朝・昼・夜のどれか、日付の無い行には時間帯なし(毎日)か `candidate`(候補)、だけを受け付ける**: 日付は文字列のまま比べて並べるので、形がそろっていないと、期間の絞り込みと並びが崩れるため。時間帯は、知らない値があると `CASE` で並びの位置が決まらず、日付の無い行に朝・昼・夜があると同じエリアの条件に当たらなくなるため。日付の行に `candidate` を受け付けないのは、候補は期間によらず1つのリストで、日付付きの候補があると期間で見える候補が変わるため。DBにCHECKを付けないのは、日付と時間帯の組の決まりは列を足すマイグレーションでは書けず、検査を1か所に保つため。
- **献立のrepository・service・handlerはレシピと分け、トランザクションの関数 `inTx` だけをrepositoryのパッケージ関数にして共用する**: 献立はレシピの保存・削除の中で作られない独立した操作のため。トランザクションの扱いと注意書きを1か所に保つ。
- **マイグレーションは `internal/db` で直接embedする**: 読み込み側は `Migrate()` だけなので、専用のパッケージは分けない。
- **依存は `handler → service → repository` に保ち、serviceはrepositoryの具象型を直接持つ**: テストの差し替えなど、インターフェースが要る場面がまだROADMAPに無いため。
  - handlerはrepositoryをimportしない。「見つからない」は、repositoryのエラーをserviceが自分のエラーに置き換えて伝える。ユーザー向けの文言はserviceのエラー値に持たせ、handlerはHTTPステータスへの振り分けだけを行う。
  - タグはレシピに従属するものとして、レシピのrepository・service・handlerで扱い、層ごとに型を分けない。タグはレシピに付いている間だけ存在し、作るのも消すのもレシピの保存・削除の中で行う。タグだけを操作するAPIは無い。
  - 保存・削除のトランザクションはrepositoryのメソッドの中で完結させる。SQLをrepositoryに閉じ込めたまま、レシピとタグの書き込みを1つにまとめられる。
- **名前のチェックとタグ名の正規化はserviceで行う**: どちらも業務ルールのため。画面でも同じ規則でタグの重複を防ぐが、正しさを決めるのはサーバー。
  - 名前は前後の空白を除いて空なら不可とし、保存するのも空白を除いた後の値。`body` は自由テキストとして書かれたまま保存する。
  - タグ名は前後の空白を除き、空を捨て、完全一致の重複をまとめる。大文字と小文字は区別し、書かれたとおりに保存する。表記ゆれを吸収する比べ方は、絞り込み・検索の側で行う。
- **PUTは全体置換にし、部分更新(PATCH)は作らない**: 項目が名前・本文・人数・タグ・材料だけのため。全体置換なので、送られなかった `body`・`tags`・`ingredients` は空、`servings` は0として扱う(nullを含む)。
- **人数は `recipes.servings` に0〜99の整数で持ち、0を未設定にする。範囲の検査はserviceで行い、DBにCHECKを付けない**: 0人分のレシピは無いので、未設定をNULLにせず0で表せる。JSONは常に整数になり、画面でnullを扱わずに済む。CHECKを付けないのは、検査を1か所に保つため(献立の日付と時間帯と同じ)。
  - handlerでは生のJSONのまま受け、整数のリテラルでなければ「人数は0〜99の整数にしてください」で弾く(`parseIntLiteral`。取り込みの作った回数と同じ読み方)。整数の型で読むと、小数や文字列が「リクエストの形式が不正です」になり、人がどう直せばよいか分からないため。
  - 人数は作った回数と違い、編集フォームで書き換える項目で、別の端末の操作で変わることが無いため、PUTの全体置換に含める。
- **作った回数・ブックマーク・画像は専用エンドポイントでだけ変え、PUTの全体置換では受け付けない**: PUTに含めると、編集中に別の端末で「作った」・ブックマーク・画像を変えたとき、保存で古い値に戻ってしまう。
  - 回数の増減はSQLの式(`cooked_count + 1`、下限0は `MAX`)で行い、読んでから書く手順にしない。
  - 画像のボディはJSONに包まず、バイト列のまま送れる。
- **ブックマークの付け外し・画像を外す・回数の減算は、すでにその状態でもエラーにせず、200で更新後のレシピを返す**: 画面側で今の状態を確かめずに呼べる。別の端末で先に変わっていても失敗せず、画面は返ってきたレシピで表示を合わせればよい。ブックマークは回数ではなく状態を決める操作なので、PUT/DELETEにして何度送っても結果が同じになるようにする。
- **IDの存在は事前にSELECTせず、書き込みの結果で確かめて404にする**: 問い合わせが1回で済み、確かめてから書くまでの間に別の端末で消されても取り違えない。
  - DELETEは `RowsAffected` が0なら404にする。
  - 作った回数・画像のUPDATEは、`RETURNING` で返った更新後の行をそのまま応答に使い、行が無ければ404にする。
  - PUTはUPDATEの `RowsAffected` が0なら404にし、タグを付け替えた後にSELECTで読み直して返す(受け付けない回数の実際の値も返せる)。タグより先にUPDATEするのは、存在しないidにタグを付けると外部キー違反になり、404と見分けにくいため。
  - ブックマークは書き込みの後にSELECTで読み直し、行が無ければ404にする。付けるときは `INSERT ... SELECT id FROM recipes WHERE id = ? ON CONFLICT DO NOTHING` にする(`VALUES (?)` では、存在しないidが外部キー違反になるため)。外すときのDELETEは、行が無くてもエラーにならない。2つの文は1つのトランザクションにまとめる。
- **一覧APIはid昇順(登録順)で本文とタグも含めて返し、画面の並び順はブラウザで決める**: SQLiteの文字列比較では日本語の名前がよみ順に並ばないため、名前の比較は `Intl.Collator` が使えるブラウザで行う。並び順を変えるたびに通信せず、家庭内の規模なら全件を並べ替えても十分速い。一覧と詳細でレスポンスの形を分けない。
- **レシピを返す応答は、一覧・1件取得・`RETURNING` のどれも、同じ列リスト `recipeColumns` で読む**: 応答の形が1つにそろい、読み込む処理も1つで済む。列を足すときはこの列リストに足す(別に書くと、応答によって項目が欠ける)。
  - タグ名の配列は相関サブクエリの `json_group_array`(タグのid順)で、材料も同じく `json_group_array(json_object(...) ORDER BY position)` で、`bookmarked` は `EXISTS` サブクエリで読む。家庭内の規模なら、行ごとのサブクエリでも重くならない。
  - 画像の有無は `typeof(image) = 'blob'` で調べる。列の型だけを見て中身を読まないので、画像の本体を読まずに `image_url` を組み立てられる。
- **画像はファイルでなくrecipesのBLOB列に入れる**: 保存先がDBファイル1つなので、preview用DBを使えば画像も自動で分かれ、バックアップや配置もDBファイルだけで済む。1レシピ1枚・2MBまでならSQLiteで足りる。
- **`image` はrecipesの最後の列にする**: SQLiteは大きなBLOBを行の後ろのオーバーフローページに置き、BLOBより後ろの列を読むとそこを辿るため。今後recipesに列を足すときはこの点に注意する。
  - `ALTER TABLE ... ADD COLUMN` は列を末尾に足すので、そのままでは `image` の後ろに付く。recipesに列を足すときは、同じマイグレーションの中で `image` を別名に変え、`image` を足し直して中身を写し、古い列を `DROP COLUMN` で消して、`image` を末尾へ戻す(0011)。テーブルを作り直す手順は使わない。外部キーが有効なまま `DROP TABLE recipes` を実行すると、暗黙の `DELETE` でタグの紐付け・ブックマーク・材料・献立がCASCADEで消える。マイグレーションはトランザクションの中で走るので、`PRAGMA foreign_keys` を切ることもできない。
  - ブックマークは、行があるかどうかで状態を表せば済み、外すときも行を消すだけなので、列にせず `recipe_bookmarks` で持つ。レシピを消せばCASCADEで一緒に消える。
- **画像URLの `v`(`image_version`)は、ブラウザのキャッシュを切り替えるためだけに使う**: 画像URLは `immutable` で1年キャッシュされる。
  - `image_version` は保存のたびに増やし、画像を外しても戻さない。外して付け直したときに同じ `v` になると、古い画像が表示されてしまう。
  - 取得では `v` を見ず、常に今の画像を返す。古い版はDBに残さないため。
- **`image_url` はhandlerで組み立てる**: パスはルーティングの知識のため。modelは画像の有無と版をJSONに出さずに持ち、handlerが応答に `image_url` を足す。
- **画像の大きさ・形式の検査はhandlerで行う**: `http.MaxBytesReader` で、2MBを超えた時点で読むのをやめ、大きなボディをメモリに溜めない。形式は `http.DetectContentType` がimage/jpegかどうかで見る。ボディの検査はDBより前なので、IDが無く画像も不正なときは400になる。
- **タグはレシピのJSONに名前の配列で持たせ、idは画面に出さない**: 画面がタグを見分けるのも、URLの絞り込み条件(`?tag=名前`)も名前で足りる。名前はUNIQUEなので取り違えない。
- **タグの置き換えは、紐付けを全部消して付け直した後に、未使用のタグを消す順で行う**: 付けたままのタグを途中で消さないので、idが変わらず、タグの並び(id昇順=最初に作られた順)が保存のたびに入れ替わらない。
- **未使用のタグは保存・削除のたびに消し、`GET /api/tags` は `tags` をそのまま返す**: 未使用のタグがDBに残らないので、使われているかを毎回確かめなくてよい。
- **材料名の候補は `GET /api/ingredient-names` で、`recipe_ingredients` から名前の完全一致でまとめて返し、材料名の表やAPIのパス `/api/ingredients` は作らない**: 材料は量を持つ行なので、`/api/ingredients` だと名前だけの配列ではなく材料の行が返るように読めるため。タグと違い材料名は行ごとに書いた文字列で、別の表に持つと保存のたびに未使用の名前を消す処理が要る。行から集めれば、使われている名前だけが常に出る。タグと同じくレシピに従属するので、レシピのrepository・service・handlerで扱う。完全一致にするのは、表記の違う名前を両方見せて、どちらに寄せるかを人が選べるようにするため。
  - 並びは、使っているレシピが多い順にし、同じ数なら先に使い始めた順にする。表記ブレを減らすのが目的なので、多く使われている書き方を先に出して、そちらに寄せやすくする。同じレシピに同じ名前が2行あっても1つと数え、1つのレシピの書き方で順位が上がらないようにする。使い始めた順は、日時の列が無いので、レシピのid順で、同じレシピの中は並び順で決める。並べ方まで決めるので、SQLで並べる。
- **材料は `recipe_ingredients` に1行ずつ持ち、量は数量(REAL)と、数の位置を `{0}` で表した書式に分けて保存する**: 数量を数として持てば、量の文字列を解析し直さずに数として扱える。書式に数量を当てはめれば、書いた量の文字列に戻せる。並び順は `position` 列で持ち、主キーを `(recipe_id, position)` にして、保存のたびに全行を消して入れ直す(並べ替えても番号が重ならない)。
  - 量から数を取り出すのはserviceで行う(業務ルールのため)。数とみなすのは半角・全角の数字の並びで、間に小数点が1つあってもよい。他の文字体系の数字まで含まないよう、`unicode.IsDigit` は使わず正規表現で決める。数が2つ以上の量は、分数・範囲・桁区切りを1つの数と取り違えないよう、エラーにする。
  - 書式に `{0}` が現れるのは、数を置き換えた1か所だけ。数以外の部分に数字は残らない(量に `{0}` と書いても、その「0」が数として数えられる)。そのため、量の文字列に戻すときは最初の `{0}` を1か所置き換えれば足りる。
  - エラーは先頭の1行だけを「材料N行目: 理由」で返し、Nは送られた配列での行番号にする(両方空で捨てた行も数える。編集フォームの行の位置とそろえるため)。行のエラー型は、名前が空のエラー値を包んでも `Unwrap` しない。`Unwrap` すると、レシピ名が空のエラーの分岐にも当たるため。レシピ名と材料の両方が不正なら、レシピ名のエラーを返す。
- **量の数に桁数の上限は設けず、float64に収まらない数だけをエラーにする**: 家庭のレシピで精度が落ちる桁数の数を書くことはまず無く、決まりとエラー文言を増やさないため、精度の低下は受け入れる。有効数字が16桁を超える数は保存すると別の数になり、1e21以上や1e-6未満の数は、量の文字列に戻すと「1e+22」のような指数表記になる。一方、無限大になる数(整数部が309桁を超えるなど)を保存すると、SQLiteのJSONが `9.0e+999` を出してGoで読めなくなり、そのレシピも一覧も500になって画面から直せない。そのため、無限大になる数だけは「量の数が大きすぎます」で弾く。
- **POST/PUTでは材料を `amount`(量の文字列)で受け、応答では `quantity` と `format` で返す**: 画面は書いたとおりの文字列を送るだけでよく、数かどうかを決めるのはサーバーだけ(入力チェックはサーバーだけで行う)。材料は名前以外の項目があるので、タグのような名前の配列でなく、オブジェクトの配列にする。
- **`recipe_tags.tag_id` にはインデックスを作らない**: 主キー `(recipe_id, tag_id)` で、レシピからの検索は足りる。タグの削除や未使用タグの判定で全件を走査しても、家庭内の規模なら問題にならない。

### 取り込み

- **取り込みのボディは、要素を生のJSONのまま並べた配列として読み、1件ずつ読み直す**: 1件の型の誤り(`title` が数値など)で全体が「リクエストの形式が不正です」にならず、「N件目: 形式が不正です」と何件目かを返せる。ボディが `null` のときは配列としての読み込みがエラーにならないので、読んだ結果がnilかどうかで配列でないと判断する(空の配列はnilにならず「取り込むレシピがありません」になる)。要素が `null` のときも構造体への読み込みがエラーにならず空の件になるので、`{` で始まらない要素は先に形式の誤りにする。
- **取り込みの作った回数は生のJSONのまま受け、整数のリテラルだけを受け付ける**: 整数型で受けると `3.0` や大きすぎる値で件全体が形式の誤りになり、`json.Number` で受けると `"3"` のような文字列も通ってしまう。省略とnullは0とし、負の数は業務ルールとしてserviceで弾く。
- **取り込みは全件を検査してから、1つのトランザクションで配列の順に登録する**: 1件でも不正なら1件も登録しないので、途中まで登録されたあとに送り直して二重に登録されることがない。handlerで読めなかった件も理由を付けてserviceへ渡し、検査とエラー文言の組み立てをserviceの1か所にまとめる。
- **取り込みの不正は1件につき最初の理由1つにまとめ、先頭から10件までを改行区切りで返し、残りは「ほかN件」とする**: 1回送れば何件かまとめて直せ、数百件が不正でもエラー文言が長くならない。理由は、handlerで読めなかったもの(形式の誤り・整数でない作った回数)→名前が空→作った回数が負、の順に決まる。そのため、名前が空で作った回数が `3.0` の件には作った回数の理由が出る。エラー文言に改行が入るので、取り込み画面のエラー欄は改行どおりに出す。
- **取り込みのボディの上限は5MBにし、上限を超えた時点で読むのをやめる**: 本文1,000字程度のレシピなら約1,500件まで一度に送れ、読み込みのメモリはPi Zeroにも収まる。画像と同じく、大きなボディをメモリに溜めない。
- **取り込みではタグを足すだけにし、未使用タグの削除は行わない**: 新しいレシピにタグを付けるだけなので未使用のタグは生まれず、1件ごとに未使用のタグを探さずに済む。タグを足す処理(同じ名前のタグが無ければ作る)は通常の保存と共用し、タグの作り方を1か所に保つ。
- **取り込みでは、同じ名前のレシピがあっても別のレシピとして登録する**: 名前はUNIQUEでなく、通常の作成と同じ扱いにする。
- **取り込み画面は貼った文字列をブラウザで解析せず、そのままサーバーへ送る**: 画面共通の「入力チェックはサーバーだけで行う」に合わせ、構文の誤りもサーバーの「リクエストの形式が不正です」に任せる。`api()` は本文が文字列のときは文字列化し直さずにそのまま送る。常に `JSON.stringify` するように変えると、ボディがJSONの文字列1つになり、配列でないとして弾かれる。
- **取り込みに成功したら貼り付け欄を空にし、失敗したら入力を残す**: もう一度「取り込む」を押しても、同じレシピが二重に登録されないようにする。失敗したときは、直して送り直せるようにする。
- **「取り込む」ボタンは詳細ページの「保存」と同じく上部の右に置き、結果とエラーは貼り付け欄の上に出す**: 貼り付け欄の高さによらず、スクロールしないで押せ、結果も押した位置の近くに出る。
- **受け付けるJSONの形の説明と例は貼り付け欄の下に常に出し、選択・コピーできるのは例だけにする**: スマホでも欄がすぐ目に入り、2回目からは読み飛ばして貼れる。例は写して自分のJSONを作れるようにし、説明の文はコピーする用が無いので選択できないままにする。
- **取り込み画面の「一覧へ戻る」は、詳細ページの、一覧から来たかの判定と同じ式で、一覧から来たときだけブラウザの戻ると同じに動かす**: 一覧の絞り込み条件を残すため。判定の式は使うのが2画面だけなので共通部品に移さず、各画面のJSに同じ式を書く。直すときは両方を直す。
- **一覧・献立から取り込み画面へは、上部右のメニューから移る**: 取り込みはたまにしか使わない操作なので、見出しの行には入口を直接置かず、たまに使う操作をまとめるメニューに入れて、上部右に並ぶボタンを増やさない。項目は画面を移る操作なのでリンクにし、文字だけにする。
  - 開き方・閉じ方・置き方は並び順のメニューと同じにし(理由は「一覧の絞り込み」の並び順の項目)、見た目のCSS(`.menu`)と置く処理(`placeMenu`)を共用する(どちらも base.css と common.js に置く)。片方だけ直すと、2つのメニューの見た目と動きがずれるため。
  - 項目を押したら、移る前にメニューを閉じる。閉じないと、ブラウザの戻るでキャッシュから一覧が復元されたとき、メニューが開いたまま出るため。
  - 一覧の読み込みに失敗してもメニューのボタンは出す。取り込みは一覧の中身に関わらないため。

### 画面共通

- **画面は1つのHTMLと同名のJSに分け、画面によらない既定スタイルは base.css に置く**: 3画面の見た目を1か所でそろえる。base.css には要素の既定スタイルと役割クラスだけを書き、画面固有の部品のCSSは各HTMLの `<style>` に置く。HTMLでは base.css をアイコンのCSSの後に読み込む。同じ詳細度なら後の指定が効くので、配布ファイルを編集せずに base.css で上書きできる。
- **画面によらないJSの部品は `common.js` に置き、画面のJSより先に読み込む**: 一覧・詳細・取り込みで、API呼び出しや回数の表示を同じ処理で使う。置くのは、画面の要素IDや画面の状態を参照しない関数と定数だけにする。`common.js` が画面の要素IDを参照すると、その要素を持たない画面で動かなくなるため。
  - 要素が要る部品(「先頭へ戻る」、ダイアログの外側タップの判定)は、要素を各画面のHTMLに置き、引数で受け取る。特定の要素IDを前提にする確認ダイアログの処理は、そのダイアログを持つ詳細ページのJSに置く。
  - ダイアログの外側タップは、`pointerdown` と `click` の対象がどちらも `<dialog>` 自身のときだけとみなす。中でテキストを選ぶドラッグが外側で終わっても、閉じないようにするため。
  - ES modulesにせず、クラシックスクリプトのグローバルで共有する。部品が少なく、画面ごとに `import` を並べる手間に見合わないため。HTMLでは `common.js` → 画面のJSの順に書く。画面のJSでは `common.js` と同じ名前をトップレベルで宣言しない(同名の `const` があるとエラーになる)。
- **一覧と献立の切り替えは、上部右に並べたアイコンだけのリンク(レシピ・献立)で行い、その右にメニューを置く**: どちらの画面からも同じ位置で切り替えられ、見出しの行のボタンも増やさずに済む。画面を移る操作なのでリンクにし、長押しや中クリックで新しいタブにも開ける。詳細と取り込みには置かない。どちらも一覧か献立から入る画面で、上部には来た画面へ戻る操作と保存などの操作がすでに並んでいるため。
  - 今いる画面のボタンは、`aria-current="page"` で伝え、時間帯の切り替えのオンと同じ青系の背景とアイコンの色で示し(枠の中で隣のボタンと形が同じまま、どちらにいるかが色で分かるようにするため)、押しても移らない。押したり戻したりする操作ではないので `aria-pressed` は使わない。読み上げ名は画面で変えない(名前に状態を足すと二重に伝わるため)。リンクのまま移る動きだけを止めるのは、一覧で誤って押しても絞り込みの条件を消さないため。色の指定は、hover・押している間の指定より詳細度を高くする(低いと、そのとき色が変わる)。
  - 上部右のボタンとメニューのHTMLは、一覧と献立に同じものを書き、動き(`setupMainMenu`・`setupPageNav`)は common.js で共用する。画面は素のHTMLで描く決まりなので、ヘッダーをJSで作らない。ボタンや項目を変えるときは、両方の画面を直す。
- **入力チェックはサーバーだけで行う**: クライアントに二重実装せず、APIの `error` メッセージをそのまま表示する。
- **ボタン・入力欄・ダイアログ・画像・画像なしの枠は同じ枠線と角丸にそろえ、アイコンだけのボタンも角丸の四角にする**: 画面全体の形をそろえ、ボタンと入力欄が並んでも線の太さと色が同じに見えるようにする。編集フォームで画像を選んだり外したりしても、プレビューと「画像なし」枠の形が変わらない。
  - ボタンは白地に枠を付けたアウトラインにし、保存の色(`.primary`)と取り消せない操作の色(`.danger`)は役割クラスで付ける。色の意味をクラスで表し、画面ごとに色を書かないため。
  - ボタンは `inline-flex` でアイコンと文字を並べ、縦位置と間隔をそろえる。
  - 入力欄は内側に余白を取る。角丸にすると文字が角に寄って見えるため。
  - 例外: 献立の期間選択の、枠の中のボタン(開始日・日数・前後の移動)と日数の入力欄には枠線を付けない。理由は「献立」の項目に書く。角丸の枠にまとめたボタン(時間帯の切り替え、一覧と献立の切り替え)の枠の中のボタンにも枠線を付けない。理由は次の「並べて1組にするボタン」の項目に書く。
  - **並べて1組にするボタン(献立の時間帯の切り替え、一覧と献立の切り替え)は、1つの角丸の枠に入れて縦線で区切り、中のボタンには枠線を付けない。形は base.css の `.button-group` にまとめる**: 一組の選択肢だと分かるようにし、ボタンごとの枠が隣り合って線が二重に見えないようにするため。中のボタンも高さ44pxと、hover・押している間の背景はほかのボタンと同じにして、枠線が無くても押せると分かるようにする。2か所で同じ形を使うので base.css に置き、片方だけ直して形がずれないようにする。今いる画面や選んでいる時間帯の色は、各部品の指定で付ける。
  - 例外: 詳細の編集中の材料欄の、入力欄・掴む部分・外すボタンには枠線を付けない。理由は「詳細ページ」の項目に書く。
  - 例外: 詳細の編集中の材料欄の「材料を追加」は、枠線を破線にする。理由は「詳細ページ」の項目に書く。
  - 例外: 「先頭へ戻る」は丸くする。画像や本文の上に重なって浮かぶので、他のボタンと形を変えて浮いていることが分かるようにする。大きさ・枠・hoverと押している間の背景は他のボタンと同じ。
  - 例外: 一覧タイルの回数バッジと「候補に追加」の下地は、角丸を他より小さくする。高さが小さく、同じ半径では両端が丸いカプセル形に見えて、他の部品の角丸の四角と形がそろわないため。小さくしすぎると角が尖って見えるので、角丸の四角に見える大きさにする。左上と右上に並ぶ2つは、枠線も半径もそろえる。
  - 例外: 献立の縮小版パネルの縮小画像と、画像なしの下地は角丸にしない。パネルの高さいっぱいに置いていて上下が枠線に接するので、角だけを丸めると枠線との間に隙間ができて欠けて見えるため。
- **操作が済んだことの知らせは、画面の下端中央に約3秒だけ出すトーストにし、common.js の部品にする**: ページを移らない操作で、押した位置がページの上の方とは限らないため、どこまでスクロールしていても目に入る位置に出す。画面によらない部品なので、トーストの要素は各画面のHTMLに置き、引数で受け取る(common.js が画面の要素IDを参照しない決まりのため)。
  - 要素は `role="status"` にし、`hidden` を使わずに空かどうかで出し分ける。live regionを常に置いておかないと、文言を入れたときに読み上げられないことがあるため。
  - 続けて出すときは文言を差し替えて時間を数え直し、積み重ねない。連続して押しても画面がトーストで埋まらないようにするため。
  - タップは下へ通す。出ている間も、下にあるタイルを押せるようにするため。
  - 幅は、両側に「先頭へ戻る」1つ分と間を残した本文の列の幅までにする。中央に置いても右下の「先頭へ戻る」に重ならないため。
- **影は、ほかの部品の上に重なる「先頭へ戻る」・トースト・ダイアログ・ドラッグ中の材料の行・ドラッグ中の献立のパネルの写しにだけ付け、ダイアログの影を大きく広げる**: 重なっていることを影で表す。ダイアログは「先頭へ戻る」の上にも開くので、影を広げて一番手前にあると分かるようにする。影の濃さは同じにし、広がりだけで手前か奥かを表す。ドラッグ中の材料の行と献立のパネルの写しは「先頭へ戻る」と同じ影で、ほかの部品の上に浮いていることを示す。トーストも「先頭へ戻る」と同じ影で、一覧の上に浮いていることを示す。
- **タッチで押す部品(ボタン・ボタンの見た目のリンク・1行の入力欄)は高さ44px以上、アイコンだけのボタンは44px四方以上にする**: タッチで押しやすくする。base.css の要素と役割クラスの指定で決めるので、画面で部品を足せば何もしなくても満たす。
  - 例外: 一覧の検索欄の中の、探す対象の切り替えとキーワードの入力欄は低くする。検索欄の箱を縦に大きくしないため。どちらも左右いっぱいなので、タッチでも狙いやすい。
  - 例外: キーワードを消すボタンは、横幅を44pxのまま、高さを入力行に合わせる。入力行の右端に重ねるので、はみ出さないようにする。
  - 例外: 一覧タイル上の札は、小さいまま押して絞り込める。タイルの大きさを変えずに、複数のタグを1行に並べるため。押し損ねても、札の外なら詳細へ移るだけで、絞り込みも選択中タグの札の「外す」で戻せる。
  - 例外: 詳細の閲覧表示の札は、小さいまま押して一覧へ移れる。名前と画像の間の札の行を縦に大きくしないため。押し損ねても、ブラウザの戻るで詳細へ戻れる。札は `<a>` で、base.css の最小の高さはかからないので、打ち消しは要らない。
  - 例外: 献立の期間選択で日数を打つ入力欄は低くする。日数のボタンを押してから確定するまでの間だけ出る欄で、出たときにはもうフォーカスが入っており、打つのはキーボードなので、押し直すことがほとんど無いため。44pxにすると、下線が枠の線に重なって見える。
  - 例外の部品は、画面の `<style>` で base.css の最小の高さを打ち消す(打ち消さないと44pxに広がる)。
- **ボタンとボタンの見た目のリンクは、hoverの背景を `@media (hover: hover)` の中だけで付け、押している間(`:active`)の背景は常に付ける**: タッチ端末ではタップ後にhoverが残り、押した後も色が付いたままに見えるため。押している間の手応えは `:active` で出す。
  - hover・押している間の背景は無効のボタンには付けず、無効のボタンは薄くする。保存中などに無効になったボタンが押せるように見えないようにする。
  - 例外の部品は、画面の `<style>` でIDを含む指定にして背景を透明にする。IDを含まないと、base.css のhover・押している間の背景のほうが優先されて出てしまう。
  - 例外: 一覧の検索欄の中の、キーワードを消すボタンと探す対象の切り替えは、hover・押している間も背景を付けない。検索欄の箱の枠の内側に重ねているので、背景を付けると角丸の枠線にかかって見えるため。
- **押すたびに状態が切り替わるボタン(「作った」・ブックマーク・絞り込み)は、押した状態を背景と枠の色で表し、`aria-pressed` で伝える**: 同梱しているのはoutline版のアイコンだけで、塗りつぶしに切り替えられないため。CSSは `aria-pressed` の値を見て色を付け、状態の値を1つにまとめる。色の指定はIDを含めて、base.css のhover・押している間の背景より優先させる(IDを含まないと、押した状態でもhoverや押している間に色が変わる)。
  - ブックマーク中は青系、「作った」はオレンジ系にする。両方が押された状態でも、色でどちらか分かるようにするため。
  - 献立の時間帯の切り替えのオンは、タグ選択ダイアログで選んだタグと同じ青系にする。どちらも「選んでいる」状態なので、色の意味をそろえるため。
  - `aria-label` と `title` は状態で変えず、状態は `aria-pressed` だけで伝える。状態ごとに名前を変えると、読み上げで状態が二重に伝わるため。
- **アイコンだけのボタン・リンクには、`aria-label` と `title` にもとの文言を入れ、アイコン自体は `aria-hidden="true"` にする**: 読み上げではアイコンの文字ではなく名前が読まれ、PCではカーソルを合わせると意味が出る。
- **アイコンは意味ごとに決め、4節「アイコン」の表にアイコン名・このプロジェクトでの意味・使う所をまとめる**: 同じ意味に別のアイコンを使ったり、同じアイコンを別の意味に使ったりすると、画面によって意味がぶれるため。アイコンを足す・替えるときは、先に表を見て、同じ意味のものがあれば使い回す。画面の説明や設計判断には意味の言葉だけを書き、名前は表の1か所にまとめる。
- **作った回数はアイコンと数字だけで表し、0回は数字を出さない**: 一覧で作ったことのあるレシピが見分けやすく、文言を切り替える処理も要らない。
- **画面を移る操作はリンクにし、ボタンの見た目にするときは `<a class="button">` にする**: 長押しや中クリックで新しいタブにも開ける。base.css では `a.button` をボタンと同じ見た目にする。`<a>` は既定では枠を高さの外側に足すので、`box-sizing: border-box` を指定してボタンと高さをそろえる。
- **確認は詳細ページの確認 `<dialog>` 1つを文言違いで使い回し、`confirm()` は使わない**: 見た目を画面とそろえるため。使うのは削除と未保存の破棄だけで、どちらも取り消せない操作なので、OKボタンはHTMLで取り消せない操作の色に固定し、JSで切り替えない。ボタンは文字だけにする(OKの文言を「削除する」「破棄する」と差し替えて使い回すので、アイコンを固定できない)。
- **タグの札は base.css の役割クラスにし、「外す」ボタン付きの札はその変種にする**: 詳細の編集フォームと一覧の選択中タグの2画面で同じ札を使うため。一覧タイル上の札の小ささは一覧の `<style>` で、詳細の閲覧表示の札をリンクにしたときの下線の打ち消しとhover・押している間の背景は詳細の `<style>` で上書きする。どちらも使うのが1画面だけのため。
- **textareaは上下だけ大きさを変えられるようにし、base.css の要素の指定に置く**: 入力欄は本文の列いっぱいの幅なので、横に広げると列からはみ出す。高さは長い本文を書くときに広げたいので、変えられるまま残す。どの画面でも同じtextareaの振る舞いなので、base.css に置く。
- **`[hidden]` には `display: none !important` を指定する**: `display` を指定した要素では `hidden` 属性が効かなくなるため。
- **入力候補(`<datalist>`)を付けた入力欄には、ブラウザが右端に出す▼のマークを出さない。base.css の要素の指定に置く**: ▼があると選ぶしかないプルダウンに見え、自由に打てる欄だと分かりにくいため。候補は打ち始めるかクリックすれば出るので、マークが無くても使える。入力候補を付けた欄ならどの画面でも同じ振る舞いにしたいので、base.css に置く。`list` 属性の無い入力欄(日付など)のマークは残す。
- **UIの文字は body で選択できなくし、選ばせたい要素だけ選択できるように戻す**: 長押しやドラッグでボタン・見出し・タグの札が選択され、タッチ操作の邪魔になるのを防ぐ。既定を選択不可にしておくので、新しい画面を足しても、何もしなければ選択できない扱いになる。iOS Safari向けに `-webkit-user-select` も並べて書く。
  - 入力欄(`input`・`textarea`)と `[contenteditable]` は base.css で戻す。iOS Safariでは祖先に `-webkit-user-select: none` があると入力欄に文字を入力できなくなることがあり、貼り付け欄も戻さないと長押しの「ペースト」が出なくなるため。どれも要素の既定の振る舞いなので base.css に置く。
  - 画面固有の要素(詳細の名前と本文、取り込みの例)は各画面の `<style>` で戻し、base.css には書かない。どれを戻すかとその理由は各画面の項目に書く。
- **本文の列の幅は、一覧のタイルでも詳細と同じにして広げない**: 広い画面で操作が遠くならないようにする。
- **「先頭へ戻る」は、下へスクロールしているときだけ本文の列の右下に浮かせる**: 先頭にいるときは押しても何も起きないため出さない。本文の列の幅と同じく、広い画面で操作が遠くならないよう、本文の右端にそろえる。
  - 出すかどうかは、初期化時と `scroll`・`pageshow` で判定する。再読み込みやbfcacheからの復元でスクロール位置が戻ったときも正しく出すため。表示の切り替えや絞り込みでページが短くなったときは、ブラウザが `scroll` を出すので別に呼ばない。
  - 横の位置は、本文の列の右端と画面の端からの余白の、内側にある方にそろえ、`%` で求める。fixedの `%` はスクロールバーを除いた表示領域の幅が基準なので、本文の右端にそろう。狭い画面では本文の余白と同じだけ端から離れる。
  - なめらかにスクロールし、端末で動きを減らす設定のときだけすぐ移る。移動の様子が見えるので、どこへ戻ったかが分かるため。CSSの `scroll-behavior` は他のスクロールまで変わるので使わず、`scrollTo` の引数で指定する。
  - `body` の下の余白をボタンの高さ分広げる。ページの最後までスクロールしたとき、浮かせたボタンが最後のタイルや本文欄の右下(サイズを変える取っ手)を隠さないようにするため。

### 詳細ページ

- **詳細はまず閲覧表示にし、「編集」で編集フォームに切り替える**: 調理中の誤編集や、画面キーボードが出るのを防ぐため。
  - 操作ボタンは上部の「一覧へ戻る」と同じ行に置く。本文が長くても、スクロールせずに閲覧表示の操作や編集中の「保存」「キャンセル」を押せるようにする。
  - 編集中は左端の「一覧へ戻る」を「キャンセル」に入れ替え、右側は「保存」と「抽出」だけにする。編集をやめる操作をキャンセル1つにまとめ、保存とキャンセルを左右に離して押し間違いを防ぐ。「抽出」は右端に置き、メニューが右端をそろえて開いたときに画面からはみ出さないようにする。
  - 保存ボタンはフォームの外(上部の行)にあるので、`form` 属性でフォームに結び付けている。外すと保存ボタンを押しても送信されない(名前欄のEnterでの送信はフォームの中なので変わらない)。
  - 編集フォームのエラー文言はフォームの先頭に出す。保存ボタンが上部にあるので、押した位置の近くに結果を出す。
- **「作った」は押すたびに切り替わる1つのボタンにし、取り消し専用のボタンは置かない**: SNSの「いいね」と同じく、押すと回数が増えて押した状態になり、もう一度押すと減って元に戻る。続けて押しても回数が重ねて増えず、取り消すと必ず開いたときの回数に戻る。
  - 押した状態は画面のJSだけで持ち、ページを読み込むたびに押す前に戻す。記録したいのは回数で、誰がいつ押したかではないので、DBには持たない。編集に切り替えてもページを離れるまでは保つので、閲覧表示に戻ったあとも取り消せる。
- **ブックマークの状態は画面で持たず、サーバーの `bookmarked` をそのまま出し、押したときは表示中の値を見て付けるか外すかを選ぶ**: 「作った」と違い、ブックマークはDBに持つ状態のため。付け外しは何度送っても同じ結果になるので、別の端末で先に変わっていても、返ってきたレシピで表示がそろう。失敗したときは表示を書き換えず、元のまま残す。
  - ボタンは閲覧表示の操作ボタンの先頭(「作った」の左)に置く。状態を切り替えるボタン2つを隣に並べ、取り消せない削除からいちばん離して押し間違いを防ぐ。
- **詳細は1件取得APIで読む**: 詳細ページは単独のURLで開くため、一覧のデータは使えない。`?id=` の値は画面で検査せずURLエンコードしてAPIへ渡し、サーバーの `error` 文言をそのまま出す(入力チェックはサーバーだけで行う)。例外は `?id=` が空のときで、パスが `/api/recipes/` になって静的配信の404が返り、意味のある文言が出ないため、画面側で「IDが不正です」を出す。
- **一覧か献立へ移るときは、その画面から来たときだけブラウザの戻ると同じに動かす**: 一覧の絞り込み条件はURLにあるので、戻れば条件も戻る。献立も、戻ればスクロール位置と日付の開閉が残る。来た画面は、読み込み時の `document.referrer` が同じオリジンの `/recipes.html` か `/plans.html` かで決める(取り込み画面の一覧の判定も同じ式なので、直すときは両方を直す)。献立から来たときは、押した先が一覧ではなくなるので、上部左のボタンを「献立へ戻る」にする。どちらでもないとき(URLを直接開いたときなど)は、一覧へのリンクとして動く。
  - 削除した後も、来た画面へは戻るで移る。どちらからも来ていなければ履歴を置き換えて一覧へ移り、詳細のURLを履歴に残さない。ブラウザの戻るで、削除済みのレシピのページに戻らないようにする。
  - 新規作成の保存では、POSTの直後に、履歴を増やさずURLを `?id=` 付きへ書き換える。画像の保存が失敗して編集フォームにとどまっても、再読み込みで同じレシピを開けるようにする。
- **編集フォームの人数欄は `type="text"` に `inputmode="numeric"` を付け、`type="number"` にしない**: `type="number"` は数として読めない入力の値を空にするので、空欄を0として保存する決まりと重なって、打ち間違いが黙って0で保存されるため。全角の数字は画面で半角に直し、数字だけなら数として、それ以外は文字列のまま送り、正しさはサーバーで決める(入力チェックはサーバーだけで行う)。
- **人数の0は、閲覧表示では出さず、編集フォームでは空欄で出す。未保存の判定は送る値で比べる**: 0は未設定の意味なので、「0人分」と出すと設定した人数に見えるため。空欄と「0」はどちらも0として保存されるので、どちらに変えても未保存の変更に数えない。
- **閲覧表示の人数は `role="img"` にして、読み上げ名と `title` を「N人分」にする**: アイコンは読み上げないので、数字だけでは何の数か分からないため。見出し(`h1`)の外の兄弟要素にして、見出しの文字の大きさを受けないようにし、`align-items: baseline` で名前の1行目にそろえる。
- **材料の量を書式と数量から文字列に戻す関数 `formatAmount` は common.js に置く**: 閲覧表示の量の列と、編集フォームの量の欄の両方で使うため。
- **編集フォームの材料の行は、入力欄の値を正とし、配列に写して持たない**: 保存と未保存の判定のときに、画面の順で読み出す。入力のたびに描き直すと、フォーカスとIMEの変換が切れるため。名前の入力に合わせて変えるのは、外すボタンと掴む部分の名前だけにする。
- **材料は、名前も量も空の行を含めて画面の行の順のまま送る**: サーバーは両方空の行を捨てたうえで、エラーの「材料N行目」を送られた配列での位置で返す。画面で空の行を除いてから送ると、番号が画面の行とずれる。
- **名前も量も空の材料の行は、未保存の変更に数えない**: 保存してもサーバーが捨てるので結果が変わらないため。編集を始めたときの行と今の行の両方から、前後の空白を除いて両方空の行を外して比べる。「材料を追加」を押しただけなら、確認を出さずにキャンセルできる。
- **材料が0件のレシピで編集を始めたときは、空の行を1つ出す。外して0行になったときは足さない**: 「材料を追加」を押さずにすぐ打ち始められるようにする。外すのは明示した操作なので、勝手に行を戻さない。
- **材料の欄でのEnterは、IMEの確定でなければ次の欄へ移り、最後の行の量の欄では行を足して移る**: 何もしなければEnterでフォームが送信され、材料を書いている途中で保存されてしまう。キーボードだけで続けて書けるようにする。IMEの判定はタグ欄と同じ式(`isComposing` と `keyCode === 229`)。
- **材料の外すボタンの読み上げ名と `title` は「「名前」を外す」にし、名前が空の行では「N行目の材料を外す」にする**: 同じボタンが行ごとに並ぶので、どの行のボタンか分かるようにする(タグの札の「外す」と同じ形)。空の行が複数あっても区別できるよう、番号は行を足し外すたびに振り直す。
- **材料の名前欄の入力候補は、タグ欄と同じく `<datalist>` に入れ、編集を始めるたびに `GET /api/ingredient-names` で読み、失敗しても無視する**: 候補は入力の補助なので、取れなくても手で打てば足りるため。別の端末で増えた材料名も出る。datalistは材料欄に1つだけ置き、行を作る関数で名前欄に結び付けるので、「材料を本文から抽出する」で足した行にも同じ候補が付く。量の欄には付けない。
  - 編集中のレシピにある名前も候補から外さない。下味と仕上げで同じ調味料を書くような、同じ名前の材料を2行書くことがあるため。外さないので、候補は読んだときに1回入れれば済み、入力や行の足し外しのたびに作り直さない。
- **材料の行を外したら、詰めてきた同じ位置の行の外すボタンへフォーカスを移す。末尾なら1つ前の行、1行も残らなければ「材料を追加」へ移す**: フォーカスが `body` に落ちず、続けて外していける。
- **材料欄には見出しを付けず、欄全体を `role="group"` の読み上げ名「材料」でまとめ、入力欄のプレースホルダは「材料」「量」にする**: ほかの欄と同じく、見出しの行でフォームを縦に伸ばさないため。名前欄のプレースホルダを「名前」にするとレシピの名前欄と見分けにくくなる。
- **材料欄は行を1つの角丸のパネルにまとめ、行の間を横線、行の中の掴む部分・名前・量・外すボタンの間を縦線で区切り、入力欄とボタンには枠を付けない。掴む部分と外すボタンは44px四方のアイコンだけのボタンのまま保つ**: 部品ごとに枠を付けると行の中で枠が隣り合って線が二重に見え、どの名前とどの量が同じ行かもたどりにくいため。行と列の線だけにすると、閲覧表示の材料の表と同じく線で組をたどれる。枠を外しても、タッチで押せる大きさは変えない。
  - 中の線は外枠より薄くする。外枠はほかの部品と同じ線にそろえ、中の区切りと見分けられるようにするため。
  - パネルの角に接する掴む部分と外すボタンは、接する角だけを外枠の内側に合わせて丸める。hoverと押している間の背景がパネルの角丸からはみ出さないようにするため(献立のパネルの外すボタンと同じ)。
  - フォーカスの強調はブラウザ標準のまま、マスの内側に出す(`outline-offset: -2px`)。枠が無いと入力中の欄が分かりにくいが、外側に出すと隣のマスやパネルの角丸に重なるため。iOS Safariでは強調が出ず、カーソルの点滅だけになることは受け入れる。
  - 材料が0行の間はパネルを出さない(`:not(:empty)` のときだけ枠と余白を付ける)。中身の無い枠だけが残らないようにするため(閲覧表示で0件の表を隠すのと同じ)。
- **材料欄の行を足すボタンは、パネルの下に横幅いっぱいで置き、枠線を破線にして、文言を「材料を追加」にする**: 破線の枠は、一覧の追加パネルと同じく、まだ無いものを足す場所だと示す。横幅をパネルにそろえると、パネルの続きに見え、タッチでも狙いやすい。文言に「材料」を入れるのは、すぐ上のタグ欄の「追加」と、見た目でも読み上げでも区別できるようにするため。変えるのは線の種類だけにし、枠と文字の色、hoverと押している間の背景はほかのボタンのままにして、押せる部品だと分かるようにする。
- **材料の行の並べ替えは、行の左端の掴む部分だけをPointer Eventsのドラッグで受け、HTML5のドラッグ&ドロップは使わない**: HTML5のドラッグ&ドロップはタッチ端末のブラウザでは動かないため。`touch-action: none` は掴む部分にだけ付けてポインタを捕まえるので、ほかの場所のドラッグはふつうのスクロールや入力欄の操作のまま残る(行全体に付けると、スマホで材料欄の上からスクロールできなくなる)。左端に置くのは、右端の外すボタンから離して押し間違いを防ぐため。
  - 掴む部分はボタンにし、フォーカスがあるときは上下の矢印キーで1行ずつ動かす。キーボードや読み上げでも順番を変えられるようにするため。読み上げ名と `title` は外すボタンと同じ形にする。行の中でボタンが2つになるので、外すボタンはクラス `ingredient-remove` で探す(行の最初のボタンを取ると掴む部分を拾う)。
  - ドラッグ中は、掴んだ行もほかの行も `transform` で動かし、DOMの順は離したときに1回だけ入れ替える。動かしている間に入れ替えると、行の位置が変わって入る位置の計算も見た目も跳ぶため。入る位置は、掴んだときに測った各行の元の位置と、掴んだ行の中心を比べて決める。
  - 離したときは、よける動きのアニメーション(`sorting` クラス)を止めてから `transform` を外し、DOMを入れ替える(順が逆だと、外す瞬間に行が元の位置へ戻って見える)。タッチがOSに取り消されたとき(`pointercancel`)や捕捉を失ったときは入れ替えず、元の並びに戻す。
  - 表示領域の上端・下端から48px以内に近づけている間は、近いほど速く(1フレーム最大12px)自動でスクロールする。スマホで画面に収まらない位置へも1回のドラッグで動かせるようにするため。掴んだ行の位置はページ上の座標で求め、スクロールの量も反映する。
  - ドラッグ中の行は自分の角丸で中身を切り抜き、行の間の横線を消す。パネルから浮いて動く行の角から、掴む部分の背景や横線がはみ出して見えないようにするため。パネルのほうでは切り抜かない。切り抜くとパネルの端の外へ動かした行と影が欠けるため。
  - 送信中は受け付けない。保存中に順番が変わると送った内容と画面がずれるため。掴む部分は `setBusy` でほかのボタンと一緒に無効になる。
  - 並べ替えは、未保存の変更の判定と保存に手を加えずに反映される。どちらも入力欄を画面の順に読み出しているため。
- **編集のキャンセルでは、未保存の変更があれば確認する**: 変更の有無は、編集を始めたときの値と比べて決める。既存のレシピなら閲覧表示へ、新規作成なら一覧へ戻る。
- **戻る・再読み込み・タブを閉じるでの離脱は、編集中に未保存の変更があるときだけ、`beforeunload` でブラウザ標準の確認に任せる**: これらの操作は、画面内の確認 `<dialog>` では止められないため。画面内で編集をやめる操作はキャンセルだけ(編集中は「一覧へ戻る」を出さない)なので、画面内の確認 `<dialog>` で足りる。
  - 画面内で確認を済ませた遷移(新規作成のキャンセルで「破棄する」を選んだ後など)では、ブラウザの確認を重ねて出さない。画面内から一覧へ移る処理は、必ず `leaveToList()` を通す(通さずにURLを変えると、確認が二重に出る)。`leaveToList()` が立てる印は、bfcacheから戻ったときに `pageshow` で下ろす(下ろさないと、戻った後に編集しても離脱確認が出ない)。
  - iOS Safariでは確認が出ないことを受け入れる。`beforeunload` の確認に対応していないため。個人利用で、入力の自動保存などの代替はROADMAPに無いので作らない。
- **本文は書いたとおりの改行で出し、`http://`・`https://` のURLだけをリンクにする**: 本文に書かれたHTMLを解釈させないよう、`innerHTML` を使わず、URLの部分は `<a>`、残りはテキストノードで入れる。
  - URLは `http://`・`https://` から、空白やASCII以外の文字の手前までとし、末尾の句読点・閉じ括弧(`. , : ; ! ? ' " ) ] } >`)を外す。日本語の文中に書いたURLが、後ろの文字や「。」「)」を巻き込まないようにする。括弧の対応は数えないので `)` で終わるURLは末尾が欠けるが、レシピの出典URLでは稀なので受け入れる。
  - リンクは新しいタブで開き、`rel="noopener noreferrer"` を付ける。調理中に見ているレシピの画面を残すため。開いた先からこのページを操作させず、LAN内のURLも送らない。
  - 長いURLの途中での折り返しは、リンクにだけ許す。本文のほかの文字の折り返し方を変えないため。
- **閲覧表示のレシピ名・材料・本文だけを選択できるようにする**: 材料や出典URLをコピーしたいのはこの3つの要素だけのため。本文中のリンクは親に従う。一覧タイルの名前は、タイル全体が詳細へのリンクで、長押しはリンクの操作に使うので、選択できないままにする。
- **閲覧表示の材料は `<table>` の2列にし、見出しを付けず、読み上げ名を `aria-label`「材料」で付ける**: 名前と量の組が行としてそろい、まとめて選んでコピーすると行ごとに名前と量がタブ区切りで写る。見出しを付けないのは、閲覧表示のタグ・画像・本文にも見出しが無いのにそろえ、スマホで本文が下へ押し出されないようにするため。
  - 量は右端に寄せ、行と行の間だけに線を引く(表の上下の外枠には引かない)。名前と量が離れる広い画面でも、どの名前の量かを線でたどれる。
  - 量は `formatAmount` で書式に数量を当てはめて出し、画面で数を組み立て直さない。量の文字列への戻し方を、編集フォームの量の欄と1か所にそろえるため。
  - 名前は `overflow-wrap: anywhere` で折り返し、量は `break-word` にする。量まで `anywhere` にすると、長い名前に押されて量が1文字ずつ折れる。
- **閲覧表示のタグの札は、そのタグ1つだけで絞り込んだ一覧へのリンクにし、一覧で使っていた条件は引き継がない**: 詳細で見かけたタグから、同じタグのレシピをたどれるようにする。来たときの一覧の条件を引き継ぐと、キーワードやほかのタグとのANDで、押したタグのレシピが一部しか出ないことがあるため。同じタブで移るので、ブラウザの戻るで詳細に戻れる。編集フォームの札は「外す」を押す場所なので、リンクにしない。
  - 押せることは、ほかに印を付けず、hoverと押している間の背景の変化だけで示す(一覧タイル上の札と見せ方をそろえるため)。札の地がもともと灰色なので、それより濃い色にする。hoverの背景は `@media (hover: hover)` の中だけで付ける。
- **編集フォームの欄には見出しを付けず、名前・タグ・本文の欄はプレースホルダで示し、読み上げ用の名前は `aria-label` で付ける**: 見出しの行の分だけフォームが縦に伸び、スマホでは本文欄が下へ押し出されるため。プレースホルダは入力すると消えるが、欄の並び順と中身で区別できる。読み上げはプレースホルダに頼らず `aria-label` で名前を付ける。タグの入力欄は、付けた札の列と区別するため、読み上げでは「追加するタグ」のままにする。画像欄は「画像なし」枠やプレビューで画像の欄だと分かるので、文言を足さない。
  - 欄の間隔はフォームのflexの `gap` で取り、各欄の上下のmarginは0にする。エラー文言・プレビュー・「画像なし」枠は状態によって出たり消えたりするが、隠れた要素はgapに数えられないので、どの状態でも欄の間がそろう。marginで取ると要素ごとの指定が重なり、間隔がずれやすい。
- **選んだ画像はブラウザで長辺800px以下に縮めてJPEGにし、保存するまで送らない**: 2MBの上限に収まり、Pi Zeroで画像を処理しなくて済む。保存前は送らないので、破棄してもサーバーには何も残らない。
  - 変換は `<img>` に読み込んでcanvasへ描く。ブラウザがEXIFの向きを反映した大きさで描くため、スマホの写真が横倒しにならない。描く前に白で塗り、透過PNGの透過部分が黒くならないようにする。
- **編集中の画像の変更は、「変更なし」「新しい画像」「外す」のどれかを表す1つの値で持つ**: 未保存の判定と、保存時に呼ぶAPIを、この値だけで決められる。もともと画像の無いレシピで外したときは「変更なし」に戻す。
- **保存はレシピのPOST/PUTを先に、画像APIを後に呼ぶ**: 新規作成では、画像を送るためのidがPOSTまで無いため。画像だけが失敗したら、選んだ画像を残して編集フォームにとどまり、表示中のレシピを保存済みのものに替える。再保存はPUTと画像の送り直しになり、新規作成でも二重に登録されない。
- **画像は幅いっぱいにし、高さは画面の高さに対する割合で固定して、合わない分は切り抜く**: 縦長・横長どちらの写真でも高さが一定になり、スマホでも名前・タグのすぐ下に本文が見える。閲覧表示と編集のプレビューで同じ見た目にする。「画像なし」枠は、文言・案内・44pxの「画像を選ぶ」を縦に並べても窮屈にならない高さが要るので、画像の高さには合わせない。
- **編集フォームの画像欄は、画像の有無でできる操作だけを出す**: 画像が無いときは「画像なし」枠に貼り付けと「画像を選ぶ」を、画像があるときはプレビューに「画像を外す」だけを出し、下に並べるボタン行は置かない。その状態で使えない操作が並ばず迷わない。差し替えは外してから選び直す形にし、画像がある状態での貼り付けや選び直しで、うっかり上書きしないようにする。
  - 「画像を外す」はアイコンだけにしてプレビューの右下に重ね、取り消せない操作の色にしない。画像を隠す範囲が小さく済む。外しても保存するまでは確定せず、キャンセルで戻せる。
  - 「画像を選ぶ」は `contenteditable` の貼り付け欄の外に置き、枠いっぱいの貼り付け欄の上に重ねる。ボタンを中に入れると編集できる中身の一部になり、中身を戻す処理とぶつかるため。「画像なし」と案内の文言は貼り付け欄の中に置き、枠のどこを長押ししても「ペースト」が出るようにする。ボタンを重ねた層は `pointer-events: none` にして、ボタンだけで受ける(外すと、層の下の貼り付け欄にタップが届かなくなる)。

  - 貼り付けた画像は「画像を選ぶ」と同じ処理に渡す。縮小・JPEG変換・プレビュー・未保存の判定・保存を、画像の入手方法によらず1つの流れにする。

  - 入力欄に文字を残したまま保存すると、その文字もタグとして足す。打ったタグが黙って消えないようにする。入力欄に文字があるだけでも未保存の変更とみなし、キャンセルや離脱で確認を出す。
  - 候補は、編集を始めるたびに `GET /api/tags` で読み、失敗しても無視する。別の端末で増えたタグも候補に出る。候補は入力の補助なので、取れなくても手で打てば足りる。付けているタグは候補から外す。
  - 札の「外す」は44px四方のアイコンだけのボタンにし、編集フォームの札は閲覧表示より大きくする。アイコンだけのボタンを、タッチで押しやすい44px以上にそろえる規則を優先する。閲覧表示の札は押すと一覧へ移るリンクだが、一覧タイル上の札と同じく小さく出す(「画面共通」の44pxの項目の例外)。

### 一覧タイル

- **一覧はタイルグリッドにし、列数はグリッドの `auto-fill` の最小幅だけで決め、media queryを書かない**: 最小幅は、スマホで2列、本文の列の幅で4列までになるように選ぶ。行と列の間隔は同じにする。名前は枠の外に出さないので、行の間だけを広げて名前とタイルの対応を示す必要が無い。
- **一覧タイルは `<li>` の中に詳細へのリンク `<a>` を置き、枠線と角丸はリンクの中の正方形の要素に付けて、はみ出しを切り抜く**: 画像と名前の帯を1つの枠に収め、帯の下側の角を枠の角丸に合わせるため。回数バッジは枠の内側にあるので欠けない。リンク自体の下線と文字色は打ち消す。
- **名前は画像の有無によらず、正方形の下端の帯に1行で重ね、枠の外には出さない**: タイルが正方形1つにそろい、画像なしでも同じ場所で名前を読める。長い名前は「…」で省略し、全文はタイルの `title` と詳細で確かめる。文字の大きさは帯の上のタグの札と同じにする。それより大きいと、タイルの幅では短い名前でも省略されたため。
  - 画像なしのタイルの中央には、名前ではなく料理のアイコンを薄く置く。名前は帯に出るので二重に出さない。写真が無いのは欠けや不具合ではないので、画像が無いことを示すアイコンではなく、料理のタイルだと分かるアイコンにする。画像が無いことを示すアイコンは、詳細の編集中の「画像を外す」にだけ使う。
- **一覧の画像は `loading="lazy"` で読み、サムネイルは作らない**: 縮小せずに出すので、画面外のタイルの画像までPi Zeroから一度に取りに行かないようにする。画像は保存時にブラウザで縮めてあるので、サムネイルのためにPi Zeroで画像を処理しなくて済む。
- **一覧タイルの回数バッジは0回では出さず、1回以上は下地のオレンジの濃さ5段階で回数の多さを示す**: よく作るレシピが一覧で一目で分かり、まだ作っていないレシピも見分けやすい。
  - 段階は `Math.ceil(回数 * 5 / 最大値)` の1〜5にする。`回数 / 最大値 * 5` の順で計算すると、境目の値が小数の誤差で次の段階に上がることがあるので、掛けてから割る。
  - 最大値は、絞り込む前の全レシピから、描き直すたびに求める。絞り込み・検索・並び替えで同じレシピの色が変わらず、読み直しで回数が変わっても、全タイルが同じ基準で描かれる。
  - 5段階の色は、白と5段階目の色の間を同じ幅で補間し、段階が上がるほど同じだけ濃くなるようにする。5段階目だけは、下地が濃く黒では読みにくいので、アイコンと数字を白にする。枠線の色はどの段階でも変えず、変えるのは下地だけにする。
  - アイコンと数字の中身は、詳細の「作った」ボタンと共用する common.js の部品で作り、一覧のクラスを足して重ねる。アイコンと数字を1か所で決めるため。出すかどうかと色は一覧だけで決め、詳細は0回でもアイコンを出す(押して回数を変える操作のため)。
  - 行の高さをアイコンにそろえ、数字の有無でバッジの高さが変わらないようにする。指定は、共用のクラスでなく一覧のバッジのクラスに書く(共用のクラスに書くと、詳細の「作った」ボタンの高さまで変わる)。
  - バッジはタイルの左上に置く。タイルではブックマークを付け外しせず、詳細と一覧の絞り込みで扱う。右上は「候補に追加」のボタンに使う。
- **「候補に追加」は、タイルの右上に置いた44px四方の透明で枠のないボタンの中に、回数バッジと同じ形の下地を入れて小さく見せる**: 押せる範囲はタッチで押しやすい44px四方のまま残し、写真を隠す範囲だけをバッジと同じ大きさに抑えるため。下地は外枠からの距離をバッジとそろえ、左上のバッジと左右対称に並べる。
  - ボタンはリンクの中に置かず、タイルの `<li>` の中でリンクの兄弟要素として重ねる。`<a>` の中には `<button>` を置けないため。
  - hoverと押している間は、透明な部分ではなく下地だけに色を付ける。base.css のhover・押している間の背景は、IDを含む指定で透明に打ち消す(IDを含まないと、base.css の指定のほうが優先される)。
- **「候補に追加」は、既存の献立のAPIで候補の先頭(位置0)に1件置くだけにし、候補用のAPIを作らない**: 候補は献立の行なので、置く位置の決め方を献立画面と共用できるため。一覧は献立の行を持たないので、追加した後に読み直さない。
- **「候補に追加」は、送信中はそのタイルのボタンだけ押せないようにし、ほかのタイルは押せるままにする**: ダブルタップで同じレシピが2件入らないようにしつつ、いくつかのレシピを続けて足せるようにするため。送信中のレシピは画面の状態に持ち、送信中に絞り込みなどで描き直しても押せないままにする。描き直したタイルは新しい要素になるので、応答の後は今のタイルのボタンを探して戻す。無効にするとフォーカスが外れるブラウザがあるので、押す前にフォーカスがあったときだけ戻す。
- **「候補に追加」の失敗は、一覧のエラー欄に「候補に追加できませんでした: 理由」で出す**: 同じ欄に読み込みの失敗も出るので、何が失敗したかを見分けられるようにするため。エラー欄はページの上の方にあり、下までスクロールしていると気づきにくいことは受け入れる。次に押したときに消すので、古い失敗が残らない。
- **タイルのタグは名前の帯のすぐ上に1行で並べ、はみ出す分は末尾から隠して「+N」にまとめる**: タイルの大きさを変えずに、付いているタグが分かる。1つ目だけでも収まらないときは、そのタグを「…」で省略する。札の行と名前の帯は1つにまとめて下端に置き、札の行の高さを決め打ちしない。
  - タグで絞り込んでいるときは、選んでいるタグを除いて並べる。選んでいるタグは表示中のどのタイルにも付いていて、選択中タグの札にも出ているため。Nは、除いた後に並べるタグのうち、隠した数にする。残りが0件なら札の行を出さない。タグを選ぶたびにタイルを作り直すので、外したタグはすぐ戻る。
  - 収まるかどうかは描画した後に幅を測って決めるので、列数が変わる `resize` のたびに測り直す(1フレームに1回にまとめる)。
- **タイル上の札を押すと、そのタグをタグの絞り込みに加え、ページの先頭へすぐ移る。「+N」と札の外を押したときは詳細へ移る**: 見かけたタグで、ダイアログを開かずに絞り込めるようにする。
  - 札はリンクの中に置いたままにし、一覧のリストで受けたクリックが札からのときだけ、詳細へ移るのを止めて絞り込む。`<a>` の中には `<button>` を置けず、札の行をリンクの外へ出すと、名前の帯の上への重ね方や好評の縁との重なりを作り直すことになるため。その代わり、札はキーボードや読み上げでは押せない。その場合はタグ選択ダイアログで絞り込む。
  - 押せる札にだけ `data-tag` でタグ名を持たせ、「+N」には持たせない(持たせると、「+N」を押しても絞り込んでしまう)。
  - 先頭へは、なめらかに動かさずにすぐ移る。押した直後に一覧の中身が入れ替わるので、入れ替わった一覧をスクロールしていく様子を見せる意味が無いため。
  - hoverの背景は `@media (hover: hover)` の中だけで付け、押している間の背景は常に付ける。理由はボタンと同じで、タッチ端末でタップ後に色が残らないようにするため。
- **名前がちょうど「好評」のタグが付いたレシピは、一覧タイルの内側の縁をオレンジで明滅させて強調する**: アイコンを足さずに、よく褒められたレシピが一覧で目に入るようにする。オレンジは写真に重ねても目立つ。回数バッジの5段階目と色は近いが、形と位置(タイルの縁全体)で見分けられる。
  - 判定はタグ名の完全一致にし、検索用の正規化は通さない。「好評!」「大好評」を対象にしないため。絞り込む前のタグで判定するので、「好評」で絞り込んでいても強調は残る。
  - 強調するのは一覧タイルだけで、詳細ページ・トグルボタン・API・取り込みの項目・絞り込みは足さない。好評はタグ1つで表すので、付け外しは編集フォームのタグ欄、絞り込みは今のタグの絞り込みで足りる。
- **好評の縁は、正方形の要素の疑似要素を一番手前に重ねて内側に描き、外側のグローは使わない**: 外側に影を付けると、好評のタイルが並んだときにグリッドの間隔が色で埋まり、隣の好評でないタイルまで縁取られて見えた。内側に描けば、強調がそのタイルの枠の中に収まる。
  - 正方形の要素そのものに内側の影を付けると、全面に敷いた画像の下に隠れる。そのため層を重ね、`pointer-events: none` でタップをリンクへ通す(外すと、タップがリンクへ届かない)。
  - 好評のタイルでも枠線は残す。重ねる層の角丸は、正方形の角丸から枠線の太さを引いた値にして、枠の内側の角に合わせる。枠線か角丸を変えるときは、両方を直す。枠線が残るので、回数バッジの位置は好評のタイルでも変えない(好評のタイルだけずらすと、ほかのタイルとバッジの位置がそろわない)。
- **好評の縁は加算合成で重ね、`opacity` だけを0〜1に往復させて明滅させる。端末で動きを減らす設定のときは明滅を止め、光ったままにする**: 加算合成なら、写真の色を塗りつぶさずに縁が光って見える。明滅の動きがあれば、密集していても好評のタイルだけを見分けやすい。影そのものを動かすより描き直しの負担が軽く、タイルの多い一覧でもスマホやタブレットで重くなりにくい。値は写真に重ねて見ながら決めた。
  - 次の2つは承知の上で受け入れる。`opacity` が0まで下がるので、好評でないタイルと区別がつかない瞬間がある。画像なしのタイルは下地が薄い灰色なので、加算すると縁がほぼ白になり、ほとんど強調されない(画像なしのタイルだけ指定を分けることはしない)。
- **強調したタイルでは「好評」の札を札の行に並べず、「+N」にも数えない。代わりに、読み上げ用の見えない「好評」の文字を、札の行の外(名前の帯の先頭)に置く**: 縁の明滅で分かることを札で二重に示さず、ほかのタグの場所を空ける。見えない文字はリンクの読み上げ名に残り、読み上げでも好評だと分かる。札の行の外に置くのは、札が収まるかの測り方と「+N」の数え方を変えないため。「好評」で絞り込んでいるときは、ほかの選択中タグと同じく、読み上げ名からも除く。見えなくするクラスは使うのがこの画面だけなので、base.css ではなく一覧の `<style>` に置く。
- **レシピの追加は一覧の先頭のパネルから行い、ヘッダーに新規作成ボタンは置かない**: 追加の入口がタイルと同じ並びにあり、タッチ端末でも大きな的になる。0件でも同じ場所に出るので、空状態の案内文は要らない。並び順や絞り込みによらず先頭に置く。
  - パネルには名前の帯と回数バッジを付けず、破線の枠の中央に、足すことを示すアイコンと「追加」を出す。レシピのタイルと形と大きさをそろえながら、レシピではないことが一目で分かる。枠と文字の色、hoverと押している間の背景は、ボタンと同じ規則にそろえる(hoverは `@media (hover: hover)` の中だけ)。
  - パネルはHTMLに置かず、一覧を描くたびにJSで作る。描き直すときにリストを丸ごと空にして作り直すので、HTMLに固定で置くと、残すための処理が要る。
- **一覧はbfcacheから復元されたとき(`pageshow` の `persisted`)に読み直し、詳細は読み直さない**: 一覧は、復元されると詳細ページでの保存・削除・「作った」が反映されないため。詳細は、編集中の入力が消えないよう復元のままにする。

### 献立

- **献立の期間は端末のlocalStorageに持ち、DB・URLには持たない**: 期間は献立の中身ではなく、その端末でどこを見るかの設定なので、別の端末の表示を変えない。URLに持たないのは、一覧から上部右の献立のリンクで移ったときも、前に見ていた期間が残るようにするため。読めない値や範囲外の値は捨てて「今日から7日間」にし、読み書きに失敗しても画面は使えるようにする。
- **期間の値は画面で検査する**: 「入力チェックはサーバーだけで行う」の例外。期間はサーバーに送らない値なので、確かめられるのは画面だけのため。日数が1〜31の整数でなければ、近い値に丸めずに元の日数に戻す。打ち間違いで期間が黙って変わらないようにするため。
- **日付の計算は年月日の数で行い、ミリ秒の足し引きはしない**: 夏時間のある地域で、日付が1日ずれないようにするため。
- **開始日は、「M/D(曜)」を出したボタンの上に透明な日付入力欄を重ね、ボタンを押したときにその欄の日付選択を開く**: 日付入力欄をそのまま見せると、表示の形がブラウザごとに変わり、曜日も出ないため。欄をボタンと同じ大きさで重ねるのは、日付選択がボタンの位置に開くようにするため。欄は `pointer-events: none` にして、押すのはボタンで受ける。日付選択を開く仕組みが無いブラウザでは、欄にフォーカスするだけにする。値を消したときは開始日を変えない。
- **日数は、押したときだけその場で数字の入力欄に替える**: ふだんは「から7日間」の文の一部として読めるようにし、変えるときだけキーボードで打てるようにする。Enterで入力欄を隠すと欄の外を押したときと同じ確定がもう一度起きるので、確定と取り消しは1回だけ処理する。IMEの変換を確定するEnterでは確定しない。
- **前後の移動は、開始日を日数分ずらす**: 続けて押すと、期間が重なりも空きもなく並ぶ。
- **期間選択UIは見出しのすぐ下、候補より上に置く**: 開いてすぐ、どの期間を見ているかが分かるようにするため。
- **期間選択UIは、1つの角丸の枠を横幅いっぱいに置き、前後の移動を枠の左端と右端に、「M/D(曜) から N 日間」をその間の中央に入れ、枠の中のボタンはどれも枠線なしにする**: 期間を1つの文として読め、前後の移動もその期間を動かす同じ部品だと分かるようにするため。前後の移動を両端に置くと、矢印の向きと置き場所がそろい、文との間に余白ができて文の続きに見えないので、区切りの縦線は置かない。枠を横幅いっぱいにして、下に並ぶ候補・毎日・日付のエリアと左右の端をそろえる。開始日・日数のボタンの背景は角丸にせず、「から」「日間」との間を空ける。背景が文字に接して文字まで押せる部品に見えないようにし、枠の上下に接する背景の角だけが丸く欠けて見えないようにするため。両端の前後の移動の背景だけは、枠からはみ出さないよう枠の角丸に合わせる。枠の中のボタンも高さ44pxを保ち、hover・押している間の背景をほかのボタンと同じにして、枠線が無くても押せると分かるようにする。
- **日数の入力中は、数字の部分だけを下線の細い入力欄に替え、日数のボタンと同じ幅にする**: 入力に替えても枠の大きさと「から」「日間」の位置がずれず、文の一部をその場で書き換えているように見えるようにするため。数字入力の増減の矢印は出さない。
- **候補はブックマークとは別に、献立の行として持ち、並びは行の並び順にする**: ブックマークは「気に入ったレシピ」の印で、献立を組むために一時的に集めるものとは役割が違うため。ブックマークは一覧の絞り込みと詳細で使い続け、候補には引き継がない。候補は献立のAPIで一緒に読むので、期間によらず毎回全件を出す。
- **候補の見出しは「候補」にし、0件のときは文言を出さず、枠の中央に「候補に追加」のアイコンを薄く大きめに出して、何をすれば候補に並ぶかを伝える。アイコンは読み上げない**: 献立を組むときの役割は見出しで示し、何をすれば候補に並ぶかは、並ばないときにアイコンで示せば足り、文の行で画面を長くしないため。薄く大きめにするのは、空の帯と同じく、置いたパネルと見間違えないようにするため。読み込みに失敗して枠が空のときもアイコンを出すのは、空の枠の見た目をいつも同じにして、失敗した理由はエラー欄の文言で伝えるため。
- **候補の読み込みの失敗は、献立の読み込みの失敗と同じ1つの文言で、期間選択UIの下に出す**: 候補は献立のAPIで読み、並べるにはレシピ一覧も要るので、献立と候補は必ず一緒に失敗する。区画ごとに出すと、同じ理由が2回並ぶため。
- **縮小版パネルは横長の1行にして縦に積み、左から掴む部分・縮小画像・名前を並べる**: 狭い画面でも名前が読める。ドラッグで入る位置も、材料の行と同じく上下の1方向だけで決められる。掴む部分を左端に置くのも、材料の行とそろえるため。
- **パネルは `<li>` の中に、詳細へのリンクと掴む部分を兄弟要素として並べ、掴む部分はフォーカスできない飾り(`aria-hidden`)のままにして、ボタンにしない**: 掴む部分をリンクの外に置くので、ドラッグで詳細へ移ってしまわない。ボタンにしないのは、献立に置く・動かす・外す操作がドラッグだけで、キーボードで行う操作がROADMAPに無いため。ボタンにすると、フォーカスしても押しても何も起きない部品になる。
- **候補の縮小画像は `loading="lazy"` で読み、サムネイルは作らない**: 理由は一覧タイルの画像と同じ。
- **パネルのドラッグは、材料の行と同じく、掴む部分だけをPointer Eventsで受ける**: HTML5のドラッグ&ドロップはタッチ端末で動かず、`touch-action: none` を掴む部分だけにして、ほかの場所ではふつうにスクロールできるようにするため。表示領域の端での自動スクロールも材料と同じにし、速さの計算は common.js の `autoScrollSpeed` で共用する。片方だけ直すと、2つのドラッグの手応えがずれる。
- **ドラッグ中は、パネルの写しをbodyの上に浮かせて動かし、エリアの中身は動かさない。入る位置は、区画の色と、レイアウトを変えない横線で示す**: 材料の並べ替えと違ってリストの外へ動かすので、入る場所を空けると下のエリアがずれ、指の下のエリアが入れ替わって跳ぶため。中身が動かないので、置き先と入る位置は、掴んだときに測った位置だけで決められる。
- **置き先は、毎日では見出しを含む区画全体、各日付では朝・昼・夜の帯ごとにし、日付の見出しとエラー欄の上で離したときは表示している最初の帯の先頭に入れる**: 時間帯は離した帯で決める。見出しの上でも置けるようにして、空のエリアを狙い損ねないようにする。入れる先を表示している最初の帯の先頭にするのは、帯より上で離した指の位置と、入る位置がそろうため。候補のパネルを候補の上や区画の外で離したときは何もしない。畳んだ毎日・日付は見出しも枠も置き先から外す(枠の大きさが0で位置を測れず、入った先も見せられないため)。畳んだかどうかは、区画の見出しのボタンの `aria-expanded` で判定する(畳む要素が毎日と各日付で違うため、枠の要素では片方が判定から漏れる)。オフの時間帯の帯と、3つともオフの日付の区画も同じ理由で置き先から外す。
- **朝・昼・夜の表示は、期間と同じく端末のlocalStorageに持ち、DB・URLには持たない**: その端末でどこを見るかの設定で、別の端末の表示を変えないため。読めない値・知らない時間帯・重なりを含む値は捨てて3つともオンにし、置いたパネルが知らないうちに隠れないようにする。
- **時間帯の切り替えは、期間の枠の下の行の右端に置く。「期間」のグループは期間の枠だけに付け、切り替えは「表示する時間帯」の別のグループにする**: 期間の枠が横幅いっぱいを使うので同じ行には並べられず、すぐ下に置いて、どこを見るかの設定どうしで近くにまとめるため。右端に置くと、左端からの期間の枠と重ならず、別の部品だと分かる。切り替えが期間の一部として読まれないようにする。
- **オフの帯は各日付で出さず、置き先から外す。3つともオフにしたときは各日付の枠も出さず、見出しの見た目と開閉は変えない**: 見えない帯には入れられない(入った先が見えない)ため。中身の無い枠の線だけが残ると壊れた帯に見えるため。開閉を残すのは、帯をオンに戻したとき畳んだ日付がそのまま残るようにするため。
- **見出しの件数は、オフの時間帯も消さずに出し、オフの時間帯だけ、0件は薄く、1件以上は赤にする**: 隠した帯に置いたレシピを見落とさないため。オンの帯は中身が見えるので色を変えず、赤は「隠れた帯にパネルがある」という意味だけにする。件数の並びは切り替えで変えず、どの日付でも同じ位置に数字が並ぶようにする。
- **帯の出し分けは `#day-areas` の `data-hidden-meals` 1つに空白区切りで持ち、帯と件数の見た目はCSSの `~=` で出し分ける**: 期間を変えると帯を作り直すが、親の属性は残るので、作り直すたびにかけ直さなくて済むため。区切りを空白以外にしたり、属性を帯の側に持たせたりすると `~=` が効かず、作り直した帯で状態が抜ける。
- **ドラッグ中は時間帯の切り替えを押しても何も起きない**: 開閉と同じく、掴んだときに測った置き先の位置がずれるため。
- **各日付は見出しのボタンで朝・昼・夜の帯の枠だけを畳め、見出しの右に朝・昼・夜の件数を常に出す(0件も出す)**: 日数が多くても見たい日付まで短くたどり着けるようにするため。畳んでも件数でその日の置き具合が分かり、開閉で見出しの並びが変わらず、どの日付も同じ位置に数字が並んで置き忘れた時間帯が見分けやすい。エラー欄は、戻したパネルが畳んだ日付にあっても理由が見えるよう出し続ける。候補は献立を組む間ずっと使うので畳まない。
- **毎日も見出しのボタンで枠だけを畳めるようにし、見出しには朝・昼・夜の件数を出さない。期間を変えても開閉は変えない**: 毎日に置いたものを見終えたら畳み、各日付まで短くたどり着けるようにするため。毎日には時間帯が無く、件数で置き忘れた時間帯を見分ける必要も無い。毎日の中身は期間で変わらないので、期間をめくるたびに畳み直さなくて済むよう、区画を作り直さずに状態を残す。覚えないこと、ドラッグ中に開閉しないこと、エラー欄を畳まないことは各日付と同じ。
- **各日付の開閉の状態は覚えず、開いたときと期間を変えたときは全部開いておく**: 置き場所を見落とさないため。戻るでキャッシュから復元されたときはブラウザが戻した状態のままにし、詳細を見て戻るたびに畳み直さなくて済むようにする。
- **一括開閉は、期間の枠の下の行の左端に、時間帯の切り替えのグループの外のボタンとして置く**: 開閉もどこを見るかの操作なので、時間帯の切り替えと同じ行にまとめるため。この行は右端しか使っておらず、左端なら切り替えと離れて別の部品だと分かる。グループの外に置くのは、時間帯の切り替えの一部として読み上げられないようにするため。
- **一括開閉は押した状態を持つトグルにせず、次に押したときの操作を名前とアイコンで示すボタンにする。`aria-pressed` は使わず、`aria-label` と `title` を「すべて折り畳み」「すべて展開」で替える。名前とアイコンは毎日と各日付の見出しの `aria-expanded` から毎回求め直し、別の変数に持たない**: 開閉の状態は見出しの側にあり、ボタンの押した・戻したに当たる状態が無いため。開閉が変わる道筋は、見出し・一括開閉・期間を変えたときの作り直し・戻るの復元と複数あるので、状態を別に持つとずれる。見出しのボタンを集めるときは毎日と各日付の両方を拾う(`.plan-area-toggle`)。1つでも開いていれば畳む側にするのは、開いた区画が残っているときに押すと、まず画面を短くする側にそろうようにするため。畳む目的は、見たい日付まで短くたどり着くことにある。
- **端末の今日の日付の見出しは、ボタン全体の背景を黄緑にし、`aria-current="date"` で伝える。読み上げ名は変えない**: 期間をめくっても、今日がどこか一目で分かるようにするため。黄緑にするのは、朝・昼・夜の帯の地の色(青・橙・紫系)のどれとも色相が離れていて、開いている日付で見出しとすぐ下の朝の帯がつながって見えないため(青系の背景だと朝の帯の地の色に近く、枠を足さないと見分けにくい)。背景だけで見分けられるので枠は付けず、ほかの見出しにも、文字の位置をそろえるための透明な枠は付けない。読み上げ名に「今日」を足すと、`aria-current` と二重に伝わる。色の指定は、hover・押している間の指定より詳細度を高くする(低いと、そのとき色が変わる)。毎日と候補の見出しは変えない。
- **今日かどうかは、見出しを作り直したときに加えて、タブやアプリから戻って表示されたときと、戻るでキャッシュから復元されたときにも判定し直す。ドラッグ中でも付け替える**: 開いたまま日付をまたいでも、前の日が強調されたまま残らないようにするため。タイマーで見張らないのは、画面を見ていない間に動かす必要がなく、戻ったときに合わせれば足りるため。ドラッグ中も付け替えるのは、変わるのが色だけで見出しの大きさが変わらず、掴んだときに測った置き先の位置がずれないため。
- **ドラッグ中は見出しも一括開閉も押しても開閉しない**: 置き先と入る位置は掴んだときに測った位置で決めるので、開閉して下のエリアがずれると離した所と違う所に入るため。
- **見出しの開閉の目印は山形の矢印にし、期間の前後移動には軸のある矢印を使う**: 同じ形の矢印が、同じ画面で「開閉」と「移動」の両方に使われないようにするため。山形は開閉の目印として広く使われる形で、期間の前後移動を山形に戻すと、どちらの意味か形で見分けられなくなる。
- **各日付は、角丸の枠1つの中に朝・昼・夜の帯を上から並べ、帯は地の色だけで見分ける。「朝」「昼」「夜」の文字は出さず、読み上げ名だけを付ける**: 1日の献立を1つのまとまりとして読めるようにし、文字の行で帯の高さを増やさないため。候補と毎日には時間帯が無いので分けない。
- **帯の地の色を明るくするときは、色相を変えずに彩度も一緒に上げる**: 明るさだけを上げると色がくすみ、寝ぼけた印象になったため。帯は地の色だけで見分けるので、色相を保って時間帯ごとの色味を残す。
- **各日付の帯に置いたパネルの外枠は、その帯の地の色と色相をそろえた濃い色にし、毎日・候補のパネルとドラッグ中の写しの外枠は灰色のままにする。色は帯の子のパネルを選ぶCSSだけで決める**: 帯どうしが接していても、パネルがどの時間帯に属するかが枠の色でも分かるようにするため。毎日と候補には時間帯が無いので色を付けない。写しは body の上に浮かせて描くので、帯の子を選ぶCSSには当たらず、JSを足さずに灰色になる。パネルに時間帯の印を持たせて色を付けると、帯の間で動かすたびに付け直しが要り、外し忘れると移った先と違う色が残るため。
- **空の帯にも、パネル1枚分の高さを残す**: 空の帯の上でも、狙って離せるようにするため。
- **空の帯の中央には、その時間帯のアイコンを薄く大きめに出し、読み上げさせない**: 帯は地の色だけで見分けているので、何も置いていない帯でもどの時間帯かが分かるようにするため。置いたパネルと見間違えないよう、一覧の画像なしタイルの料理のアイコンと同じく薄くする。帯には読み上げ名があるので、アイコンは読ませない。パネルを持ってきている間も出したままにする。パネルが入るまでは、帯は空のままのため。
- **空の毎日の枠の中央には、朝・昼・夜のアイコンをアイコンの半分ほどの間を空けて横に並べ、薄く大きめに出し、読み上げさせない**: 毎日は朝・昼・夜を通して毎日使うレシピを置く場所だと、文の行を足さずに伝えるため。薄く大きめにするのは、空の帯と同じく、置いたパネルと見間違えないようにするため。毎日の区画には見出しがあるので、アイコンは読ませない。3つは1つの `::before` に並べ、間はEN SPACE(U+2002)で空けて、最後のアイコンの後ろに余白を作らない。EN SPACEは幅が0.5emと決まっているので、アイコンの半分の間になる。半角スペースは幅がフォントで変わり、アイコンのフォントには空白の字形が無く端末の既定のフォントで描かれるため、間が端末で変わる。字の間隔で空けると、最後のアイコンの後ろにも間が付き、中央からずれるため。
- **空の帯・空の毎日・空の候補のアイコンは、要素を足さず、空の枠の `::before` にCSSで出す。文字コードは同梱のTabler IconsのCSSの値を写す**: 帯は `<ul>` で、置く位置は帯の子要素を数えて決め、空の帯の横線は帯が子を持たないことで出し分けている。要素を足すと、この3つが崩れるため。帯が子を持たないことで出し分けるので、空の帯には要素も空白の文字も入れない。文字コードはアイコンのCSSの更新では直らないので、更新の手順(README)で確かめる。毎日と候補の枠も、空かどうかを `:empty` だけで決め、出し分けのための処理を画面のJSに置かない。読み込みに失敗したときも、枠を空にするだけでアイコンが出る。
- **置き先の帯は、地の色を残したまま内側に縁だけを付ける。毎日と候補は地の色を替える**: ドラッグ中も、どの時間帯に入れるかが色で分かるようにするため。
- **帯の入る位置の横線は帯の中に出し、末尾は帯の下の余白、空の帯は上の余白に出す**: 帯は隙間なく接しているので、外に出すと隣の帯の線に見えたり、角丸の枠で切れたりするため。空の帯で上に出すのは、パネルが入る位置に合わせるため。
- **送信中と読み込み中は掴めないようにする**: 送信中に次を置くと、並行して届いた要求の順でサーバーの並びが画面と入れ替わることがあるため。読み込み中は、置いたパネルがまだ並んでおらず、送る位置がずれるため。
- **献立は、開いたとき・期間を変えたとき・戻るで復元したときに、レシピ一覧と献立を並行して読み直し、古い応答は捨てる**: 献立の行のレシピを、同時に読んだ一覧から必ず引けるようにする。期間を続けて変えたとき、先に送った要求の応答が後から届いても、表示中の期間とずれないようにする。詳細ページで変えた名前・画像や、消したレシピも、戻ったときに反映される。期間の読み直しで置いたパネルが消えるので、日数を変えずに確定したり取り消したりしたときは、描き直さない。
- **候補のパネルを毎日・帯へドラッグしたときは、その行を動かし、候補から消す。写しの行は作らない**: 候補は献立を組むために一時的に集めておく場所で、置いた後も残るとどれをまだ置いていないか分からなくなり、手で外す手間も増えるため。同じレシピを何日も置きたいときは、一覧から候補へ足し直す。候補も献立の行なので、置いたパネルと同じ動かすAPI・同じ処理(`movePlan`)で動かす。処理を分けると、失敗したときの戻し方とエラーを出す場所がずれる。
- **置いたパネルを掴んだときだけ候補の区画も置き先に加え、離した位置へ動かす。候補のパネルを掴んだときは加えず、候補の中で並べ替える操作は作らない**: 置いてみてやめたレシピを、外して一覧から足し直さずに候補へ戻せるようにするため。入る位置は毎日と同じく横線で示し、見出しの上で離したときは先頭に入れる。候補への移動も毎日・帯への移動と同じ動かすAPI・同じ処理(`movePlan`)で行う。処理を分けると、失敗したときの戻し方とエラーを出す場所がずれるため。
- **ドラッグ中、動かしているパネルは元の場所に薄くして残す**: エリアの中身を動かさない理由は、候補から置くドラッグの項目のとおり。どのパネルを動かしているかが分かるようにする。
- **置いたパネルを区画の外で離したときは何もせず、献立から外すのは外すボタンだけにする**: 手が滑っただけで献立から外れないようにするため。候補の上で離したときも外さずに候補へ戻すので、ドラッグで行がなくなることは無い。
- **献立から外すときに確認を出さない**: ボタン1回で済ませるため。外しても消えるのは献立の行だけでレシピは残り、一覧から候補に足し直したり置き直したりすれば戻せる。
- **動かした・外したパネルはすぐ表示に反映して保存し、失敗したら元の位置へ戻して、元の区画にエラーを出す**: 指を離した位置ですぐ結果が見える。エラーを元の区画に出すのは、戻ったパネルの近くで、戻ったことと理由が一緒に分かるようにするため。同じエリアで元と同じ位置に離したときは送らない。並びが変わらない保存で、送信中に掴めない時間を作らないため。
- **パネルは行のidを持つ**: 動かす・外すAPIは行のidで1件を指すため。同じエリアに同じレシピが何件あっても、レシピのidでは見分けられない。画面でパネルを作るのは読み込んだ行からだけなので、どのパネルにもidがある。
- **動かすAPIは、行のidと、移る先のエリア・位置だけを送る**: 置くAPIと同じく、別の端末で変えた並びを古い並びで上書きしないため。位置は、移る先のエリアで動かす1件を除いた並びでの0始まりの番号で受け、範囲外は先頭・末尾に寄せる。同じエリアの並べ替えも別のエリアへの移動も同じ処理で済む。位置の探し方とずらし方(repositoryの `slotPosition`)は置く処理と共用する。片方だけ直すと、置いたときと動かしたときで入る位置がずれるため。画面は、掴んだパネルを含む並びでの位置から、動かす1件を除いた位置に直して送る。
- **動かす行の存在は事前に確かめず、最後のUPDATEの `RETURNING` で確かめて404にする**: ほかの書き込みと同じく問い合わせを増やさない。行が無かったときは、先にずらした並びもトランザクションごと取り消される。
- **候補・毎日・各日付のすべてのパネルの右端に、アイコンだけの「外す」ボタンを置き、押すとすぐ外す**: 候補のパネルを外す手段がほかに無いため。右端に置くのは、材料の行と同じく左端の掴む部分から離して押し間違いを防ぐため。ボタンは枠線なしにして、パネルの枠の中で枠が重ならないようにする。
- **外すボタンの読み上げ名と `title` は「「名前」を外す」にし、外した後は、詰めてきた同じ位置のパネルの外すボタンへフォーカスを移す(末尾なら1つ前)**: 同じボタンがパネルごとに並ぶので、どれのボタンか分かるようにする(材料・タグの札の「外す」と同じ形)。フォーカスを移すのは、`body` に落ちずに続けて外していけるようにするため。そのエリアにパネルが残らないときは移さない。
- **献立の1件を外すDELETEは、行が無くても204を返す**: 別の端末で先に外されていても、画面が望む結果(その行が無い)は同じになる。失敗にして画面で元に戻すと、サーバーに無いパネルが画面に残る。レシピのDELETEが404を返すのとは分ける。

### 一覧の絞り込み

- **一覧の読み込みは `GET /api/recipes` と `GET /api/tags` を並行して呼び、どちらかが失敗したら一覧の読み込み失敗として扱う**: タグ選択ダイアログのタグをid昇順に並べるため(レシピのJSONにタグのidは無い)。片方だけで画面を出すと、タグが欠けたまま絞り込めてしまう。
  - 検索欄・絞り込みの行・追加パネルは、読み込みに成功したときだけ出す。失敗したときに操作や追加の入口だけが出ると、一覧が空なのと見分けがつかないため。成功すれば、タグが0件でも絞り込みの行を出して画面の並びを一定にする(押すと、ダイアログで「一緒に選べるタグはありません」と分かる)。一覧のエラー欄は、空のときは隠す。
- **絞り込み(タグ・キーワード・ブックマーク)と並べ替えは、一覧APIの結果を画面内で行い、サーバーに絞り込みのAPIを作らない**: 一覧APIは全件を本文・タグ・ブックマーク付きで返し、家庭内の規模ならブラウザで絞っても十分速い。押したり入力したりするたびに通信しなくて済む。
  - 条件は1か所にまとめてANDでかけ、並べ替えはその後に行う。一覧の描画とタグ選択ダイアログの候補が、同じ結果と同じ並びを使うため。キーワードやブックマークで絞れば、選ぶと0件になるタグが候補から自然に消える。読み込んだ配列自体の並び(APIのid昇順)は変えない。
- **絞り込みの条件と並び順は、URLクエリに `history.replaceState` で書き戻し、読み込みのたびにURLから戻す。既定の値はURLに付けず、知らない値と存在しないタグは既定として扱って、URLからも消す**: 詳細から戻ったとき・再読み込み・bfcacheからの復元のどれでも、URLを読み直すだけで同じ状態になる。`pushState` にしないのは、操作のたびに履歴が増えて、戻るで一覧から出られなくなるため。クエリごとの値は4節「一覧」のURLクエリに書く。
  - 読み込み時は、検索欄の値と並び順のボタンの表示もURLから入れ直す。再読み込みでブラウザが入力欄に戻した値と、表示・条件が食い違わないようにするため。
  - キーワードは、語に分けた形ではなく、前後の空白を除いた入力のまま残す。欄に戻したとき、打ったとおりの文字が出る。
  - 探す対象は、キーワードが空でも残す。キーワードを消して打ち直すときも、詳細から戻ったときも、選んだ対象のまま探せる。
  - 選んでいるタグは、選んだ順ではなく、タグ全体と同じid昇順で持つ。同じタグを選んでいれば、URLも選択中タグの札の並びも同じになる。
- **既定の並び順は新着順(id降順)にする**: 追加したばかりのレシピが、追加パネルのすぐ後ろに出る。
- **名前は `Intl.Collator('ja')` で比べ、漢字の名前が読みの順にならないことは受け入れる**: 読みを持つ列が無いため。ひらがな・カタカナは五十音に近い順になる。Collatorは1つ作って使い回す。比べるたびに作ると、並べ替えのたびに件数に比例して作り直すことになる。
- **名前が同じなら新着順、作った回数が同じなら名前順、それも同じなら新着順で決める**: 最後に必ずidで決まるので、選び直しや読み直しで並びが入れ替わらない。
- **並び順は、基準と昇順/降順のアイコンを並べたボタンと、その下に開く文字だけのメニューにし、絞り込みの行の右端に寄せる**: 4つから1つを選ぶ操作で、4つのボタンを並べると、狭い画面で行が何段にも折り返すため。アイコンだけにして幅を取らない。右端なので、タグの札が増えても左側の並びが動かない。ボタンには今の並び順の文字が出ないので、読み上げ名と `title` に含める。メニューの項目は、アイコンでは意味が分かりにくい「作った回数が少ない順」なども言葉で確かめられるよう、文字だけにする。
  - メニューは、外側を暗くしないモーダルの `<dialog>` にする。Escで閉じる動きと、閉じたときにフォーカスがボタンへ戻る動きをブラウザに任せられるため。外側のタップはタグ選択ダイアログと同じ判定で閉じ、下のタイルが押されて詳細へ移ることもない。開いている間はボタンも押せないので、ボタンをもう一度押すと外側のタップとして閉じる。
  - メニューは文書の座標で置き、ページと一緒にスクロールさせる。画面に固定すると、開いたままスクロールしたときにボタンから離れるため。
  - 今の並び順の印は `aria-current` で表し、CSSはその値で印を出す。印のアイコンは全項目に置いて今の並び順以外は見えなくし、印の有無で文字の位置がずれないようにする。
  - 開くと今の並び順の項目にフォーカスする。キーボードで開いたとき、そこから選び直せるようにするため。
- **タグ選択ダイアログは、開いたとき閉じるボタンにフォーカスし、決定ボタンを置かない**: スマホ・タブレットで開くたびに画面キーボードが出て、タグが隠れないようにするため。押すたびに裏の一覧とURLへすぐ反映するので、閉じる操作(閉じるボタン・Esc・外側のタップ)のどれでも選んだ状態は同じになり、取り消しの扱いが要らない。
- **ダイアログに並べるのは、選んでいるタグと、今の絞り込み結果に付いているタグだけにする**: 押すと0件になるタグを出さない。選んでいるタグは入力によらず常に出し、押した状態のまま外せる。押した状態は、青系の背景・枠・文字と選んでいることを示すアイコンで表し、色だけに頼らない。描き直したあとは同じタグのボタンへフォーカスを戻し、無ければ閉じるボタンへ戻す。
- **文字の比べ方は、NFKC→小文字化→カタカナ(ァ〜ヶ)のひらがな化の順で正規化して部分一致を取り、キーワードの検索とタグ選択ダイアログの検索で同じ関数を使う**: 全角と半角、大文字と小文字、ひらがなとカタカナを区別せずに探せ、2つの検索で入力の規則がそろう。NFKCを先にするのは、半角カナを全角にしてからひらがなへ置き換えるため(順を入れ替えると、半角カナが一致しない)。
  - 正規化した後に空白(全角空白はNFKCで半角になる)で語に分け、すべての語を含むときに一致とする(AND、語の順は問わない)。語が無いキーワードは常に一致とする。空白を含むタグ名は、語ごとのANDで探すことになる。
  - 「名前と本文」では、名前と本文を改行でつないだ1つの文字列に、同じ比べ方をかける。語は空白を含まないので、つなぎ目をまたいで一致することがなく、「語ごとに、名前か本文のどちらかに含まれれば一致」と同じ結果になる。本文の正規化は入力のたびに全件で行うが、家庭内の規模なら十分速い。
- **「条件に合うレシピがありません」は、ブックマーク・タグ・キーワードのどれかで絞っていて0件のときだけ出し、探す対象だけを変えたときは出さない**: 絞っていないときの0件はレシピが無いだけで、追加パネルで足りる。キーワードが空なら、対象によらず絞らない。
- **ブックマークの絞り込みはアイコンだけのトグルにし、絞り込みの行の先頭(「タグ」ボタンの左)に置く**: 先頭なら、タグを選んで札が増えても位置が変わらず、「タグ」ボタンと札も隣り合ったままになる。押した状態は、詳細のブックマークと同じ青系で示す。読み上げ名と `title` は「ブックマークで絞り込む」にし、詳細の「ブックマーク」(付け外し)と読み上げで区別できるようにする。
- **キーワードの検索はIMEの変換中も入力のたびに絞り込み、EnterはIMEの確定でなければフォーカスを外すだけにする**: ひらがなとカタカナを区別しないので、変換前の読みでもカタカナの名前に一致する。結果は入力のたびに出るので送信の操作は要らず、スマホでは画面キーボードが閉じて結果が見える。
- **キーワードを消すボタンは、入力欄の右端に重ねたアイコンだけのボタンにし、キーワードがあるときだけ出す**: `type="search"` の標準のボタンは、ブラウザによっては出ず、出ても小さいため、自前で置く。消したあとは入力欄にフォーカスを戻し、探す対象は戻さない(消すのはキーワードで、対象は探し方の設定のため)。大きさとhoverは「画面共通」の44pxとhoverの項目の例外。
- **探す対象(名前のみ/名前と本文)は、検索欄の箱の内側の上段に置いた、左右いっぱいのリンク風のボタンで切り替える**: 絞り込みの行には余裕が無いため、ボタンを足さずに検索欄の中にまとめる。今の対象の文言をそのまま出し、押すたびに切り替える。2つから選ぶだけなので `<select>` にはしない。高さは「画面共通」の44pxの項目の例外にする。押すと切り替わることは、下線と切り替えのアイコンで示す。下線は文字の `<span>` にだけ付ける(inline-flexのボタンに付けると、アイコンにも下線が引かれる)。
  - 既定の対象は名前のみにする。本文には材料や手順の語が多く、名前で探したいときに関係ないレシピが混ざるため、既定は狭くする。
- **検索欄は外側の箱に枠と角丸を付け、中の切り替えボタンと入力欄は枠を無くす**: 上段のラベル行と入力行を、1つの欄に見せるため。中の部品の角丸は、箱の枠の内側に合わせる(箱の角丸か枠線を変えるときは、中の部品も直す)。入力欄のフォーカスの枠はブラウザ既定のoutlineのままにし、枠を無くした入力欄でもフォーカスがどこにあるか分かるようにする。入力欄の高さは「画面共通」の44pxの項目の例外。文字は1rem(16px)より小さくしない。iOS Safariが、フォーカス時に画面を拡大するため。
- **切り替えボタンの読み上げ名は見えている文言(今の対象)にし、入力欄の `aria-label` も同じ文言に合わせる。プレースホルダは「キーワード」に固定する**: 入力欄に入ったとき、読み上げで今どの対象から探すかが分かるようにする。ラベル行と同じ文言が2回並ばないよう、プレースホルダは対象を言わない。切り替えボタンの `title`「探す対象を切り替える」は、PCのカーソル表示と読み上げの補足になる。
