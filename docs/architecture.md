# 設計概要

コード構成・DB・API・画面の現状と、逆行を防ぐための設計判断をまとめる。
1〜4節は実装時に実態へ合わせて更新し、5節には `architect` の計画に含まれる設計判断を転記する。

## 1. コード構成

```
cmd/server/main.go       # エントリポイント(DBオープン→マイグレーション適用→ルーティング登録→ListenAndServe)
internal/config/         # 設定(待ち受けアドレス・DBパス・開発モードを環境変数で受け取る)
internal/db/             # sql.DBオープン、マイグレーション実行
internal/db/migrations/  # SQLマイグレーションファイル(embedでバイナリに焼き込み)
internal/model/          # ドメイン構造体
internal/repository/     # DBアクセス層(SQL実行のみ)
internal/service/        # ビジネスロジック層
internal/handler/        # HTTPハンドラ層
web/embed.go             # web/static をembedで焼き込み、fs.FSとして提供
web/static/              # フロントエンド(画面ごとのHTMLと同名JS。一覧 recipes.html / recipes.js、詳細 recipe.html / recipe.js。画面によらないJS部品 common.js。全画面共通の既定スタイル base.css。embedでバイナリに焼き込み)
web/static/vendor/       # 同梱した外部ライブラリ(配布ファイルのまま。tabler-icons/ にoutlineのCSS・woff2・LICENSE。版数はREADME)
Makefile                 # make / make help(ターゲット一覧)/ make run(開発起動)/ make build-rpi(RaspberryPi Zero向けビルド)/ make build-win(Windows向けビルド)
bin/                     # ビルド成果物の出力先(Git管理外)
scripts/                 # preview用サーバーの起動スクリプト(preview-server.ps1)
data/                    # SQLiteファイルの実行時生成先(Git管理外)
```

## 2. DBスキーマ

### `recipes`(レシピ)
| カラム | 型/制約 |
|---|---|
| id | INTEGER PRIMARY KEY |
| name | TEXT NOT NULL(タイトル) |
| body | TEXT NOT NULL DEFAULT ''(材料・調味料・手順を含む自由テキスト) |
| cooked_count | INTEGER NOT NULL DEFAULT 0(作った回数) |
| image_version | INTEGER NOT NULL DEFAULT 0(画像を保存した回数。画像URLの `v` に使う) |
| image | BLOB(JPEG。NULLなら画像なし。必ず最後の列にする) |

### `tags`(タグ)
| カラム | 型/制約 |
|---|---|
| id | INTEGER PRIMARY KEY |
| name | TEXT NOT NULL UNIQUE(大文字・小文字を区別) |

### `recipe_tags`(レシピとタグの紐付け)
| カラム | 型/制約 |
|---|---|
| recipe_id | INTEGER NOT NULL REFERENCES recipes(id) ON DELETE CASCADE |
| tag_id | INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE |

主キーは `(recipe_id, tag_id)`。どのレシピにも付いていないタグはレシピの保存・削除と同じトランザクションで消すので、`tags` には使われているタグだけが残る。

### `schema_migrations`(マイグレーション適用履歴)
| カラム | 型/制約 |
|---|---|
| name | TEXT PRIMARY KEY(マイグレーションファイル名) |
| applied_at | TEXT NOT NULL DEFAULT (datetime('now')) |

`internal/db/db.go` の `Migrate()` が `main.go` から起動時に呼ばれ、 `internal/db/migrations/*.sql` を未適用のものだけファイル名昇順・1ファイル1トランザクションで適用する。

## 3. APIエンドポイント

ルーティングは `internal/handler/router.go` の `NewRouter()` に集約する(Go 1.22以降のメソッド付きパターン)。レシピのJSONは `{"id","name","body","cooked_count","tags","image_url"}`(`tags` はタグ名の配列でタグのid昇順、無ければ `[]`。`image_url` は画像があれば `/api/recipes/{id}/image?v={image_version}`、無ければnull)。POST/PUTのリクエストは `{"name","body","tags"}` で、`tags` が無い・nullなら空として扱い、そのレシピのタグを丸ごと置き換える(前後の空白を除き、空は捨て、完全一致の重複はまとめ、同じ名前のタグが無ければ作る)。PUTは `cooked_count` も画像も受け付けず値も変えない。

| メソッド パス | 概要 |
|---|---|
| GET /healthz | 死活監視用(`{"status":"ok"}`固定) |
| GET /api/recipes | レシピ一覧取得。200で配列(id昇順、bodyとtagsを含む。0件は `[]`) |
| GET /api/tags | 使われているタグ名の配列(id昇順、0件は `[]`) |
| POST /api/recipes | レシピ新規作成。リクエスト `{"name","body"}`、201で作成したレシピ |
| GET /api/recipes/{id} | レシピ1件取得。200 |
| PUT /api/recipes/{id} | レシピ更新(全体置換)。リクエストは作成と同じ、200で更新後のレシピ |
| DELETE /api/recipes/{id} | レシピ削除。204(ボディなし) |
| POST /api/recipes/{id}/cooked | 作った回数を1増やす。200で更新後のレシピ |
| DELETE /api/recipes/{id}/cooked | 作った回数を1減らす(0未満にはしない)。200で更新後のレシピ |
| PUT /api/recipes/{id}/image | 画像を保存(`image_version` を1増やす)。ボディはJPEGのバイト列そのまま(上限2MB)。200で更新後のレシピ |
| DELETE /api/recipes/{id}/image | 画像を外す。画像が無くても200で更新後のレシピ |
| GET /api/recipes/{id}/image | 画像のバイト列。`Content-Type: image/jpeg`、`Cache-Control: public, max-age=31536000, immutable`。`?v=` は見ない |
| GET / | ルートパスのみ `/recipes.html` へリダイレクト(302)。それ以外は静的ファイル配信(embed。`DEV_MODE=1` のときのみ `os.DirFS("web/static")` から配信) |

エラー応答は `internal/handler/respond.go` の `writeError` で `{"error": "メッセージ"}` として返す。

| ステータス | 条件 | メッセージ |
|---|---|---|
| 400 | `{id}` が数値でない・1未満 | IDが不正です |
| 400 | リクエストJSONが不正 | リクエストの形式が不正です |
| 400 | `name` が空白除去後に空 | 名前を入力してください |
| 400 | 画像のボディが2MBを超える | 画像が大きすぎます |
| 400 | 画像のボディがJPEGでない(空を含む) | JPEG画像を送ってください |
| 404 | 対象IDのレシピが無い | レシピが見つかりません |
| 404 | `GET .../image` でレシピに画像が無い | 画像が見つかりません |
| 500 | 上記以外(詳細はログのみ) | サーバー内部でエラーが発生しました |

## 4. 画面

| 画面 | 内容 | 状態 |
|---|---|---|
| `recipes.html`(レシピ一覧) | 画面幅で列数が変わるタイルグリッド(1px灰色の枠線の正方形の下端に半透明の黒い帯で名前を白文字1行(長い名前は「…」で省略)。画像なしは無地の枠の中央に薄い色のti-photo-off。作った回数=ti-chef-hatと数字、0回はアイコンのみ、を右上に重ねる)。タイルは `recipe.html?id=N` へのリンク。名前の帯のすぐ上にタグの札を1行で小さく並べ、収まらない分は「+N」。見出しの下に名前の検索欄(入力のたびに、空白で区切った語をすべて名前に含むレシピだけを表示。キーワードがあるときだけ右端にアイコンだけの「キーワードを消す」。キーワードは `?q=` に残る)と、その下に絞り込みの行(ti-filter「タグ」ボタンと、選択中タグの札+アイコンだけの「外す」。選択は `?tag=` に残る)。ボタンはタグ選択の `<dialog>`(検索欄(空白区切りのAND)とトグルボタン、閉じるボタン・Esc・外側タップで閉じる)を開き、選んだタグをすべて持つレシピだけを表示(AND。名前のキーワードとも AND)、0件なら「条件に合うレシピがありません」。グリッドの先頭は `recipe.html` へのリンクの追加パネル(破線の枠の正方形の中央に ti-plus と「追加」。0件でも出し、一覧の読み込みに失敗したときは出さずエラー文言だけ)。ブラウザの戻るでキャッシュから復元されたときは一覧を読み直す | 実装済み。ロジックは `recipes.js`(共通部品は `common.js`) |
| `recipe.html`(レシピ詳細) | `?id=N` なら閲覧表示(名前・タグの札・画像・本文。タグが0件なら札の行は出さない)、`id` が無ければ新規作成フォーム。上部の左に一覧へ戻るボタン、閲覧表示では右に「作った」(押すたびに加算と減算を切り替えるトグル)・編集(アイコンのみ)・削除。「編集」で入力フォームへ切り替わり(名前の下にタグ欄=付けた札の列(札ごとにアイコンだけの「外す」)と、`GET /api/tags` の候補を `<datalist>` に入れた入力欄と「追加」ボタン(Enterでも足せる)。名前と本文の間に画像欄=画像があればプレビューの右下にアイコンだけの「画像を外す」を重ね、無ければ「画像なし」枠=枠全体が貼り付け欄(Ctrl+Vやスマホ長押しの「ペースト」でクリップボードの画像を受け取る)で、中央に「画像を選ぶ」と「Ctrl+V・長押しで貼り付け」の案内)、保存すると閲覧表示に戻る。編集中に未保存の変更があると、戻る・再読み込み・タブを閉じる・一覧へ戻るボタンでブラウザ標準の離脱確認を出す。削除・破棄の確認は専用の確認 `<dialog>`。IDが無効・存在しないときはエラー文言と戻るボタンだけ | 実装済み。ロジックは `recipe.js`(共通部品は `common.js`) |

## 5. 設計判断(逆行防止用)

- **モジュール名は `kondate-supporter`**: 外部へ公開せず `go install` もしないため、GitHubのパスにはしない。importを短く保ち、旧実装を参照するときの読み替えを無くす。
- **ディレクトリは使う項目で作る**: `.gitkeep` などの目印ファイルは置かない。`internal/db`・`model`・`repository`・`service` は、そのコードを初めて書くROADMAP項目で作る。ヘルパー関数や設定項目も、使う項目で追加する。

- **SQLiteの接続は1本に制限する**: `SetMaxOpenConns(1)` で書き込みを直列化し `SQLITE_BUSY` を避ける。単一プロセス・個人利用でRaspberryPi Zeroにも合う。PRAGMAは新規接続にも確実に効くようDSNの `_pragma` で指定する(接続後の `Exec` ではプールが作る新規接続に反映されないことがある)。
- **マイグレーションは `internal/db` で直接embedする**: 読み込み側は `Migrate()` だけなので専用パッケージは分けない。
- **serviceはrepositoryの具象型に依存する**: テストの差し替えなどインターフェースが必要になる場面がまだROADMAPに無いため、`*repository.RecipeRepository` を直接持つ。
- **handlerはrepositoryをimportしない**: 依存を `handler → service → repository` に保つ。「見つからない」はrepositoryの `ErrNotFound` をserviceが自分の `ErrNotFound` に置き換えて伝える。ユーザー向けメッセージはserviceのエラー値に持たせ、handlerはHTTPステータスへの振り分けだけを行う。
- **名前の入力チェックはserviceで行う**: 「前後の空白を除いて空なら不可」は業務ルールなのでserviceに置き、保存するのも空白を除いた後の値。`body` は自由テキストとして書かれたまま保存する。
- **PUTは全体置換**: 項目が name・body・tags だけなので部分更新(PATCH)は作らない。
- **一覧はid昇順(登録順)でbodyとtagsも含めて返す**: SQLiteの文字列比較では日本語の名前がよみ順に並ばないため名前順は採らない。家庭内の規模なので一覧と詳細でレスポンスの形を分けない。
- **ID存在確認は事前にSELECTしない**: DELETEは `RowsAffected` が0なら404とする。作った回数・画像のUPDATEは `RETURNING` で更新後の行をそのまま応答に使い、行が無ければ404とする。PUTはタグを付け替えた後の値を返すため、UPDATEの `RowsAffected` が0なら404とし、保存後にSELECTで読み直す(受け付けない `cooked_count` の実際の値も返せる)。
- **作った回数は専用エンドポイントでだけ変える**: PUTの全体置換に回数を含めると、編集中に別の端末で「作った」を押した場合、保存で回数が古い値に戻ってしまう。そのためPUTでは受け付けず、加算・減算はSQLの `cooked_count + 1` で行う(読んでから書く手順にしない)。
- **減算は0で止め、エラーにしない**: `MAX(cooked_count - 1, 0)` で下限をSQLに任せる。0回で取り消しても200で0回のまま返し、画面側で回数を確かめなくて済むようにする。
- **「作った」は押すたびに切り替わる1つのボタンにし、取り消し専用のボタンは置かない**: SNSの「いいね」と同じく、押すと回数が増えて押した状態になり、もう一度押すと減って元に戻る。続けて押しても回数が重ねて増えず、取り消すと必ず開いたときの回数に戻る。
- **「作った」の押した状態は画面のJSだけで持ち、詳細ページを読み込むたびに押す前に戻す**: 記録したいのは回数で、誰がいつ押したかではないのでDBには持たない。編集に切り替えてもページを離れるまでは保つので、閲覧表示に戻ったあとも取り消せる。
- **作った回数はアイコンと数字だけで表し、0回は数字を出さない**: 一覧で作ったことのあるレシピが見分けやすく、文言を切り替える処理も要らない。一覧タイルでは画像(画像なしでは枠)の右上に重ねて位置をそろえる。
- **押した状態は背景と枠の色で表し、`aria-pressed` で伝える**: 同梱しているのはoutline版のアイコンだけで、塗りつぶしに切り替えられないため。CSSは `aria-pressed` の値を見て(IDを含む指定でbase.cssのhover/activeより優先して)色を付け、状態の値を1つにまとめる。
- **画像はファイルでなくrecipesのBLOB列に入れる**: 保存先がDBファイル1つなので、preview用DBを使えば画像も自動で分かれ、バックアップや配置もDBファイルだけで済む。1レシピ1枚・2MBまでならSQLiteで足りる。
- **`image` はrecipesの最後の列にする**: SQLiteは大きなBLOBを行の後ろのオーバーフローページに置き、BLOBより後ろの列を読むとそこを辿るため。`image_version` を先に足して一覧で読んでも画像に触れない。今後recipesに列を足すときはこの点に注意する。
- **画像の有無は `typeof(image) = 'blob'` で調べる**: 列の型だけを見て中身を読まないので、一覧・1件取得・RETURNINGで画像の本体を読まずに `image_url` を組み立てられる。
- **`image_version` は保存のたびに増やし、画像を外しても戻さない**: 画像URLは `immutable` で1年キャッシュされる。外して付け直したときに同じ `v` になると古い画像が表示されてしまう。
- **`image_url` はhandlerで組み立てる**: パスはルーティングの知識なので、modelは `HasImage`・`ImageVersion`(`json:"-"`)を持ち、handlerが `recipeResponse` に `image_url` を足して返す。
- **画像の大きさ・形式の検査はhandlerで行う**: `http.MaxBytesReader` で2MBを超えた時点で読むのをやめ、大きなボディをメモリに溜めない。形式は `http.DetectContentType` がimage/jpegかどうかで見る。ボディの検査はDBより前なので、IDが無く画像も不正なときは400になる。
- **画像は専用エンドポイントでだけ変える**: PUTの全体置換に含めると、別の端末で画像を変えた直後の保存で古い画像に戻ってしまう。ボディもJSONに包まずバイト列のまま送れる。
- **画像を外す操作は、画像が無くても200にする**: 画面側で有無を確かめずに呼べるようにする。
- **画像の取得では `v` を見ない**: `v` はブラウザのキャッシュを切り替えるためだけのもので、古い版はDBに残さないため常に現在の画像を返す。
- **画面は1つのHTMLと同名のJSに分け、画面によらない既定スタイルは base.css に置く**: 見た目をそろえる土台を先に決めるため、画面が1つのうちから base.css を作る。base.css には要素の既定スタイルと役割クラスだけを書き、タイルや画像欄など画面固有のCSSはHTMLの `<style>` に残す。HTMLではアイコンのCSSの後に読み込む。
- **画面によらないJSの部品は `common.js` に置き、画面のJSより先に読み込む**: 置くのは、画面のDOM要素のIDや画面の状態変数を参照しない関数・定数だけ(`$`・`api`・`cookedContent`・`toJpeg` と `MAX_IMAGE_SIDE`・`onOutsideTap`)。特定の要素IDを前提にする `confirmAction` などは、その要素を持つ画面のJSに置く。詳細ページを分けると一覧と詳細でAPI呼び出しや回数の表示を共用するため、画面を増やす前に切り出しておく。
- **共通JSはES modulesにせず、クラシックスクリプトのグローバルで共有する**: 部品が少なく、画面ごとに `import` を並べる手間に見合わないため。HTMLでは `common.js` → 画面のJSの順に書く。画面のJSでは `common.js` と同じ名前をトップレベルで宣言しない(同名の `const` があるとエラーになる)。
- **ボタンは白背景・1px枠・角丸8pxのアウトラインにし、色は役割クラスで分ける**: 保存は `.primary`(青系)、削除と確認ダイアログのOKは `.danger`(赤系)、それ以外は灰色。色の意味をクラス名で表し、画面ごとに色を書かない。アイコンだけのボタンも同じ角丸の四角にする。
- **入力欄・ダイアログ・画像・画像なしの枠も角丸8pxにそろえる**: ボタンと同じ値で画面全体の形をそろえる。編集フォームで画像を選んだり外したりしても、プレビューと「画像なし」枠の形が変わらない。
- **入力欄とダイアログの枠はボタンと同じ1px・#999にする**: ブラウザ既定の枠をやめ、ボタンと並んだときの線の太さと色をそろえる。
- **入力欄は内側の余白を0.5remにし、名前欄は高さ44px以上にする**: 角丸にすると文字が角に寄って見えるため。名前欄をボタンと同じ高さにして、タッチで押しやすくする。
- **一覧タイルの枠線・角丸は `.tile-visual` に付け、`overflow: hidden` で中身を切り抜く**: 画像と名前の帯を1つの枠に収め、帯の下側の角を枠の角丸に合わせるため。回数バッジは枠の内側にあるので欠けない。
- **確認ダイアログのOKボタンはHTMLで `.danger` に固定する**: 使い回す文言は「削除する」「破棄する」だけで、どちらも取り消せない操作のため、JSでクラスを切り替えない。
- **hoverの背景は `@media (hover: hover)` の中だけで付け、:activeは常に付ける**: タッチ端末ではタップ後にhoverが残り、押した後も色が付いたままに見えるため。押している間の手応えは :active で出す。
- **hover/activeの背景は `:not(:disabled)` に限り、無効のボタンは `opacity: 0.5` で薄くする**: 保存中などに無効になったボタンが押せるように見えないようにする。
- **詳細は1件取得APIで読む**: 詳細ページは単独のURLで開くため、一覧のデータは使えない。`?id=` の値は検査せず `encodeURIComponent` してAPIへ渡し、サーバーの `error` 文言をそのまま出す(入力チェックはサーバーだけで行う)。例外は `?id=` が空のときで、パスが `/api/recipes/` になって静的配信の404が返り、意味のある文言が出ないため、画面側で「IDが不正です」を出す。
- **「一覧へ戻る」は、一覧から来たときだけ `history.back()` にする**: 判定は読み込み時の `document.referrer` が同じオリジンの `/recipes.html` かどうか。一覧の絞り込み条件をURLに残す項目を入れたとき、ブラウザの戻ると同じ動きにしておけば戻ったときも条件が残る。URLを直接開いたときなどは `recipes.html` へのリンクとして動く。
- **削除後は一覧へ移り、詳細のURLを履歴に残さない**: 一覧から来たときは `history.back()`、それ以外は `location.replace("recipes.html")` で移る。ブラウザの戻るで削除済みのレシピのページに戻らないようにする。
- **新規作成の保存では、POSTの直後に `history.replaceState` でURLを `?id=` 付きにする**: 画像の保存が失敗して編集フォームにとどまっても、再読み込みで同じレシピを開けるようにする。
- **一覧は `pageshow` の `persisted` のときに読み直し、詳細は読み直さない**: 一覧はbfcacheから復元されると詳細ページでの保存・削除・「作った」が反映されないため。詳細は編集中の入力が消えないよう復元のままにする。
- **詳細ページの操作ボタンは上部の戻るボタンと同じ行の右側に置く**: 本文が長くても、スクロールせずに「作った」「編集」「削除」を押せるようにする。編集中と読み込みエラーのときは隠し、戻るボタンだけを出す。
- **画面を移るボタンは `<a class="button">` にする**: 一覧のタイル・追加パネル・戻るが対象。リンクなので長押しや中クリックで新しいタブにも開ける。base.cssでは `a.button` をボタンと同じ見た目にし、`<a>` の既定が `content-box` なので `box-sizing: border-box` で高さを44pxにそろえる。
- **詳細はまず閲覧表示にし、「編集」で入力フォームに切り替える**: 調理中の誤編集やキーボードの出現を防ぐため。本文は `textContent` と `white-space: pre-wrap` で書いたとおりの改行で表示する。
- **確認は画面内の確認 `<dialog>` を文言違いで使い回す**: 削除確認と未保存の破棄確認で共用し、`confirm()` は使わない(見た目を画面とそろえるため)。
- **編集のキャンセルでは、未保存の変更があれば確認する**: 変更の有無は編集開始時の値との比較。ページの離脱は次項の `beforeunload` で確認する。外側タップの判定は確認 `<dialog>` で使い、 `pointerdown` と `click` の対象がどちらも `<dialog>` 自身のときだけとみなし、テキスト選択のドラッグで閉じないようにする。
- **ページ離脱の確認は `beforeunload` でブラウザ標準のダイアログに任せる**: 詳細ページを分けたので、戻る・再読み込みで編集中の入力が消えるようになった。これらは画面内の確認 `<dialog>` では止められないため、一覧へ戻るボタンも含めて標準ダイアログにそろえる。確認するのは編集中で `isDirty()` が真のときだけ。リスナーは常に登録し、判定は中で行う。
- **画面内で確認済みの遷移では `leaving` を立てて `beforeunload` を素通りさせる**: 新規作成のキャンセルで「破棄する」を選んだ後に、ブラウザの確認を重ねて出さないため。`leaveToList()` で立て、bfcacheから戻ったときは `pageshow` の `persisted` で下ろす。
- **iOS Safariでは離脱確認が出ないことを受け入れる**: `beforeunload` の確認に対応していない。個人利用で、入力の自動保存などの代替はROADMAPに無いため作らない。
- **入力チェックはサーバーだけで行う**: クライアントに二重実装せず、APIの `error` メッセージをそのまま表示する。
- **レシピ本文は構造化しない**: 材料・調味料・手順は `body` 1カラムの自由テキストに持たせる。名称+数量+単位での構造化やLLMによる抽出はROADMAPに項目が無い限り着手しない。
- **Makefileはsh前提で書く**: 開発PCではGit Bash/WSLからmakeを実行する。cmd.exeでの動作は考えず、環境変数は `VAR=値 コマンド` の形で渡す。
- **引数なしの `make` はhelpを表示する**: `.DEFAULT_GOAL := help` にして、`make` だけを打ったときに開発サーバーが起動しないようにする。どのターゲットがあるかもその場で分かる。
- **helpの一覧はターゲット行末尾の `## 説明` から自動で作る**: `awk` で `$(MAKEFILE_LIST)` を読んで抜き出す。ターゲットを増やすときはその行に `## 説明` を書くだけでよく、help側を書き換えない。詳しい理由や注意は、これまでどおりターゲットの上の行に `#` コメントで書く。
- **`make run` は固定パスへビルドしてから実行する**: `go run` は実行のたびに一時パスへバイナリを作るため、Windowsファイアウォールの許可を何度も求められ、許可ルールも増え続ける。
- **`make run` は `DEV_MODE=1` で起動する**: 画面ファイルをディスクから配信し、HTML/JSの修正をビルドし直さずに確認できるようにする。
- **開発用・preview用・Windows常用のバイナリ名を分ける**: Windowsでは実行中のexeを上書きできないため。つなぎ運用のサーバーを動かしたまま開発用やpreview用をビルドしても失敗しないようにする。
- **`make build-win` はRaspberryPiを用意するまでのつなぎ**: 開発用の `make run` とは別に、embed配信・シンボル除去済みの配置用exeを作る。GOARCHは指定せず、ビルドしたマシンに合わせる。
- **RaspberryPi Zero向けは `GOARM=6`・`CGO_ENABLED=0`・`-trimpath -ldflags="-s -w"` でビルドする**: Pi Zero/Zero WはARMv6のため。SQLiteドライバがCGO不要なので静的バイナリ1つで配置でき、シンボルを除いて転送・保存のサイズを抑える。
- **外部ライブラリはCDNを使わず `web/static/vendor/<名前>/` に無編集で同梱する**: LAN内でインターネットにつながらなくても画面が崩れないようにするため。embedでバイナリに入るので配置はファイル1つのまま。版数はREADMEに記録する。
- **Tabler Iconsはoutline(3.49.0では無印の `tabler-icons.min.css` / `fonts/tabler-icons.woff2`)のCSSとwoff2だけを置く**: filled・200/300版、woff・ttfは使わない。CSSの `src` は先頭がwoff2で、対応ブラウザは後ろの形式を取りに行かないため、CSS内の残りの参照は書き換えずに放置する。
- **アイコンだけのボタンには `aria-label` と `title` にもとの文言を入れる**: 読み上げで名前が分かり、PCではカーソルを合わせると意味が出るようにするため。アイコン自体は `aria-hidden="true"`。`icon-only` クラスで44px四方以上にしてタッチで押しやすくする。
- **ボタンは `inline-flex` でアイコンと文字を並べる**: 縦位置と間隔を `align-items` と `gap` でそろえる。- **一覧はタイルグリッドにし、列数は `repeat(auto-fill, minmax(140px, 1fr))` だけで決める**: media queryを書かずにスマホは2列、40remの本文幅では4列までになる。
- **本文幅は40remのまま、タイル一覧でも広げない**: 詳細ページと幅をそろえ、広い画面で操作が遠くならないようにする。
- **名前は画像の有無によらず正方形の下端の半透明の黒い帯に白文字1行で重ね、枠外には出さない**: タイルが正方形1つにそろい、画像なしでも同じ場所で名前を読める。長い名前は `text-overflow: ellipsis` で省略し、全文はタイルの `title` と詳細で確認する。
- **画像なしタイルの中央には名前ではなく薄い色の ti-photo-off を置く**: 名前は帯に出るので二重に出さず、画像が無いことを一目で分かるようにする。
- **タイルは `<a class="tile">` にし、見た目は正方形だけにする**: 輪郭は `.tile-visual` の枠線が担う。リンクの下線と文字色は打ち消す。
- **一覧の行と列の間隔はどちらも0.5remにする**: 名前の行が枠外になくなり、行の間を広げて名前との対応を示す必要がなくなったため。
- **一覧の画像は `loading="lazy"` で読む**: 縮小せず出すので、画面外のタイルの画像までPi Zeroから一度に取りに行かないようにする。サムネイルは作らない。
- **作った回数のバッジは `cookedContent()` を使い回し、クラスを足して重ねる**: 詳細の「作った」ボタンと見た目・0回の扱いを1か所で決める。
- **一覧の回数バッジは `.tile-cooked` に `line-height: 1rem` を指定し、アイコンと数字を同じ高さの行に収める**: アイコンはTabler Iconsの `line-height: 1` で1remの高さだが、数字は既定の行高でそれより高くなり、0回(アイコンのみ)と1回以上でバッジの高さが変わっていた。幅は桁数に合わせて変わるままにする。共用の `.cooked` でなく `.tile-cooked` に書くのは、詳細の「作った」ボタンを変えないため。
- **プレビューは起動時に前回のプレビュー用exeを止め、`DEV_MODE=1` で起動する**: 固定パスへビルドするため、前回分が残るとビルド失敗とポート競合が起き、古い埋め込み画面が配信され続けていた。画面ファイルはディスクから直接配信してHTML/JSの再ビルドをなくす。ユーザーの開発サーバー(`make run`)とは実行ファイル名・ポート・DBとも別。
- **確認ダイアログのボタンは文字だけにする**: OKボタンは「削除する」「破棄する」と文言を差し替えて使い回すため、アイコンを固定できない。
- **レシピの追加は一覧先頭のパネルから行い、ヘッダーに新規作成ボタンは置かない**: 追加の入口がタイルと同じ並びにあり、タッチ端末でも大きな的になる。0件でも同じ場所に出るので、空状態の案内文は要らない。
- **追加パネルは一覧の読み込みに成功したときだけ出す**: 失敗したときに追加の入口だけが出ると、一覧が空と見分けがつかないため。一覧のエラー欄は `.error` にして、空のときは隠す。
- **追加パネルは名前の帯と回数バッジを付けず、破線の枠で中央に ti-plus と「追加」を出す**: レシピのタイルと形と大きさをそろえながら、レシピではないことを一目で分かるようにする。枠と文字の色はボタンにそろえて #999 と #555 にし、hover/activeの背景もボタンと同じ規則(hoverは `@media (hover: hover)` の中だけ)で付ける。
- **追加パネルは `loadList()` の中でJSから作る**: 一覧を読み直すときにリストを丸ごと空にして作り直すため。HTMLに固定で置くと、読み直すたびに残す処理が要る。
- **選んだ画像はブラウザで縮小・JPEG変換し、保存するまで送らない**: 長い辺が800pxを超えるときだけ縮め、canvasで品質0.85のJPEGにする。2MBの上限に収まり、Pi Zeroで画像を処理しなくて済む。保存前は送らないので、破棄してもサーバーには何も残らない。
- **変換は `<img>` に読み込んでcanvasへ描く**: ブラウザがEXIFの向きを反映した大きさで描くため、スマホの写真が横倒しにならない。描く前に白で塗り、透過PNGの透過部分が黒くならないようにする。
- **編集中の画像の変更は `imageChange`(null / `{blob,url}` / `"remove"`)の1つの値で持つ**: 未保存の判定と保存時に呼ぶAPIをこの値だけで決められる。もともと画像の無いレシピで外したときはnullに戻し、変更なしとして扱う。
- **保存はレシピのPOST/PUTを先に、画像APIを後に呼ぶ**: 新規作成では画像を送るためのidがPOSTまで無いため。画像だけが失敗したら、選んだ画像を残して編集フォームにとどまり、`current` を保存済みのレシピに替える(新規作成ならこの時点でURLも `?id=` 付きになっている)。再保存はPUTと画像の送り直しになり、新規作成でも二重に登録されない。
- **画像は幅いっぱい・高さ50vhまでとし、はみ出す分は `object-fit: cover` で切る**: 縦長の写真でもスマホで本文がすぐ下に見える。閲覧表示と編集のプレビューで同じ見た目にする。
- **編集フォームの画像欄は、画像の有無でできる操作だけを出す**: 画像が無いときは「画像なし」枠に貼り付けと「画像を選ぶ」を、画像があるときはプレビューに「画像を外す」だけを出し、下に並べるボタン行は置かない。その状態で使えない操作が並ばず迷わない。差し替えは外してから選び直す形にし、画像がある状態での貼り付けや選び直しでうっかり上書きしないようにする。
- **「画像を選ぶ」は `contenteditable` の外に置き、枠いっぱいの貼り付け層の上に重ねる**: ボタンを中に入れると編集できる中身の一部になり、`beforeinput`/`input` で中身を戻す処理とぶつかるため。「画像なし」と案内の文言は貼り付け層の中に置き、枠のどこを長押ししても「ペースト」が出るようにする。ボタンの層は `pointer-events: none` にしてボタンだけで受け、それ以外のタップは下の貼り付け層に届ける。枠の高さは、文言・案内・44pxのボタンを縦に並べても窮屈にならない10remにする。
- **「画像を外す」はアイコンだけにしてプレビューの右下に重ね、`.danger` にしない**: 画像を隠す範囲が小さい。外しても保存するまでは確定せずキャンセルで戻せるので、取り消せない操作に使う赤にはしない。
- **クリップボードの画像は `contenteditable` の欄の `paste` イベントで受ける**: `navigator.clipboard.read()` はHTTPのLAN内では使えないため。スマホの長押しに「ペースト」を出すため入力できる要素にし、`inputmode="none"` で画面キーボードを抑止する。
- **貼り付けた画像は「画像を選ぶ」と同じ `setPendingImage` に渡す**: 縮小・JPEG変換・プレビュー・未保存の判定・保存を、画像の入手方法によらず1つの流れにする。
- **貼り付け欄の中身は `beforeinput` で変えさせず、変わったら `input` で戻す**: `inputmode="none"` で止まるのはスマホの画面キーボードだけで、PCのキー入力やドロップは止まらないため。IME変換など止められない入力に備え、本来の中身を控えて入れ直す。
- **貼り付けは「画像なし」枠の上でだけ受け付ける**: ページ全体でCtrl+Vを拾うと、名前や本文への貼り付けと区別できないため。
- **処理中は貼り付け欄を無効にせず、貼り付けを無視する**: 欄が編集できないものに変わると、フォーカスや長押しメニューの動きが変わるため。
- **`[hidden]` には `display: none !important` を指定する**: `display` を指定した要素では `hidden` 属性が効かなくなるため。
- **静的ファイルにキャッシュ用の仕組みは作らない**: 画面が少なくLAN内の通信なので、ROADMAPに項目が無い限り着手しない。
- **デプロイは手作業とし、仕組みを作らない**: 転送や常駐化(systemd・Windowsのサービス化)の自動化は個人利用では必要性が薄いため、READMEの手順だけで運用する。
- **タグはレシピに従属するものとして、RecipeRepository・RecipeService・RecipeHandlerで扱う**: タグはレシピに付いている間だけ存在し、作るのも消すのもレシピの保存・削除の中で行う。タグだけを操作するAPIは無いので、層ごとに型を分けない。
- **保存・削除のトランザクションはrepositoryのメソッドの中で完結させる**: SQLをrepositoryに閉じ込めたまま、レシピとタグの書き込みを1つにまとめる。接続は1本に制限しているので、トランザクションの中では `r.db` を使わず必ず `tx` を使う(使うと空き接続を待ち続けて止まる)。
- **外部キーはDSNの `_pragma=foreign_keys(1)` で有効にする**: SQLiteは接続ごとに既定で外部キーが無効で、`ON DELETE CASCADE` も効かない。トランザクションの中で `PRAGMA foreign_keys` を実行しても効かないため、接続を開くときに指定する。
- **タグはレシピのJSONに名前の配列で持たせ、idは画面に出さない**: 画面がタグを見分けるのも、URLの絞り込み条件(`?tag=名前`)も名前で足りる。名前はUNIQUEなので取り違えない。
- **タグ名の配列は `recipeColumns` の相関サブクエリ `json_group_array(t.name ORDER BY t.id)` で読む**: 一覧・1件取得・作った回数と画像の `RETURNING` まで、レシピを返すすべての応答に同じ形でタグが入り、読み込みも `scanRecipe` 1つで済む。家庭内の規模なら行ごとのサブクエリでも重くならない。
- **リクエストの `tags` は、無いときもnullのときも空として扱う**: PUTは全体置換なので、`body` と同じく送られなかった項目は空にする。
- **タグ名の正規化(前後の空白・空・重複)はserviceで行い、大文字と小文字は区別する**: 名前のチェックと同じく業務ルールなのでserviceに置く。保存するのは書かれたとおりの名前で、表記ゆれを吸収する比べ方は絞り込み・検索の側で行う。画面でも同じ規則で重複を防ぐが、正しさを決めるのはサーバー。
- **タグの置き換えは、紐付けを全部消して付け直した後に、未使用のタグを消す順で行う**: 付けたままのタグを途中で消さないので、idが変わらず、タグの並び(id昇順=最初に作られた順)が保存のたびに入れ替わらない。
- **未使用のタグは保存・削除のたびに消し、`GET /api/tags` は `tags` をそのまま返す**: 未使用のタグがDBに残らないので、使われているかを毎回確かめなくてよい。
- **`recipe_tags.tag_id` にはインデックスを作らない**: 主キー `(recipe_id, tag_id)` でレシピからの検索は足りる。タグの削除や未使用タグの判定で全件を走査しても、家庭内の規模なら問題にならない。
- **タグ欄の「外す」は44px四方のアイコンだけのボタンにし、編集フォームの札は閲覧表示より大きくする**: アイコンだけのボタンはタッチで押しやすい44px以上にそろえる規則を優先する。閲覧表示の札は押す操作が無いので小さく出す。
- **タグの札は `base.css` の役割クラス `.tags`・`.tag` にし、「外す」ボタン付きの札は `.tags.removable` にする**: 詳細の編集フォームと一覧の選択中タグの2画面で同じ札を使うため。タイル上の札の小ささは `recipes.html` の `<style>` で上書きする。
- **タグの絞り込みは一覧APIの結果を画面内で絞るだけにし、サーバーに絞り込みのAPIを作らない**: 一覧APIは全件をタグ付きで返し、家庭内の規模ならブラウザで絞っても十分速い。タグを押すたびに通信しなくて済む。
- **一覧の読み込みは `GET /api/recipes` と `GET /api/tags` を並行して呼び、どちらかが失敗したら一覧の読み込み失敗として扱う**: ダイアログのタグをid昇順に並べるため(レシピのJSONにidは無い)。片方だけで画面を出すと、タグが欠けたまま絞り込めてしまう。
- **選んでいるタグはid昇順で持ち、URLの `?tag=名前`(複数なら繰り返し)に `history.replaceState` で書き戻す**: 詳細から戻ったとき・再読み込み・bfcacheからの復元のどれでも、`loadList()` でURLを読み直すだけで同じ状態になる。`pushState` にしないのは、タグを押すたびに履歴が増えて、戻るで一覧から出られなくなるため。URLにあっても存在しないタグは読み込み時に捨て、URLからも消す。
- **絞り込みの行は一覧の読み込みに成功したときだけ出し、タグが0件でも出す**: 追加パネルと同じく、失敗したときに操作だけが出ないようにし、0件でも画面の並びを一定にする。押すとダイアログで「一緒に選べるタグはありません」と分かる。
- **タグ選択ダイアログは開いたとき閉じるボタンにフォーカスし、決定ボタンを置かない**: スマホ・タブレットで開くたびに画面キーボードが出てタグが隠れないようにするため。押すたびに裏の一覧とURLへ即反映するので、閉じる操作(閉じるボタン・Esc・外側タップ)はどれでも選んだ状態が同じで、取り消しの扱いが要らない。
- **ダイアログに並べるのは、選んでいるタグと、今の絞り込み結果に付いているタグだけにする**: 押すと0件になるタグを出さない。選んでいるタグは入力によらず常に出し、押した状態のまま外せる。押した状態は青系の背景・枠・文字と ti-check で示し、色だけに頼らない。描き直したあとは同じタグのボタンへフォーカスを戻し、無ければ閉じるボタンへ戻す。
- **文字の比べ方は `normalizeForSearch`(NFKC・小文字化・カタカナ U+30A1〜U+30F6 のひらがな化の順)で正規化して部分一致を取る(`matchesKeyword`)**: 全角と半角、大文字と小文字、ひらがなとカタカナを区別せずに探せる。半角カナを先にNFKCで全角にしてからひらがなへ置き換える。キーワードは正規化した後に空白(全角空白はNFKCで半角になる)で語に分け、すべての語を含むときに一致とする(AND、語の順は問わない)。語が無い(空や空白だけの)キーワードは常に一致とする。名前の検索とタグ選択ダイアログの検索で同じ関数を使い、入力の規則をそろえる(空白を含むタグ名は語ごとのANDで探すことになる)。
- **タイルのタグは名前の帯のすぐ上に1行で並べ、はみ出す分は末尾から隠して「+N」にまとめる**: タイルの大きさを変えずに付いているタグが分かる。収まるかは描画後に `scrollWidth` で測り、列数が変わる `resize` のたびに測り直す(rAFで1回にまとめる)。1つ目だけでも収まらないときはそのタグを「…」で省略する。札の行と名前の帯は `.tile-footer` にまとめて下端に置き、札の行の高さを決め打ちしない。タイル上の札は押しても絞り込まない(タイル全体が詳細へのリンクのため)。
- **「条件に合うレシピがありません」は、タグかキーワードで絞っていて0件のときだけ出す**: 絞っていないときの0件はレシピが無いだけで、追加パネルで足りる。追加パネルは絞り込み中も先頭に出す。
- **名前の検索も一覧APIの結果を画面内で絞るだけにし、条件は `filteredRecipes()` 1か所でタグとANDにする**: ダイアログの候補も同じ結果から作るので、キーワードを入れると選ぶと0件になるタグが自然に消える。
- **キーワードは前後の空白を除いた入力のまま `?q=` に入れ、空なら付けない**: 語に分けた形で持たず、欄に戻したときに打ったとおりの文字が出る。タグと同じく `replaceState` で書き戻し、`loadList()` でURLから欄に戻す(再読み込み時にブラウザが入力欄を復元しても、URLの値で上書きして表示と条件をそろえる)。
- **名前の検索はIMEの変換中も入力のたびに絞り込み、EnterはIME確定中でなければフォーカスを外すだけにする**: ひらがなとカタカナを区別しないので、変換前の読みでもカタカナの名前に一致する。結果は入力のたびに出るので送信の操作は要らず、スマホでは画面キーボードが閉じて結果が見える。
- **キーワードを消すボタンは入力欄の右端に重ねた44px四方のアイコンだけのボタンにし、キーワードがあるときだけ出す**: `type="search"` の標準ボタンはブラウザによって出ず小さいため自前で置く。消したあとは入力欄にフォーカスを戻す。検索欄は一覧の読み込みに成功したときだけ出す。
- **キーワードを消すボタンは、hover・押下中も背景を付けず透過のままにする**: 入力欄の枠の内側に重ねているため、背景を付けると角丸の枠線にかかって見える。「hoverは `@media (hover: hover)` の中だけ、:activeは常に付ける」規則の例外。`#name-search-clear` の `background: transparent` はIDを含む指定なので base.css のhover/activeより優先される。
- **タグの候補は、編集を始めるたびに `GET /api/tags` で読み、失敗しても無視する**: 別の端末で増えたタグも候補に出る。候補は入力の補助なので、取れなくても手で打てば足りる。付けているタグは候補から外す。
- **入力欄で、IMEの変換を確定するEnterではタグを足さない**: 日本語のタグ名を確定しただけで追加されないよう、`isComposing` と `keyCode === 229`(Safari向け)のときは何もしない。それ以外のEnterはフォームの送信を止めてタグを足す。
- **入力欄に文字を残したまま保存すると、その文字もタグとして足す**: 打ったタグが黙って消えないようにする。入力欄に文字があるだけでも未保存の変更とみなし、キャンセルや離脱で確認を出す。
- **在庫・献立・買い物リストは現時点のスコープ外**: 関連するテーブル・APIはROADMAPに項目が追加されるまで作らない。
